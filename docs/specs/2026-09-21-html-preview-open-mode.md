# HTML 预览与文件链接浮窗的另一种打开方式

> Status: Draft
> Owner: desktop app maintainers
> Last updated: 2026-09-22

**Objective:** HTML 文件在预览面板里既能看渲染效果也能看源码；转录里文件链接的浮窗精简成一行，并给出与默认设置相反的那种打开方式。

**Hard invariant:** 点击链接本身的去向不变（仍由 `files.open_action` 与能力探测决定，外部打开仍带 `:line:col` 后缀）；非 HTML 文件的预览档位、首视图与读取行为不变；渲染出来的 HTML 碰不到宿主页面的数据、存储与桥接接口。

## Problem

1. **HTML 只能看源码。** `.html` / `.htm` 在扩展名白名单里归 `code` 档（`frontend/packages/agentre-ui/src/lib/previewable.ts`），面板只给 Monaco 源码或与 HEAD 的对比，看不到页面长什么样；agent 常产出报告页、原型页，用户只能再去外部浏览器打开。（已验证）
2. **浮窗里看不出点下去会怎样，也换不了。** 本地文件浮窗底部只写「点击打开这个文件」（`transcript/rich-link.tsx` 的 `LocalInternalPopover`，文案 `richLink.clickToOpen`）；走预览还是系统应用取决于设置，偶尔想走另一条路得先去改设置。（已验证）
3. **浮窗信息冗余。** 同一个文件在浮窗里出现三次（项目根 + 相对路径 + 完整绝对路径），另有「本地文件」胶囊与解释性提示；真正有用的只有「哪个文件」和「怎么打开」。（已验证，见 `LocalInternalPopover` / `LocalExternalPopover`）
4. **包内拿不到默认打开方式。** `previewFile` 端口在设置为 `external` 时回 `false`（`frontend/src/components/agentre/transcript-ports-desktop.ts`），包只知道「宿主谢绝了」，既无法标出默认方式，也无法在用户明确要求时强制走预览。（已验证）

## Actors and user stories

1. As a `桌面端用户`, I want 在预览面板里直接看 agent 生成的 HTML 页面渲染效果，并能切到源码或左右对照, so that 不用离开应用就能检查产物。
2. As a `桌面端用户`, I want 悬停文件链接时一眼看到是哪个文件，并能一键用另一种方式打开, so that 不必为一次例外去改全局设置。
3. As a `控制台用户`, I want 浮窗同样简洁、HTML 同样能渲染, so that 两端体验一致（控制台没有系统打开，只少了那个按钮）。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | HTML 成为独立预览类型，沿用 markdown 的三档：渲染 / 源码 / 双栏 | 用户在 mockup 中确认。Rejected: 只加一个「渲染」开关——与 markdown 的档位控件形态不一致 |
| 2 | 渲染只用文件自身文本（沙箱 iframe 的 `srcdoc`），相对路径引用的 CSS / JS / 图片加载不到 | 两端同一实现、代价低；用户同意推荐方案（先做文本渲染）。Rejected: 本轮由宿主托管文件所在目录让相对资源可解析——桌面要本地文件服务、控制台要新增中继路径，另开 spec |
| 3 | 允许页面脚本执行，但 iframe 不给同源权限、不给弹窗与顶层导航 | 报告页常靠脚本出图表；不同源即拿不到宿主 cookie / 存储 / Wails 桥接。用户同意推荐方案。Rejected: 禁用脚本——大量产物页渲染成空白 |
| 4 | 浮窗采用「变体 A」并精简为一行：类型图标 + 路径（目录淡、文件名实）+ 行号 + 相反打开方式 + 复制 | 用户选定变体 A 并要求去掉多余解释。Rejected: 变体 B 并排两枚按钮——更占地，默认方式其实就是点链接本身 |
| 5 | 相反打开方式是文字按钮（图标 + 「系统打开」/「预览」），复制是纯图标按钮 | 相反动作是本次新增的主要能力，纯图标不易被发现；复制是通用动作，图标足够。Rejected: 两者都纯图标 |
| 6 | 只有两条路都存在时才出相反按钮；只有一条路时整项不渲染 | 与现有「能力探测、整项不渲染而非置灰」约定一致 |
| 7 | 默认打开方式由宿主经端口告知包；「在预览中打开」由用户显式触发时不受设置约束 | 解决 Problem 4；设置仍归宿主所有。Rejected: 包自己读设置——设置是宿主产品决策，包拿不到也不该拿 |
| 8 | URL 链接浮窗同步精简为同一形态（图标 + URL + 复制），去掉「点击在系统浏览器中打开」；本轮 URL 浮窗只有复制，不出任何打开按钮 | 同一种浮窗两种风格会显得不一致。远端会话里 `localhost` URL 经端口转发打开是另一个功能，用户决定本轮不纳入。Rejected: 本轮顺带接端口转发——需另定默认去向、无映射时的出口与两宿主的映射查找 |
| 9 | 路径核实（精确查找 + 后缀匹配、非文件降为纯文本、多处命中列候选）另开 spec | 需要新增 wire 批量查找并与 agentre-server 成对发布；用户同意拆分，并选定「渲染时核实」 |
| 10 | 远端会话同样出「系统打开」相反按钮；系统打开因本机没有该文件而失败时，提示用事实说明并在可预览时给「预览」出口 | 用户选定（方案 B + 提示）。Rejected: 远端会话隐藏该按钮——需要让转录端口感知会话归属；Rejected: 沿用原始错误串 toast——界面不贴机器原话 |

## HTML 预览

**识别。** 扩展名 `.html` / `.htm` 的文件归入独立的 HTML 预览类型，不再属于代码档；大小上限、二进制判定、文件不存在、离线等失败说明与重试与代码文件完全一致。

**档位。** 从「目录」入口或转录链接打开时，header 出现三档控件「渲染 / 源码 / 双栏」，默认「渲染」。档位是标签自身状态，切换标签后各自保留，持久化规则与 markdown 档位相同。

- 渲染：页面在沙箱 iframe 中渲染，可执行脚本；不同源、不可弹窗、不可导航顶层窗口；页面内链接只在 iframe 内跳转或无效果，不会把应用带离当前页面。相对资源加载失败时不另加提示，页面按浏览器默认行为缺失这些资源。
- 源码：与今天代码文件的只读 Monaco 视图一致。
- 双栏：左源码、右渲染，各占一半。

**从「未提交」入口打开。** 首视图保持今天的行为（与 HEAD 的对比），即默认落在「源码」档，且「源码」与「双栏」左侧显示的是与 HEAD 的对比；用户可切到「渲染」。

**从「本次会话」入口打开。** 仍然只显示工具 diff，没有档位控件（与今天一致）。

**带行号的链接。** 转录里带行号的 HTML 链接打开时首视图为「源码」并定位到该行（与 markdown 带行号时落到「文本」档同理）；渲染档不参与定位。

**刷新。** 本会话轮次结束时与其他文件一样重读；重读后渲染档重新加载页面。header 另有一个「重新渲染」图标按钮，仅在渲染 / 双栏档出现，点击后重新加载 iframe（重跑脚本），不重新读文件。

**用浏览器打开。** 宿主提供系统打开能力时（桌面端），HTML 标签的 header 出现「用浏览器打开」图标按钮，行为与系统默认应用打开该文件一致；控制台不渲染该按钮。

**失败。** 渲染过程中页面自身的脚本错误只影响 iframe 内部，不影响面板与应用；面板不捕获、不展示页面内部错误。

## 文件链接浮窗

**本地文件（项目内）。** 浮窗只有一行：文件类型图标、相对路径（目录部分弱化、文件名加粗；过长时从左侧截断，文件名始终完整）、有行号时的 `L<n>` 标记、相反打开方式按钮（条件见下）、复制按钮。不再显示「本地文件」胶囊、项目根、完整绝对路径和「点击打开这个文件」提示。

**相反打开方式。** 仅当该链接既可内置预览（宿主提供预览能力且扩展名可预览）又可系统打开（宿主提供系统打开能力）时出现：

- 默认方式为预览 → 按钮为「系统打开」，点击后以系统默认应用打开该文件，路径带原链接的行号后缀。
- 默认方式为系统打开 → 按钮为「预览」，点击后在预览面板打开该文件（带行号时定位到该行），不受设置影响。
- 任一条路不存在（项目外文件、文件夹、不可预览的扩展名、控制台）→ 不渲染该按钮。

点击相反按钮后浮窗关闭。点击链接本身的去向不变。

**系统打开失败。** 适用于浮窗的「系统打开」按钮与点击链接本身走系统打开两种情形（本地会话与远端会话同样出现该按钮）：

- 失败原因是**本机不存在该路径**（远端会话的文件通常如此）：toast 标题「本机上没有这个文件」，正文「它可能在远端机器上」；该链接可内置预览时 toast 带「预览」动作，点击后在预览面板打开该文件（带行号时定位到该行），不受设置影响；不可预览时不带动作。原始错误串不出现在界面上。
- 其他失败原因：沿用今天的失败 toast。
- 「本机不存在该路径」由系统打开这一侧在调起系统应用之前判定，并以可识别的失败类别告知界面；界面不靠解析错误文本来判定。

**本地文件（项目外）与文件夹。** 同样一行：图标 + 路径（项目外显示链接解析出的完整路径）+ 行号 + 复制；去掉「项目外」说明文字。

**URL。** 一行：链接图标 + URL（过长截断）+ 复制；去掉「点击在系统浏览器中打开」。

**复制。** 图标按钮，悬停 tooltip「复制完整路径」（URL 为「复制链接」）；复制内容与今天一致（完整路径含行号后缀 / URL），回执沿用现有 toast。

**键盘与无障碍。** 两个按钮都有可读的无障碍名称；浮窗的键盘可达性维持今天 HoverCard 的行为，本轮不新增焦点管理。

**文案。** 新增与删除的静态文案都走 i18n，中英两套同步；删除不再使用的旧 key。

## 兼容性

- 控制台（agentre-server 前端）通过固定版本引用共享包，升级引用后即获得新浮窗与 HTML 预览；控制台没有系统打开能力，因此不会出现相反按钮与「用浏览器打开」按钮。控制台侧的引用升级在 agentre-server 仓库另行交付。
- 宿主端口的变更对未提供新能力的宿主向下兼容：宿主不告知默认方式时，浮窗按今天的分流规则只提供一条路、不出相反按钮。
- 已持久化的预览标签：原本以代码档打开的 HTML 标签恢复后按新类型处理，档位缺省为「渲染」（从「未提交」恢复的为「源码」）。

## Out of scope

- 远端会话里 `localhost` / `127.0.0.1` URL 经端口转发打开（端口转发已在 `7dfc20a9` 支持按映射打开）——另开 spec。

- 让相对路径的 CSS / JS / 图片在渲染中生效（宿主托管目录）——另开 spec。
- 链接路径核实、后缀匹配、非文件降级与多候选浮窗——另开 spec（见 mockup 第 3 节）。
- 浮窗内的键盘焦点管理。
- agentre-server 引用升级——在该仓库另行交付。

| `FilePreviewPanel`（共享包） | HTML 三档切换、各入口的首视图、带行号落源码档、iframe 的 sandbox 属性不含同源 / 弹窗 / 顶层导航、重新渲染只重载不重读、宿主无系统打开时不出「用浏览器打开」 | `file-preview` 现有面板测试 |
| 桌面端系统打开（Go 单测） | 路径不存在时返回可识别的「本机没有该路径」失败、不调起系统应用；存在时行为不变 | `internal/app` 现有 OpenPath / validateOpenPath 测试 |
| `RichLink` 系统打开失败提示（共享包） | 「本机没有该路径」失败出事实文案，可预览时带「预览」动作并强制预览；其他失败走原 toast | `transcript/rich-link.test.tsx` |
| 桌面端 transcript 端口与预览标签 store | 端口如实告知默认方式、强制预览在 `external` 设置下仍打开标签；HTML 标签初始档位与持久化恢复 | `transcript-ports-desktop` / `file-preview-tabs-store` 现有测试 |

不能自动化的部分：Wails WebView 里沙箱 iframe 的实际渲染与脚本执行、以及浮窗的视觉形态，由收尾阶段在真实桌面应用中打开一个带脚本的 HTML 文件与几种链接人工观察确认。
