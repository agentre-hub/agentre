# 转录文件预览：两端都能从转录里点开文件

> Status: Approved
> Owner: 桌面端 / 控制台前端
> Last updated: 2026-09-06

**Objective:** 让浏览器控制台与 agentre 桌面端的用户都能从转录里点开一个会话文件，看到同一份预览（代码 / Markdown / 图片 / 改动 diff）。

**Hard invariant:**

- 服务端 Go 一行不改。文件正文与路径只经中继在浏览器与那台机器之间流过，不进服务端的任何响应结构体、不落库、不记正文——R19 的守卫面因此不变。
- 工作区内只有一份预览渲染实现。桌面端切到共享包之后，宿主里不得留下等价的第二份。
- 桌面端**侧栏**的预览行为不变（单击临时、双击常驻、键盘模型），换的只是实现出处。本轮在桌面端新增的可见行为只有一处：转录里的文件链接多了「开内置预览」这个去向。
- 桌面端「点一个文件」只有一套语义：转录里的去向与侧栏共用 `files.open_action` 这一个设置，不另立第二套。
- 跨仓交付顺序不可颠倒：共享实现先在 `agentre` 落地并推送，`agentre-server` 才能 pin 过去；消费方不得先于可解析的共享版本删除任何东西。

## Problem

1. **控制台里的文件路径是死文本。** `agentre-server/frontend/src/lib/transcriptPorts.ts` 明确不提供 `openPath` 与 `readWorkspaceFile`，并在注释里写明理由是「桌面能力，浏览器里不存在」。按共享包的能力探测约定，转录里所有与文件相关的入口因此整个不渲染。`pages/` 下也没有任何文件视图。

2. **能力其实早就在线上，缺的只有浏览器侧的渲染。** `workspacefs.*` 七个方法（`listDir` / `readFile` / `gitChanges` / `gitBranches` / `gitFileContent` / `searchFiles` / `gitState`）都登记在 `frontend/packages/agentre-wire/src/rpc-methods.ts:224-264`，agentred 与桌面端经 `internal/daemon/protobufadapter/peripheral.go:126` 注册同一份 handler，`internal/daemon/integration_test.go:435-457` 证明它们受 `requireAuth` 守着。浏览器已经在用完全相同的裸传路子跑 `remotefs.*`（`agentre-server/frontend/src/lib/remotefs.ts`，该文件注释写明「服务端一行代码都不需要改」）。

3. **桌面端转录里点文件路径，只会交给外部应用。** `frontend/packages/agentre-ui/src/transcript/rich-link.tsx` 的 `dispatchClick` 对 `local-internal` / `local-external` 一律走 `ports.openPath`。桌面端明明有内置预览，但转录里进不去——只能从侧栏进。同一个 App 里「点一个文件」因此有两种结果。

4. **预览渲染是桌面私有的。** `frontend/src/components/agentre/file-preview/` 五个文件（面板 631 行、标签条 320 行、三个视图）加上 `frontend/src/lib/file-preview/` 的 Monaco 语言表与装载器，全在宿主目录里。按 `AGENTS.md` 的跨端所有权规则，两端都要渲染的东西归 `@agentre-hub/agentre-ui`。

## Actors and user stories

1. 作为在浏览器里盯远端会话的用户，我希望点转录里的文件路径就能看到它现在的内容，这样我不必切到那台机器前面。
2. 作为审查 agent 改动的用户，我希望在浏览器里也能看到 diff，这样我能判断这一轮改得对不对。
3. 作为在桌面端看转录的用户，我希望点转录里的文件路径和点侧栏里的那一行结果一样，这样我不必记住「从哪儿点会怎样」。
4. 作为维护者，我希望预览只有一份实现，这样两端不会各自长出一套。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 入口只做转录里的文件链接与工具卡，不做文件侧栏 | 用户决定。桌面端的三模式侧栏深度依赖 Wails 绑定与桌面 store，整块抽取是另一轮的体量。Rejected: 连「目录 / 变动 / Git」侧栏一起搬 |
| 2 | 走中继裸传，服务端零改动 | `remotefs.*` 的现成先例，且不改变 R19 守卫面（那道守卫走响应结构体的反射面，中继帧不在那个面上）。Rejected: 新开一条服务端 REST 端点代理 —— 会把路径与文件正文引进服务端的响应面，正是 R19 要挡的东西 |
| 3 | 预览渲染进 `@agentre-hub/agentre-ui`，标签与布局状态留在各宿主 | 「渲染什么」跨端一致，「开在哪、开几个、怎么排」是宿主的布局问题。桌面端是右侧栏里的标签页，控制台是详情列里的右分栏 |
| 4 | 新增可选端口 `previewFile`，宿主不提供即不出入口 | 与 `openPath` / `readWorkspaceFile` 同一套能力探测约定（`transcript/ports.ts` 已写明：可选端口的语义是能力探测而不是静默失败） |
| 5 | Monaco 在控制台侧按需懒加载 | 它只在用户真的点开一个文件时才需要；控制台首屏不该为它付出体积 |
| 6 | 形状在控制台侧按 `remotefs.ts` 的先例就地声明 | 共享包按 commit 钉在 `package.json` 上，先加形状再推再挪钉子是四步跨两仓。本仓已有两处同形先例并在注释里写明双维护义务 |
| 7 | 预览与转录**左右分栏**，不是抽屉或浮层 | 用户决定。分栏让「agent 说了什么」与「文件现在长什么样」同屏可对照。Rejected: 右侧抽屉 —— 看文件时看不到对话；Rejected: 抽屉+可钉成分栏 —— 两套布局都要实现并各自测 |
| 8 | 预览栏定宽 **420**，会话列表列保持不动 | 用户决定，按 `/chat` 的**真实**宽度做的（见下「详情列只有 896」）。零新增能力。Rejected: 打开预览时把会话列表收成窄轨（转录 552 + 预览 620）—— 读感最好，但要给 `ResizableSidebar` 加一个它今天没有的收起态；Rejected: 预览占满详情栏 896 —— 那就不是分栏了 |
| 9 | 桌面端转录点开的预览复用**既有的右侧栏预览标签**，不新开面板 | 转录与侧栏指向同一个文件时应当是同一个标签；另开一个面板会让同一个文件在两处各开一份，临时/常驻语义也要复制一套 |
| 10 | 桌面端转录的去向**跟随 `files.open_action`**，不另立设置 | 用户决定。同一个 App 里「点一个文件」只该有一种结果。后果是本规格在桌面端依赖 `2026-09-06-file-open-action.md` 先落地。Rejected: 转录固定开预览（与侧栏分叉）；Rejected: 转录单独一个设置（设置面变两行、语义开始分叉） |
| 11 | 七个态里只有「设备离线」给动作按钮 | 过大 / 二进制 / 不存在都是终态，给按钮等于给一个点了必然还是失败的东西。只有离线是会自己好转的 |

## 两端的入口

`previewFile` 端口在两端都接上，但「点了开在哪」各自跟随宿主：

- **控制台**：详情列右侧的预览栏（见下「预览开在哪」）。
- **桌面端**：既有的右侧栏预览标签——与从文件侧栏点开的是同一批标签、同一套临时/常驻语义。

桌面端转录里的去向跟随 `files.open_action`：设置为「在 agentre 内预览」时点转录里的文件路径开预览标签，设置为「用外部应用打开」时维持今天的行为。可预览性判定与侧栏同源（`resolvePreviewRelPath`）；判定不通过时无论设置为何都交给外部应用，与侧栏那张表一致。

**本规格在桌面端依赖 `2026-09-06-file-open-action.md` 先落地**——那一轮才引入 `files.open_action`。控制台不受此依赖，它没有「外部应用」这个去向。

## 入口与可用性

**前提**：用户看着一条会话的转录，某个块里带有一条指向会话工作区内文件的路径（Markdown 链接、工具卡里的文件行、改动列表里的一行）。**动作**：点它。**结果**：按上一节的宿主去向开出预览，显示该文件当前在那台机器上的内容。

出不出这个入口按共享包既有的两道判定，本轮不新增口径：

- 路径必须解析成会话 cwd 之内的相对路径（`link-classify` 与 `previewable.ts` 的 `resolvePreviewRelPath`）。越出 cwd、或会话根本没有 cwd 的，不出入口。
- 扩展名必须在预览 allowlist 内。控制台里不在 allowlist 的**不出入口**——它没有「交给外部应用」这条退路；桌面端则退回外部应用，与侧栏那张表一致。

宿主没接 `previewFile` 时（例如未来的其他宿主），入口整个不渲染，而不是渲染出来点了没反应。

## 预览开在哪

**前提**：用户在会话详情里点开了一个文件。**动作**：预览进入。**结果**：详情列横向分成两栏，左侧是转录、右侧是预览。两栏同时可见，用户能对着 agent 的说法看文件本身。

### 详情列只有 896

这条约束决定了预览栏的宽度，必须先写清楚：`/chat` 的桌面态（`agentre-server/frontend/src/pages/Chat.tsx` 的 `chat-layout`）**已经是三栏**——SideNav 224 + 可拖的会话列表列（默认 320，`ResizableSidebar` 量程 220–640）+ 详情列 `flex-1`。1440 宽的窗口下，详情列实际只有 **896**。

预览栏因此定在 **420**，转录留 **476**。两边都不宽裕，这是明知的取舍：420 的代码区放得下约 60 个字符，较长的代码行需要横向滚动；转录比没有预览时窄一半，工具卡与改动行会明显变挤。换来的是零新增能力——会话列表列不动，`ResizableSidebar` 不改。

预览栏宽度在本轮是定值，不可拖。

预览栏由三段构成：

- **标签条**：同时开着的文件各占一个标签，当前标签可关闭；临时标签（单击开出来的）以斜体标名，与桌面端的临时/常驻语义一致。右端是最大化与关闭。
- **路径条**：这个文件在会话工作区里的相对路径，以及内容来自哪台机器、那台机器此刻在不在线。
- **内容区**：按文件类型渲染，见下。

关闭最后一个标签时预览栏整个收起，转录回到全宽。

设计源：`agentre.pen` 的「文件打开与端口转发」分区，`B1 控制台 · /chat · 转录 476 + 预览 420`（Light / Dark）；同分区的 `B1-1（未采用）` 与 `B1-2（未采用）` 是按同一份真实宽度画出来的两个被否方案。

## 预览的内容

支持的四类与桌面端同源，判定仍由 `previewable.ts` 的 `previewKind` 单点给出：

- **代码 / 文本**：Monaco 只读渲染，语言按扩展名表。
- **Markdown**：与桌面端一致地提供渲染视图与源码视图。
- **图片**：直接渲染。
- **改动 diff**：从 Git 侧读同一文件的基线版本与当前版本做并排比较，与桌面端的 diff 视图同一份实现。

## 失败与恢复

每一种失败都要在预览面里如实说出来，不做静默空白：

- **对端离线 / 中继断开**：预览面显示「这台机器现在够不着」，并提供重试。这与控制台既有的中继失败分类同源，不新造一套措辞。
- **会话没有 cwd**：那台机器会回 `WorkspaceFsNoCwd`。入口本就不该出现（见上），若仍然到达，按「这个文件不可预览」处理。
- **文件过大 / 二进制**：`readFile` 的应答自带 `tooLarge` 与 `binary` 两个标记，预览面按标记显示「文件过大，未加载」或「二进制文件」，不尝试渲染。
- **文件已不存在**：如实显示「文件不存在」——转录里的路径来自当时那次工具调用，之后被删掉是正常情况。

**只有「对端离线」给重试按钮。** 其余三种是终态：文件不会自己变小、二进制不会自己变成文本、删掉的文件不会自己回来。给它们一个点下去必然还是失败的按钮，比不给更糟。

失败一律冒泡给预览面自己的错误态。共享包不吞异常、不做 toast——这是 `transcript/ports.ts` 已经定下的契约。

七个态（四个成功、三个失败）的完整措辞见设计源 `B2 控制台 · 文件预览 · 状态集`。

## 桌面端在这一轮里的变化

两处：

1. **实现搬家（不可见）**：预览面板与标签条从宿主目录移到共享包，桌面端改为从共享包消费并注入自己的 Wails 端口。侧栏的可见行为、标签语义、键盘模型全部不变，由既有测试锚住。
2. **转录新增预览入口（可见）**：转录里的文件链接在设置为「在 agentre 内预览」时开预览标签，而不是交给外部应用。数据链路无需新建——`workspace_fs_svc` 已经按 deviceID 分流（本机会话进程内调叶子包，远端会话借 `remote_device_svc` 的租约调 `workspacefs.*` RPC），本机与远端会话都读得到。

## 跨仓交付顺序

1. 在 `agentre` 里完成抽取与端口新增，桌面端切过去，验证、提交、推送。
2. 在 `agentre-server` 里挪 pin，接上 `previewFile` 与经中继的读取，验证。
3. 两个仓库各自独立提交。

## Out of scope

- 控制台里的「目录 / 变动 / Git」文件侧栏。
- 在浏览器里编辑或保存文件。
- 桌面端**侧栏**行为的任何改动——本轮在桌面端唯一的可见变化是转录里多了一个预览去向。
- 目录浏览——那是 `remotefs.*` 已经在做的另一件事。
