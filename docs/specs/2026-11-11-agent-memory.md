# Agent 记忆（桌面端 + 同步种类）

> Status: Approved（2026-11-11 修订已确认：项目合并、控制台删除归属时 server 级联、分叉措辞）
> Owner: 桌面端 + 共享 UI 包（agentre-ui）+ pkg/wire / pkg/syncwire；agentre-server 跟随抬钉，只接受并存储新种类
> Last updated: 2026-11-11

**Objective:** Agent 能把值得长期保留的事实记下来，之后每个新会话自动带上；用户能在一个页面里看到、修改和撤回所有记忆。

**Hard invariant:** 记忆只在 agent 自己的提示词之后追加一段背景信息，不改动提示词本身；一个会话带上的记忆在该会话内不变；AI 对记忆的任何改动都能被用户还原（修改可恢复上一版，删除只是归档）。

本 spec 是记忆系列的第一份，只覆盖「事实型」记忆。后续各自成篇，顺序为：控制台（界面与控制台会话带上记忆）、整理（梦境）、技能、会话检索、导入 CLI 原生记忆。成篇的做法和资料由技能承载，不用本 spec 的条目来装；系列里没有单独的「知识库」类别。

## Problem

1. **Agent 跨会话什么都不记得。** 已核实：两个仓库里没有任何记忆功能，agent 每个会话只带一个提示词字段（`internal/service/chat_svc/chat.go:2500`，`SystemPrompt` 由 `agents.prompt_json` 拼成）。用户纠正过的做法，下个会话要再说一遍。
2. **CLI 自带的记忆替代不了。** 已核实（Claude Code 官方文档）：它的自动记忆按仓库、按机器存放，同一仓库里的所有 agent 读写同一份，换设备、换后端就没有了。Agentre 目前也不读写它。

## Actors and user stories

1. 作为用户，我纠正过 agent 一次之后，希望它在以后的会话里记得，不用我再说。
2. 作为用户，我想知道 agent 记了什么、是哪次对话里记的，记错了能一下撤回。
3. 作为用户，我想把一条对整个部门或项目都成立的事实写一次，让相关的 agent 都带上。
4. 作为 agent，我在工作中发现一个以后还用得上的事实，想把它记下来，不打断当前回合。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 记忆是 Agentre 自己的一等资源，不依赖任何 CLI 的原生记忆 | 用户已决定。否决：托管 CLI 原生记忆——只对个别后端有效，换后端或设备就断 |
| 2 | 四层归属：全局、部门、agent、项目。一个会话能看到的 = 全局 + agent 所在部门及其所有上级部门 + 该 agent 自己的 + 会话所在项目的 | 用户已决定（「底座可以这样」）。agent 挂在上级 agent 之下时，沿上级 agent 找到最近的部门。否决：只有 agent 一层——团队约定要逐个重复写 |
| 3 | 一条记忆只属于一层，没有「某个 agent 只在某个项目里生效」这种交叉限定 | 用户已确认（2026-11-11，随 spec 审批）。项目里的事实通常对该项目的所有 agent 都有用，应写到项目层；交叉限定会让预算用量随项目变化、说不清一个数。否决：agent 层条目可限定项目 |
| 4 | 一条记忆 = 一行摘要 + 可选详情。摘要常驻提示词，详情由 agent 按需读取 | 已核实：Claude Code 是索引常驻加主题文件按需读，Hermes 是小块全文常驻；摘要加详情兼得两者。否决：纯全文小块——四层分下来容量太小 |
| 5 | 每层有摘要预算，初值 2,000 字。超出时写入照常成功，按「置顶在前、其余按最近修改」取到预算为止，其余本次不带 | 用户已确认（2026-11-11，随 spec 审批）。硬上限在同步下守不住：两台设备各自没超，合并后就超了。否决：写满即拒绝（Hermes 的做法） |
| 6 | AI 写入直接生效，没有待确认环节 | 用户已决定（2026-11-11）。单用户产品，同类产品默认都不审；待确认队列攒多了等于没审。否决：共享层写入先暂存待审 |
| 7 | AI 可以修改和归档它看得到的任何条目，包括用户写的；只有两条硬规则：AI 只能写它所属的层，AI 的删除是归档 | 用户已决定（2026-11-11，「不用做限制」）。兜底靠上一版和归档都可恢复、最近变更里看得到。代价：只保留一版，AI 连改两次后，更早的内容（包括用户最初写的）找不回来。否决：用户写过或改过的条目 AI 只读 |
| 8 | 条目只有「正常」和「已归档」两种状态；用户另有彻底删除 | 用户已确认（2026-11-11，随 spec 审批）。否决：再加一个「停用」——它和归档的效果相同（都不进提示词、都可恢复），多一个状态只多一份解释 |
| 9 | 每条记忆保留上一版，可恢复；对话卡片上的撤销、记忆页的「恢复上一版」是同一个动作 | 让「记错了一下撤回」对修改也成立，且只有一套还原机制。否决：完整历史——超出本轮需要 |
| 10 | agent 通过 `agrctl` 读写记忆，会话内调用免审批 | 已核实：`agrctl` 通道覆盖本地与远程会话；MCP 工具只有部分后端支持。现有的会话写操作都要过审批卡（`internal/service/ctl_svc/write.go`），记忆是新增的免审例外，先例是 `agrctl send`。否决：走 MCP 工具 |
| 11 | 会话带上的记忆在首个回合时取一次快照，之后不变；会话中新写的记忆下个会话才带上，没有手动刷新 | 已核实：三个后端对提示词变化的反应不一致（Claude Code 常驻进程看不到变化，Codex 带工具时每轮重发，Pi 提示词一变就重启进程），不冻结会打破提示词缓存或重启进程。否决：每轮取最新；手动刷新（用户否决了它所在的入口，见决策 19） |
| 12 | 按后端分三档：Claude Code、Codex、Pi 完整支持；内置后端只带摘要，不能写也读不到详情；acp、openclaw、hermes 不带 | 用户已决定后三者先不支持。已核实：这三个后端的运行时不读 `SystemPrompt`；内置后端能收到提示词，但不在拿到 `agrctl` 端点的名单里（`internal/pkg/agentruntime/clienv.go` 只给 Claude Code、Codex、Pi、ACP） |
| 13 | Claude Code 自带的自动记忆默认保留，用户可在设置里改为在 Agentre 会话中关闭；该开关只存本机 | 用户已决定（「可以并存，用户可以自己配置」）。原生记忆本身就是本机的，所以开关不同步 |
| 14 | 侧栏新增「记忆」入口，作为唯一的管理界面；agent、部门、项目自己的页面只放一行条数并跳转过来 | 用户已决定（「可以加一个侧栏入口」）。否决：在各归属页面各放一份列表——两处维护同一份内容 |
| 15 | 记忆作为新的同步种类在设备间同步；会话快照只存本机 | 已核实：同类资源都这样同步（`pkg/syncwire/syncwire.go`）。按条同步，两台设备同时新增不会互相覆盖 |
| 16 | 注入段落的固定文字跟随应用当前语言，条目原文照搬 | 用户已确认（2026-11-11，随 spec 审批）。否决：固定英文——用户是中文优先，段落里中英混排没有必要 |
| 17 | agent 的记忆开关默认为开，对已有的 agent 也是 | 用户已决定（2026-11-11）。代价：升级后受支持后端的新会话都会多出一段固定说明，agent 会开始自己记东西。否决：默认关 |
| 18 | 同一层里摘要完全相同的写入不新增，返回已有的那条 | 已核实：Hermes 对完全重复的写入也这样处理。同一个 agent 的多个会话并行时最容易重复记同一件事 |
| 19 | 对话界面里只有 AI 写入记忆后的卡片：不提供消息上的手动「记住」操作，右侧面板不加记忆一栏 | 用户已决定（2026-11-11，「这个功能不需要」）。用户手动加记忆在记忆页做，或直接让 agent 记 |
| 20 | 不做按每条用户消息的相关度召回 | 用户已决定（2026-11-11）。后果：超出预算的条目只有 agent 主动列出才看得到 |

## 记忆条目

- **内容**：摘要必填，至多 200 字，不含换行；详情可选，至多 4,000 字。超长的写入被拒绝，并说明上限。
- **归属**：全局、某个部门、某个 agent、某个项目之一。
- **状态**：正常或已归档。已归档的不进提示词，可以恢复。
- **置顶**：置顶的条目在预算取舍时排在最前。
- **来源**：创建者是用户，或某个 agent 在某个会话里；创建后不变。
- **上一版**：每次修改摘要或详情时保留修改前的内容，只保留一版。恢复上一版会把当前内容和上一版对调。
- **归属被删除**：删除 agent、部门或项目时，归属于它的记忆一并删除，无论删除发生在本机、从别的设备同步过来，还是在控制台上。本机这三处现有的删除确认里写明会删掉多少条记忆。
- **项目合并**：两个项目合并时，被并掉的项目的记忆移到保留的项目上，和看板任务等现有引用的处理一致（`internal/service/project_svc/merge.go`）。
- **内容检查**：写入时拒绝含有不可见字符或明显凭据格式（私钥头、常见令牌前缀）的内容，并说明原因。这只是底线检查，给 agent 的说明里另行要求不要记密钥。
- **不进日志**：记忆的摘要和详情不写进应用日志。

## 会话带上记忆

**前提**：agent 的记忆开关为开，会话使用的后端属于决策 12 的前两档。

- **取快照**：会话的首个回合开始时，按决策 2 收集可见的正常条目，每层按决策 5 取到预算为止，生成一段文字并保存为该会话的快照。之后每个回合都使用这份快照，包括恢复会话、进程重启和应用重启之后。
- **段落内容**：标题说明这是背景信息、不是指令、可能过时；按「关于用户、各级部门、agent 自己、项目」分节；每条一行，含编号、摘要、最近修改日期，有详情的标出。某层有条目因超出预算没带上时，该节末尾注明还有几条、可以用列出命令查看。
- **固定说明**：段落末尾只有几行：什么值得记、什么不记、一条只写一件事、默认记到自己那层，以及读写各用哪条命令。完整规则由记忆命令的帮助给出，不放进提示词。内置后端不带这几行。
- **位置**：接在 agent 自己的提示词之后。没有可见记忆时仍带上固定说明，使 agent 知道可以写。
- **子 agent 调用**：被调用的 agent 按自己的身份取自己的快照。
- **回退、重新生成、编辑重发**：这些都发生在同一个会话里（已核实：没有「从旧会话生成新会话」的功能，`internal/service/chat_svc/chat.go:1840`），沿用该会话的快照。
- **升级前已开始的会话**：没有快照，不带记忆。
- **远程执行**：会话在远程设备上执行时带上的内容与本地一致。远程设备上的 `agrctl` 版本不认识记忆命令时，不带段落。
- **开关为关**：不带段落，也不带固定说明。
- **让用户知道哪里不带**：记忆页上该 agent 的头部列出它的哪些执行目标不带记忆或只能读，以及原因（后端不支持、内置后端只能读摘要、那台设备需要升级）；全部完整支持时不显示。对话界面里不另行提示。

## Agent 读写记忆

**前提**：命令由某个会话里的 agent 发出。非会话调用方沿用现有规则（终端里的人直接执行，外部调用方在桌面端审批）。

- **读与检索**：列出可见条目，可按层筛选，可给关键词在摘要和详情里查找；按编号取一条的完整内容。只能读到本会话可见的条目；因超出预算没带上的条目也在列出结果里，已归档的不在。
- **新增**：给出摘要、可选详情、目标层。不指定层时记到 agent 自己；指定部门层时默认是 agent 直属的部门，也可以指明某个上级部门。目标层必须是本会话的 agent 所属的层，否则拒绝并说明。同一层里已有摘要完全相同的正常条目时不新增，返回已有的那条。
- **修改**：可以修改本会话可见的任何条目，包括用户写的。
- **删除**：对条目执行归档，同样不区分是谁写的。
- **免审批**：以上写入直接生效，不出审批卡，不要求有人值守。
- **超出预算**：写入后该层超出预算时，结果里说明超出多少，并要求合并或精简。
- **帮助**：记忆命令的帮助给出完整用法和记录规则，是固定说明里指向的那一份。
- 命令的呈现示意见 mockup ⑨；参数名按 `agrctl` 现有风格在实现时确定。

## 对话里

- **记忆卡片**：agent 的每次记忆写入在对话流里显示为一张卡片，取代通用的命令行呈现。卡片显示动作（记住了、改了记忆、归档了记忆）和摘要；写到共享层时标出是哪一层。
- **撤销**：新增的被彻底删除，修改的恢复上一版，归档的恢复为正常。撤销后卡片显示为已撤销，不可再点。条目在这次写入之后又被改过时，撤销被拒绝，卡片保持可点并就地说明原因。
- **编辑**：卡片上的编辑就地打开与记忆页相同的编辑表单。
- 对话界面没有其他记忆入口（决策 19）。

## 记忆页

**入口**：侧栏在 Hooks 之后新增「记忆」，图标用现有图标集里的 brain。

- **左列**：搜索框；「最近变更」；「全局」；部门（按组织树缩进）、Agent、项目三组，每行显示名称和正常条目数。搜索按摘要和详情过滤所有层，结果按归属分组显示。
- **右侧，选中某个归属**：
  - 头部：归属名称；该层的预算用量，超出时变为提醒色；归属为 agent 时有记忆开关，以及「让用户知道哪里不带」里的说明。
  - 添加框：输入摘要回车即新增，创建者为用户。
  - 分组：正常条目，置顶的在最前；「超出预算，本次不带」单独成组并变淡；「已归档」单独成组并默认收起；归属为 agent 时最后是「继承的」，按来源层列出条数，点开跳到那一层。
  - 行：摘要、创建者（会话可点回）、最近修改日期、有无详情。点行就地展开编辑摘要和详情。
  - 行操作：置顶、归档（已归档的是恢复）、恢复上一版（有上一版时）、移到其他层、删除。删除是彻底删除，就地二次确认。
- **右侧，选中「最近变更」**：按时间倒序列出所有层近 14 天内被新增、修改或归档过的条目，每条显示最近一次变更是谁做的、做了什么；可恢复上一版，已归档的可恢复。彻底删除的条目不出现。
- **状态**：加载中、空（见 mockup ②）、加载失败（按现有页面级失败的呈现）；保存失败时保留输入内容并就地说明。
- **其他设备的变更**：同步下来的变更到达后，当前列表随之更新；正在编辑的条目不被覆盖，保存时以后写的为准。

## 归属页面与设置

- **归属页面**：agent 详情、部门详情、项目设置里各加一行「记忆 N 条」，点击跳到记忆页并选中该归属。
- **设置 → 记忆**：一个选项，Claude Code 自带记忆在 Agentre 会话中「保留」或「关闭」，默认保留。选择关闭后，本机之后新启动的 Claude Code 进程不再加载和写入原生记忆；已在运行的进程不受影响。该选项只作用于在本机执行的会话。

## 桌面端、agentred、server 的分工

- **谁发起会话，谁说了算**：桌面端发起的会话（无论在本机还是远程设备上执行），由桌面端取快照、执行记忆命令。
- **agentred 不存记忆**：快照随运行请求原样交给它启动的 CLI；远程 CLI 里发出的记忆命令由它原样转回桌面端，是否免审批由桌面端判定。随 agentred 发布的 `agrctl` 认识记忆命令。
- **桌面端不在线时**：桌面端发起的远程会话本来就依赖桌面端在线，记忆不引入新的依赖。
- **server**：本 spec 里只是同步的中转和存储（见「同步」）。

## 同步

- 记忆条目在同一账号的设备间同步，包括状态、置顶和上一版。agent 的记忆开关随 agent 同步。
- 两台设备同时修改同一条时后写的为准，被覆盖的一方按现有「丢失的变更」方式呈现。
- 未登录时记忆只存在本机，功能不受影响。
- agentre-server 接受并存储这个新种类；在控制台删除 agent、部门或项目时，server 一并删除归属于它的记忆，否则这些记忆会带着失效的归属留在账号里，别的设备拉下来无法落库。除此之外 server 不做别的：在控制台那份 spec 落地之前，控制台发起的会话不带记忆，其中执行记忆命令会得到「不支持」的结果。

## 界面通则

所有新文案走 i18n（zh-CN 与 en）；明暗两套主题；新控件可用键盘操作并有可见焦点，图标按钮有无障碍名称。记忆卡片、编辑表单和列表行放在共享 UI 包里，桌面端通过端口接入；宿主未接端口时卡片退回通用的命令行呈现。

## Out of scope

- 控制台的记忆页、控制台会话带上记忆与 agent 提示词、server 端的记忆命令 → 控制台 spec。
- 整理（梦境）：自动合并、精简、归档与从会话记录提炼 → 整理 spec。在那之前，超出预算只靠 agent 在会话中自行整理和用户手动处理。
- 技能、会话检索、导入 CLI 原生记忆 → 各自的 spec。
- acp、openclaw、hermes 后端带上记忆；内置后端写记忆。
- 原生记忆开关作用于远程设备上执行的会话。
- 预算大小的用户设置；多于一版的修改历史；向量检索。

## Testing decisions

| Seam | What it verifies | Prior art |
|---|---|---|
| 记忆服务（仓储用 mock） | 可见范围的合成（部门链、归档排除）；预算取舍顺序；两条硬规则（只写所属层、删除即归档）；AI 可改用户写的条目；上一版的保留与对调；完全重复的新增；内容检查；归属删除时的级联（本机与同步两条路径）；项目合并时记忆迁移 | `internal/service/issue_svc` 的服务单测 |
| 记忆仓储（sqlmock） | 按归属、状态、修改时间的查询拼写 | `internal/repository/issue_repo` |
| 运行请求的组装 | 三档后端各自带上的内容；快照位于 agent 提示词之后；同一会话各回合内容相同；回退、重新生成、编辑重发沿用同一快照；开关为关、远程设备版本太旧、升级前已开始的会话不带；子 agent 用自己的快照 | `chat_svc` 中 `buildRunRequest` 的现有单测 |
| ctl 处理器 | 会话令牌写记忆不出审批卡；越层写入被拒；其他种类的写入仍要审批 | `internal/service/ctl_svc` 的现有单测 |
| 同步适配器 | 新种类的装载、应用、删除与引用；载荷类型表的守卫 | `sync_svc/adapter_issue.go` 的单测、`pkg/syncwire/payload_test.go` |
| 共享包组件（Vitest） | 记忆卡片的三种写入与撤销各状态；列表的分组（超预算、已归档）、行内编辑与失败保留输入；未接端口时退回通用呈现 | `agentre-ui` 中 `ctl-approval-card` 与排队条的组件测试 |
| 桌面端页面（Vitest） | 侧栏入口与路由；左列计数与搜索；最近变更；agent 头部列出受限的执行目标；同步变更到达后的刷新；i18n 键覆盖 | `org` 页面的现有测试、`i18n.test.ts` |

不能自动化的部分由收尾时的真机运行覆盖：在真实 Claude Code 会话里，agent 写下一条记忆后新开会话确实带上；远程执行的会话里记忆命令可用；Codex 的沙箱里记忆命令能连回 Agentre；关闭原生记忆后新进程确实不再加载它；两套主题下的对比度与键盘焦点顺序。迁移按仓库既有流程用带真实数据的库手工核对。
