# 凭据去 JWT 化，与账号设备的自动直连

> Status: Approved
> Owner: agentre-server 鉴权 + agentred / 桌面端远端连接
> Last updated: 2026-09-11

**Objective:** agentre-server 签发的所有凭据改为不透明令牌、由 server 统一核验；同一账号下的桌面端与 agentred 在 server 可达时自动建立经证书固定的 LAN 直连，此后即使 server 不可达，桌面端仍能以完整的账号身份直连 agentred。

**Hard invariant:** 已经手动 LAN 配对（`ws://` 地址 + 配对令牌）的直连，行为与本轮之前完全一致，server 不可达时照常可用；账号级能力（会话扇出、跨对端的账号级操作）只授予经账号核验过的连接。

## Problem

1. **server 为 JWT 背着一整套密钥管理，却没有从「无状态」里得到任何东西。**（已核实）server 每一次 Bearer 校验都已经查 Redis 黑名单（`agentre-server/internal/middleware/resolve.go` 的 `verifiedJWT`），刷新令牌早已以哈希存在 `device_tokens`；与此同时部署要维护 RSA 密钥对、`kid` 轮换、etcd 里的私钥路径、compose 卷与 Helm Secret（`agentre-server` 工作区里还有一份未提交的 Helm JWT Secret 挂载改动）。
2. **离线验签是 JWT 唯一承重的地方，而它的吊销是残缺的。**（已核实）agentred 的 `auth.account` 只凭缓存公钥与缓存吊销列表判定（`internal/daemon/auth/auth.go:159-189`），吊销最多滞后一个轮询周期（`internal/daemon/daemon.go:1207-1211`）；桌面端入站那一侧**完全不查吊销**（`internal/peer/account_credential.go:39-41`）。为支撑离线验签，两端各自维护公钥缓存、吊销轮询与一份手写的 RS256 解析。
3. **「都登录了同一个账号」并不能让桌面端离线直连 agentred。**（已核实）桌面端拿到 agentred LAN 地址的唯一途径是手动配对；从账号收编来的设备行没有地址、只走中转（`internal/service/remote_device_svc/adopt.go:27-29`、`conn_pool.go:388-397`）。于是 server 一不可达，账号设备就全部够不着——离线验签在这条用户最在意的路径上其实从未生效。
4. **LAN 默认明文，且凭据先于对端身份发出。**（已核实）agentred 默认监听 `0.0.0.0:7456`、未配证书时为 `ws`（`internal/daemon/state/types.go:104`），也没有自签证书的能力；直连握手先把凭据发出去，之后才复核 daemon 身份（`internal/service/remote_device_svc/dial.go:81-105`）。任何「自动拨号」若沿用这条路，笔记本换到别的网络时会把凭据交给恰好占着同一 IP:端口的陌生主机。
5. **LAN 配对连接没有账号身份。**（已核实）`auth.connect` 进来的连接不写 `AccountID`，不参与会话扇出，也做不了账号级的跨对端操作（`internal/daemon/protobuf_registry.go:100-130`，`internal/daemon/daemon.go` 的 `subscribersLocked`，R13）。自动直连若复用它，直连会比中转少一截能力。
6. **agentred 把中继的 401 当成永久状态。**（已核实）HubLink 收到 401 不刷新凭据，只能等定时刷新（`internal/daemon/relaytransport/hub.go:38`、`:203`、`:386`）。凭据格式一换，升级后的 agentred 手里那张旧令牌会让它离开中继最长一个 access TTL（2h）。

## Actors and user stories

1. 作为同时在桌面端和 agentred 上登录了同一账号的用户，我希望两台机器在同一局域网里时自动走直连，server 挂了也照样能用 agentred、照样收到会话的实时更新。
2. 作为 server 的运维者，我希望不再维护、轮换、挂载任何签名密钥。
3. 作为账号所有者，我希望在控制台撤销一台设备后，它的凭据在 server 可达的所有路径上立即失效。
4. 作为已经手动配对过 agentred 的用户，我希望这次改动之后我的直连一点都不变。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 本轮只动 `agentre-server` 与 `agentre`（桌面端、agentred、`pkg/wire`）；`agentre-hub` 不在范围 | 用户决定。hub 的 JWT 自成一套，没有任何外部验签方，与本轮无耦合。Rejected: 三仓一起改 —— 把一个独立的小改动拖进跨仓发布 |
| 2 | 设备 access token、浏览器中继票据、server 自用的镜像 / 端口转发凭据**全部**改为不透明令牌 | server 内部每次校验本就查存储（Problem 1）；留任何一种签名凭据就留着整套密钥管理。Rejected: 保留 JWT 只清理部署 —— 密钥与离线验签的维护面都还在；换成另一种签名格式 —— 密钥管理原样保留 |
| 3 | 接收方（agentred、桌面端入站）对 `auth.account` 一律**向 server 在线核验** | 用户决定。吊销立即生效，并补上桌面端入站不查吊销的缺口（Problem 2）。Rejected: 中继为对端作保 + LAN 在线核验 —— 两条信任路径并存，且中继信封也要改 |
| 4 | 核验时 server 不可达 → 以一个**新的、独立的**错误码拒绝，桌面端视为可重试 | 桌面端连接池把 -32001 当作「可能过期」并去刷新凭据（`conn_pool.go:308-355`）；server 不可达时刷新必然失败，混用只会制造一次无意义的刷新并让失败原因失真。Rejected: 复用 -32001 |
| 5 | 接收方把**成功**的核验结果按令牌摘要缓存 **60 秒**；失败不缓存 | 用户确认。与今天 agentred 吊销列表的一分钟轮询滞后同量级；浏览器每条通道、每次重连都要握手，不缓存就是每次一个 server 往返。Rejected: 不缓存 —— 握手延迟随通道数线性增长；缓存到令牌过期 —— 吊销滞后可达 2h |
| 6 | 设备 access token 只以哈希存于 MySQL 的设备令牌表；中继票据与 server 自用凭据存 Redis（2 分钟） | 设备令牌表已经逐枚记录每次签发与刷新链，访问令牌放进去就不引入新的存储面，Redis 故障也不会拖垮设备端点；中继票据的一次性消费本就依赖 Redis 且 fail-closed。Rejected: 全部放 Redis —— 今天 Redis 故障时设备请求仍放行（黑名单 fail-open），改后会变成设备端点全灭 |
| 7 | 核验端点只回答「与调用方同一账号」的令牌；跨账号一律答「无效」 | 否则核验端点就成了任意令牌的查询预言机。Rejected: 只要求调用方已登录 |
| 8 | 「账号登录 → 自动 LAN 直连、离线可用」与去 JWT **同一轮交付** | 用户决定。去掉离线验签后，离线能力改由本地直连凭据承担，两件事分开发布会有一段离线能力的空窗。Rejected: 分两轮 |
| 9 | agentred 自动签发的本地直连凭据**绑定账号**：桌面端登出即删；agentred 登出或换账号即全删；agentred 能连上 server 时按账号设备清单清掉已撤销 / 已不在账号里的设备；离线期间持续有效 | 用户决定。账号是信任边界，而离线可用要求这个判断能在离线时暂时沿用。Rejected: 再加离线有效期上限 —— 长期离线的机器会丢直连；与手动配对一样永久有效 —— 活过登出与撤销 |
| 10 | 自动直连**只走 `wss` + 证书固定**：agentred 首次启动生成并持久化自签证书，证书经已核验的账号握手下发给桌面端 | 用户决定。TLS 固定先于凭据发出完成对端身份校验，从根上消除 Problem 4 的泄露面。Rejected: 允许明文 —— 换网络即泄露；只在用户配了证书时启用 —— 默认安装永远用不上 |
| 11 | 使用自动生成的证书时，同一监听端口**同时接受 `ws` 与 `wss`**；用户自己配置了证书时维持今天的行为，并下发该证书用于固定 | 用户确认。手动配对的 `ws://…:7456/rpc` 是今天的标准形态（桌面端配对表单的示例），必须原样可用。Rejected: 改为只接受 `wss` —— 打断既有手动配对；另开一个端口 —— 多一个要放行、要通告的端口 |
| 12 | 直连使用一种**新的握手方式**，成功后连接带上与中转相同的账号身份与对端指纹 | 账号级能力只授予带 `AccountID` 的连接（Problem 5），自动直连必须与中转等价。Rejected: 复用 `auth.connect` —— 直连丢掉会话扇出与账号级操作 |
| 13 | LAN 地址与证书只经账号握手从 agentred 直接交给桌面端，**不上报 server** | 首次建立直连本就需要一次在线核验，这条已认证的连接就是最短的交付路径；局域网拓扑不进入 SaaS。Rejected: agentred 上报 server、桌面端从设备清单取 —— 多一份需要同步与保密的数据 |
| 14 | 三端同时升级，协议版本号递增，不做新旧兼容；不要求任何人重新登录 | 首发按全新发布处理。刷新令牌格式不变，旧 access token 被拒后由刷新换得新令牌。Rejected: 过渡期同时接受两种令牌 |
| 16 | 自动直连保存 agentred 下发的**全部**地址并在直连时并发尝试 | agentred 在通配监听下会通告每块可路由网卡的地址（`pkg/wire/protorpc/server.go` 的 `AdvertiseURLs`），桌面端事先不知道自己此刻与哪一块同网段；证书固定保证连错主机时不会发出凭据。Rejected: 只存第一个 —— 多网卡机器上可能恰好存了一个从桌面端路由不到的地址，直连永远建不起来 |
| 15 | 本规格落在 `agentre`；跨仓按依赖顺序交付：`agentre` 先提交推送，`agentre-server` pin 该修订后改动，两端一起部署 | `agentre` 持有 wire 协议与共享生成物（根 `AGENTS.md` 的跨仓交付顺序）。Rejected: 规格放 server |

## 凭据与核验（agentre-server）

**S1 签发。** 设备完成设备流授权或刷新时，server 发出的 access token 是不含任何可解析内容的随机串，有效期与刷新流程与今天一致；server 只保存它的摘要。浏览器换取中继票据、server 为镜像或端口转发自用签发凭据时，同样得到随机串，有效期 2 分钟，且其账号、类型与对端指纹由 server 记录。刷新令牌的格式与轮换语义不变。

**S2 Bearer 校验。** 任何带 Bearer 的请求，server 以令牌摘要查到其账号、设备、类型与对端指纹，据此放行或拒绝；设备端点、中继端点、`SessionOrDeviceAuth` 三类入口的接受 / 拒绝判据保持今天的等价关系（设备凭据进不了只收票据的入口，反之亦然）。令牌未知、已过期或所属设备已撤销时一律 401。Redis 不可用时，设备 access token 的校验不受影响。

**S3 中继票据。** 一张票据连接中继仍然只能成功一次；在有效期内它可以被任意次地出示给对端做账号握手并通过核验。

**S4 撤销与登出。** 设备被撤销（控制台操作或设备自身登出）后，它名下的所有 access token 与刷新链立即失效；此后任何接收方对这些令牌的核验都答「无效」。网页登出后，该会话换出的票据立即失效。

**S5 核验端点。** 前提：调用方持有自己有效的设备凭据。动作：提交一枚待核验令牌。结果：令牌有效且与调用方同属一个账号时，返回账号、设备、类型、对端指纹与剩余有效期；否则（未知、过期、已撤销、跨账号）返回同一种「无效」答复，不区分原因。端点受速率限制。

**S6 删除的对外面。** 公钥端点、吊销列表端点、两个 JWT 专属错误码、所有签名密钥配置与自动生成开关一并去除；服务启动不再需要任何密钥文件。部署面同步收口：compose 的密钥卷与自动生成开关、配置模板里的密钥段、Helm 模板里的任何密钥挂载、以及部署文档与 README 中「准备 / 轮换 / 备份密钥」的全部章节都不再存在。已有环境升级后，配置中心里残留的旧密钥配置不影响启动，由运维在升级后删除。

## 接收方的账号握手（agentred 与桌面端入站）

**H1 在线核验。** 前提：接收方已登录某账号。动作：对端发起 `auth.account`。结果：接收方向 server 核验该凭据；有效、且账号与接收方所登录账号一致时握手成功，连接获得账号身份与 server 返回的对端指纹（与今天从令牌里读出的值相同，`conversation_id` 的推导不变）；否则以今天「凭据被拒」的同一错误拒绝。

**H2 结果缓存。** 同一枚凭据在 60 秒内再次握手时，接收方直接沿用上一次成功的核验结果，不再访问 server；失败结果不缓存。

**H3 server 不可达。** 核验请求无法到达 server（或 server 无应答）且缓存未命中时，握手以新的「账号服务不可达」错误拒绝。桌面端收到这个错误时不刷新自己的凭据、不把设备判为「重试也没用」，按可重试的连接失败处理。

**H4 接收方自身凭据失效。** 接收方自己的凭据无效且刷新不成时，它无法核验任何对端，握手按「接收方未就绪」拒绝，与今天「缺少验证材料」同一形态。

**H5 登录取身份。** `agentred login` 完成设备流后，从 server 取得账号标识，不再解析令牌。

**H6 删除的本地面。** agentred 的吊销轮询、公钥刷新以及 `state.json` 中对应的字段，桌面端的公钥缓存，两端共用的 RS256 验签实现，一并去除。

## 自动直连

### 证书与监听

**D1.** 前提：agentred 未配置 TLS 证书。动作：agentred 首次启动。结果：生成一张自签证书并持久化在它的数据目录中，此后重启沿用同一张；LAN 监听端口同时接受 `ws` 与 `wss`，手动配对使用的 `ws://` 地址照常可用。

**D2.** 前提：agentred 已配置 TLS 证书。结果：监听行为与今天一致，自动直连固定的就是这张证书。

### 下发

**D3.** 前提：桌面端与 agentred 登录同一账号，server 可达。动作：桌面端（设备类型为 `desktop`）以自己的账号凭据完成一次 `auth.account`（中转或直连均可）。结果：握手应答额外携带 agentred 当前可被他机访问的 `wss` 地址列表、它正在使用的证书，以及 agentred 为这台桌面端签发的本地直连凭据；agentred 记录该凭据对应的桌面端指纹与签发时的账号。浏览器票据、server 自用凭据以及其它设备类型的握手不携带这些内容。

**D4.** 同一台桌面端再次完成账号握手时，地址与证书以最新值下发；本地直连凭据沿用已有的那一张，只在 agentred 那边不存在时重新签发。

**D5.** agentred 找不到任何可被他机访问的地址（例如只监听回环地址）时，不下发地址，也不签发本地直连凭据；这台设备维持仅中转。

**D6.** 桌面端收到 D3 的内容后，把对应设备行记为「来自账号的直连」：保存下发的**全部**地址与证书固定模式，凭据存入系统钥匙串。该行在设备面板里按今天 LAN 行的样式呈现（地址与证书固定标记），地址位显示最近一次直连成功的那个地址（尚未直连成功过时显示列表中的第一个），不新增文案。

### 直连握手

**D7.** 前提：桌面端持有某台 agentred 的地址、证书与本地直连凭据。动作：桌面端需要连接这台 agentred。结果：直连与中转两条路径同时发起、先成功者胜（与今天一致）；直连路径对保存的全部地址并发尝试，任一地址连上即作为直连结果；每个地址都先完成 TLS 并校验证书与固定值一致，之后才发出本地直连凭据。

**D8.** 前提：直连 TLS 已通过。动作：桌面端以新的握手方式出示本地直连凭据。结果：agentred 在不访问 server 的情况下校验凭据，并确认凭据记录的账号等于 agentred 当前登录的账号；两者都成立时握手成功，连接获得与经中转完成 `auth.account` **相同**的账号身份与对端指纹，会话扇出与账号级操作完全可用。凭据不匹配或账号不一致时以「凭据被拒」拒绝。

**D9.** 前提：server 不可达，桌面端与 agentred 在同一局域网。动作：桌面端使用 agentred（打开、续聊、接收实时更新）。结果：经 D8 的直连完成，行为与 server 可达时一致。

### 生命周期

**D10 桌面端登出。** 桌面端登出时，所有「来自账号的直连」行的地址、证书与钥匙串中的本地直连凭据被清除，这些行按今天收编行的方式处理。

**D11 agentred 登出或换账号。** agentred 登出或切换到另一个账号时，它签发过的所有本地直连凭据被删除，此后任何桌面端出示它们都被拒。

**D12 在线对账。** agentred 能连上 server 时，每分钟（与今天吊销轮询同一周期）以账号设备清单对账一次，重新连上 server 时立即对账：凭据所属桌面端已被撤销或已不在账号里，对应本地直连凭据被删除。桌面端登出会在 server 上撤销该设备，因此也经由这条路径传到 agentred。

**D13 离线期间的撤销。** server 不可达期间发生的撤销或登出，在 agentred 重新连上 server 并完成对账之前不生效；这是离线可用的代价，已接受。

**D14 手动配对覆盖。** 用户对一台「来自账号的直连」设备执行手动 LAN 配对后，该行转为手动配对行，不再随账号登出而清除，其直连改用手动配对的凭据与地址。

**D15 用户移除。** 用户在设备面板移除一台「来自账号的直连」设备时，本机的地址、证书与本地直连凭据一并删除，并按今天的移除记录阻止它被再次收编。

### 失败路径

**D16.** agentred 的 IP 变化、证书被重新生成或用户更换了证书时，直连以连接失败告终（不发出凭据），中转胜出；下一次成功的账号握手刷新地址与证书。证书与固定值不一致不触发今天的 TOFU 告警样式。

**D17.** 桌面端所在网络路由不到 agentred 的地址时，直连失败、中转胜出，设备不因此显示为异常。

**D18.** server 不可达且直连也不可达时，设备不可用，与今天仅中转设备在 server 不可达时的表现一致。

## 发布与兼容

**P1.** server、agentred、桌面端必须同时升级；wire 协议版本递增，版本窗口不接受旧版本，旧端按今天的协议不兼容路径提示升级。

**P2.** 升级不要求任何人重新登录。升级后首次出示旧 access token 被拒时：桌面端按今天的 401 行为刷新后重试；agentred 的中继连接收到 401 时**刷新一次凭据并重试**，刷新本身被拒才进入今天「需要重新登录」的永久状态。

**P3.** 已经手动 LAN 配对的连接在升级前后行为不变（Hard invariant）。

## 安全与隐私

- 不透明令牌不携带任何可读的账号或设备信息；server 只存摘要，日志不得输出令牌原文或摘要全文。
- 本地直连凭据只在 TLS 证书固定校验通过之后发出；它与证书、地址只经已核验的账号连接下发。
- agentred 的私钥只存在它自己的数据目录，不离开本机；桌面端只保存证书本身。
- LAN 地址不上报 server。
- 核验端点不泄露跨账号令牌的任何状态（S5）。

## Out of scope

- `agentre-hub` 的 JWT（决策 1）。
- 桌面端移除手动配对设备时不通知 agentred 吊销配对令牌 —— 既有缺口，与本轮无关。
- LAN 自动发现（mDNS 等）：地址只来自账号握手。
- 已建立连接在握手之后的持续复核：今天没有，本轮也不加（server 侧中继连接的既有复核不变）。
- 网页控制台的界面：浏览器只持有票据、从不解析，除传输层字段名外无可见变化。
- `agentre-server` 工作区里那份未提交的 Helm JWT Secret 挂载改动如何处置，由其作者决定；本轮落地后它不再有意义。

## Testing decisions

| Seam | What it verifies | Prior art |
|---|---|---|
| server 鉴权中间件 | 不透明令牌放行 / 拒绝；设备凭据与票据不串入口；三类入口的 Bearer 判据等价 | `agentre-server` 的 `bearer_parity_test.go`、`device_jwt_test.go` |
| server 设备令牌服务 | 签发只存摘要；刷新轮换；撤销后令牌与刷新链立即失效；Redis 不可用时设备令牌校验不受影响 | `device_svc` 既有用例（mockgen） |
| server 核验端点 | 同账号返回身份与剩余期；未知 / 过期 / 撤销 / 跨账号答同一种无效 | `device_ctr` 既有用例 |
| server 中继票据 | 连接中继只成功一次；有效期内可反复核验；网页登出后失效 | `relay_ticket_test.go` |
| agentred 账号握手 | 在线核验成功写入账号身份与对端指纹；账号不一致被拒；server 不可达返回新错误码；60 秒缓存命中不访问 server、失败不缓存 | `internal/daemon/auth/auth_test.go` |
| agentred 自动直连 | 证书首次生成并复用；`ws` 与 `wss` 同端口可用；桌面端握手下发地址 / 证书 / 凭据，其它类型不下发；新握手离线成功并带账号身份；账号不一致被拒；登出 / 换账号全删；对账删除已撤销设备 | `internal/daemon/integration_test.go` |
| 桌面端连接池 | 「账号服务不可达」不触发刷新、不判终止；自动直连行在中转不可用时经直连连上 | `conn_pool` 既有用例 |
| 桌面端设备服务 | 下发内容落行与钥匙串；登出清除；手动配对覆盖；移除后不再收编 | `remote_device_svc` 既有用例 |
| 升级行为 | agentred 中继 401 刷新一次后重试，刷新被拒才进入永久状态 | `relaytransport` 既有用例 |
| 端到端 | `agentre` 的 `make e2e`（含 remote-peer 冒烟）与 `agentre-server` 的 `make e2e` 全绿 | 既有 e2e |

无法自动化、由运行期验证覆盖（`coding.local` 上的真 server + 真 agentred + 本机桌面端）：

1. 三端登录同一账号，首次经中转握手后设备行出现直连地址与证书固定标记。
2. 停掉 server 后，桌面端仍能打开并续聊 agentred 上的会话，且能收到另一端发起会话的实时更新。
3. server 恢复后在控制台撤销这台桌面端，对账之后它的直连被拒。
4. 升级前已登录的 agentred 升级后无需重新登录即回到中继。
