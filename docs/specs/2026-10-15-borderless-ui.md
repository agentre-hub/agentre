# 无边框改版（桌面端）：外框 + 内容页、去掉结构线、设置改为对话框

> Status: Approved
> Owner: desktop app maintainers
> Last updated: 2026-10-15

**Objective:** 桌面端所有页面在浅色与深色下都不再用线条划分区域：窗口外框（标题栏、图标栏、左侧列表、Tab 条、右侧栏、状态栏）是同一个底色，工作区是一张浮起的圆角内容页，页内的卡片、代码块、设置分组、按钮与输入框都靠填充而不靠描边；设置从路由页改为浮在当前页面上的对话框。

**Hard invariant:** 正文与弱化文字对它落到的每个表面仍不低于 4.5:1（含新增的外框色与内容页色）；键盘焦点环（2px 实色，见 `docs/specs/2026-10-13-color-audit.md` 决策 7）不变且是页面上唯一会「出现」的线；未选中的复选框与单选按钮保留 `control-border`；`tokens.test.ts` 现有守卫除「边的四档」按本文改写外继续通过；所有现有功能入口（含跳到某个设置子页的入口）行为不变，只是落点从路由页变成对话框。

## Problem

证据来自源码检索、隔离验证台对真实应用的渲染与边框审计脚本；对照 mockup 在 `.dev-kit/artifacts/2026-10-15-borderless-ui/mockups/`（本地证据，不入库；评审页 `index.html` 由该目录的 Vite 服务提供）。

1. **线条过多。** 宿主 `frontend/src` 238 处、共享包 `packages/agentre-ui/src` 256 处画边的类（`border` / `border-[tblrxy]`），分布在约 200 个文件；其中大多数分隔的是**同一底色**的两块区域（侧栏工具条、面板头、卡片内头尾、弹层页眉页脚），线是唯一的分隔手段，直接删会让区域粘在一起。（已验证）
2. **浅色主题的表面没有层级。** `sidebar` = `secondary` = `muted` = `code-surface` = `#f4f4f5`，会话侧栏与 Tab 条同色；`border` = `rail` = `#e4e4e7`，标题栏、图标栏、状态栏的边与外框同色、根本看不见；`card` / `popover`（`#ffffff`）对 `background`（`#fafafa`）只有约 1.04:1，卡片、输入框外框、设置分组在浅色下几乎全靠边才被认出来。深色本来是一条清楚的五级阶梯（rail < sidebar < background < card < popover）。（已验证）
3. **弹层画了两次边。** `Dialog`、`DropdownMenu`、`Select` 内容面同时有 `border` 与自带 1px 环的 `shadow-overlay` / 自定义阴影。（已验证）
4. **outline 按钮与字段的边在无边风格里格格不入。** outline 是用得最多的按钮变体（约 131 处）；字段（输入框、文本域、下拉、搜索框）在 2026-10-13 的配色收口里统一成 `field-border`。用户在评审页上指出组织页、Hooks 页的搜索框「还是有边框」，并给出参考设计：字段是无边的灰底填充。（用户陈述 + 已验证）
5. **标题栏右侧是一排带框的文字按钮。** 「3 已结束 ⌄」「□ 停止」都是 outline 按钮；后台任务入口在没有任务运行时仍常驻显示「N 已结束」。（已验证；用户在评审中要求处理）
6. **右侧栏（大纲 / 变更 / 目录）与对话内容同底色，不易区分。** 右侧栏现在是聊天面板内部的一列，`bg-sidebar` 加左边线；去掉边线后它与对话内容融在一起。（用户陈述，2026-10-15）
7. **设置是一个路由页。** 打开设置会离开当前页面；用户给出的参考设计是浮在当前页面上的对话框（左侧灰底导航、右侧白底内容、右上角关闭）。（用户陈述）

## Actors and user stories

1. As a `桌面端用户`, I want 界面上只剩内容本身而没有满屏的分隔线, so that 注意力落在对话与任务上，而不是框线上。
2. As a `同时跑多个 agent 的用户`, I want 标题栏只在有后台任务运行时才出现一个安静的提示、悬停就能看到在跑什么, so that 不用点开弹层也知道还有没有东西在跑。
3. As a `桌面端用户`, I want 打开设置时不离开当前页面, so that 改完设置关掉就回到原来的对话。
4. As a `贡献者`, I want 「什么时候用填充、什么时候允许出现线」有一条写得出来的规则和守卫, so that 新写的界面不会把线条重新攒回来。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 方案 A「外框 + 内容页」：外框一个底色，工作区是圆角、四周留缝的内容页；层级靠表面色阶 | 用户在评审页对照现状 / A / B 后选定。Rejected: B「全平铺」（一个底色、只靠留白）——侧栏的边界和拖拽位置都看不出来，右侧栏悬空；C「只删冗余边」——几乎看不出变化 |
| 2 | 右侧栏放到外框上（P1），与左侧列表对称；页签保留文字（大纲 / 变更 / 目录） | 用户选定。Rejected: P2 内容页里凹进去的面板——多一层表面；页签改纯图标——用户要求保留文字，真正的问题是与内容同底色 |
| 3 | 后台任务入口改为一个机器人图标按钮，有任务运行时右上角一颗 6px 绿点；没有运行中的任务时整个按钮不显示；数量与明细在悬停预览卡里 | 用户在 R1/R2/R3 与 S1–S4 对照后选定。Rejected: 右下角数字角标——太大、挡住图标；数字放在图标旁边——常驻数量价值低；图标整体变绿——只靠颜色；按类型拆成两个计数——用户要一个按钮；输入框上方托盘——占对话区 |
| 4 | 停止按钮改为纯图标（实心方块），悬停时红底提示 | 用户提出标题栏多用纯图标按钮 |
| 5 | outline 按钮去边，改为与 secondary 同一套相对前景色的填充 | 用户在「按钮去边、字段留边 / 控件全部改填充 / 控件都保留边」中先选了第一项 |
| 6 | 字段（输入框、文本域、下拉、搜索框及手写的同类）也去边，改为相对前景色的填充；聚焦时只有焦点环 | 用户看到组织 / Hooks 的搜索框仍有边后，给出参考设计（无边灰底字段），**推翻 2026-10-13 配色收口的决策 14** 与本轮决策 5 的「字段留边」部分。Rejected: 保留 `field-border`——与参考设计不符 |
| 7 | 复选框、单选按钮、开关保留现状 | 它们的边就是控件本体（配色收口决策 3 / 14 的理由仍成立） |
| 8 | 设置改为浮在当前页面上的对话框 | 用户给出参考设计并在评审页确认。Rejected: 独立的系统窗口——Wails v2 单窗口，代价大；用户确认的参考就是页面内对话框 |
| 9 | 页签类控件（Hooks 的「脚本 / 运行日志」等下划线页签）改为填充的分段控件 | 与参考设计的分段控件一致；下划线是本轮审计后唯一剩下的结构性线 |
| 10 | 侧栏「需要关注」分组的琥珀色左条、模型表的「默认」单选保留 | 它们表达状态或本身是控件，不是分隔线 |
| 11 | 范围是所有桌面端页面；`agentre-server` 网页端另起一份规格，在本文交付并推送后进行 | 用户要求「所有页面都一起做」「server 也要处理」；跨仓交付顺序由 `AGENTS.md`「Cross-host frontend ownership」规定 |
| 12 | 不带子页的入口回到本次运行里上次打开的子页，首次为「外观」；不跨重启持久化 | 对话框是「临时打开再关掉」的用法，反复打开同一子页是常态。Rejected: 每次都从「外观」开始（现状）——路由页时代每次重新挂载的副作用，不是设计；跨重启持久化——没有用户诉求，多一个存储键 |
| 13 | ⌘, 在对话框打开时关闭它；Esc、关闭按钮、点击遮罩也关闭；嵌套对话框只关最上一层 | 与系统偏好设置类窗口的习惯一致，参考设计右上角有关闭。Rejected: 点击遮罩不关闭——设置里没有易丢的未保存表单（编辑都在二级对话框里），不需要防误关 |
| 14 | 从别的对话框跳进设置时先关掉那个对话框 | 避免两层模态叠在一起、关掉设置后又露出一个过期的对话框 |

## 表面阶梯

新增三个表面 token 与两档相对填充（token 两个主题都有值，有 `--color-*` 映射），取值是评审页上用户确认的观感：

| Token | 浅色 | 深色 | 用在 |
|---|---|---|---|
| 外框 `chrome` | `#ececee` | `#111214` | 标题栏、图标栏、各页的左侧列表（会话列表、组织索引列、Hooks 列表）、Tab 条、右侧栏、状态栏、设置对话框的导航列 |
| 内容页 `sheet` | `#ffffff` | `#1b1c1f` | 工作区内容页、设置对话框的内容区、活动 Tab |
| 抬起 `raised` | `#ffffff` | `#27282c` | 外框上的选中项：选中的会话行、图标栏当前项、侧栏筛选的当前项、Hooks 选中行、右侧栏大纲的当前条目 |
| 填充 | 前景色 5%（字段）/ 8%（按钮、悬停 12%） | 同左 | 字段、按钮、卡片、代码块、设置分组；按脚下表面相对取色，所以在内容页、填充分组、外框上都比脚下深一级 |

- 外框与内容页之间不画线，靠色阶区分：浅色 1.18:1、深色 1.10:1；内容页四周与外框之间留 8px 缝，圆角 12px；浅色下内容页带一圈极淡的投影（0.5px 环 + 1–3px 软影），深色不带。
- 正文对外框 15.0 / 15.3，弱化文字对外框 4.90 / 6.09、对内容页 5.78 / 5.53、对抬起色 5.78 / 4.78（浅 / 深，按现行 `muted-foreground` 计算，已验证）。
- 弱化文字（含字段占位符）对每一种填充面——包括悬停态、以及落在外框上的字段——不低于 4.5:1。评审页的取值有两处不达标：深色按钮悬停（前景 12%）4.03、浅色外框上的字段（前景 5%）4.42；填充比例在实施时以守卫为准下调或分档，观感以评审页为参照。
- 填充比例保持评审页的 5/7%（字段）与 8/12%（按钮）；单靠下调比例达不到 4.5（浅色外框上的字段要降到 4%，那时与外框只剩 1.076:1），所以新增一个只在填充面上生效的弱化文字色 `--fill-muted-foreground`（浅 `#5a5a61` / 深 `#abaeb4`），由填充工具类换入，做法与 `bg-accent` 换文字色相同；最差处 4.58 / 4.59。用户确认（2026-10-15）。
- 浅色 `--status-idle` 由 `#8c8c93` 微调为 `#84848b`：原值落在外框上只有 2.83:1，低于状态点的 3:1；新值在外框上 3.15、在白色上 3.71。这是本文唯一改动的现有色值，用户确认（2026-10-15）。
- 除上一条外，现有 token 的色值不变；`--border` 不再用于画结构线（见下节），保留给本文明确保留的少数用途。

## 结构线

- **去掉：** 外框各带之间的边（标题栏下、图标栏右、状态栏上、侧栏左右、Tab 条下与 Tab 之间、右侧栏左），面板头与面板体之间的分隔线，卡片外框与卡片内头尾的分隔线，列表行之间的分隔线（`divide-*`、`border-b last:border-b-0`），表格行线，弹层与对话框的边及其页眉页脚分隔线，滚动时输入框上方出现的分隔线。
- **替代：** 同一底色的两块区域之间用留白或填充分开；滚动后标题与正文之间用一道渐隐代替分隔线；弹层与对话框只靠表面色 + 阴影立起来（阴影不再自带 1px 环）。
- **保留：** 键盘焦点环；复选框、单选按钮、开关的边；表达状态的色条（侧栏「需要关注」的琥珀色左条、子代理运行组的状态色条）；拖放时的落点提示。
- 侧栏的拖拽调宽手柄平时不画线，悬停与拖动时出现品牌色细条（现状即如此，保持）。

## 控件

- **按钮：** outline 变体与 secondary 变体外观一致（相对前景色 8% 的填充、悬停 12%），没有边；primary、ghost、destructive 不变。全仓手写的 outline 风格按钮（带 `border` 的 `Button` 替身）一并改为同样的填充。
- **字段：** 输入框、文本域、下拉触发器、搜索框，以及看板的范围 / 筛选触发器、模型目标选择器、Hooks 侧栏搜索框等手写字段，静止态无边、相对前景色 5% 填充、悬停 7%；聚焦或展开时底色回到内容页色并显示焦点环；`aria-invalid` 时显示危险色的环。
- **就地编辑的文字**（看板任务详情的标题与描述等「看起来是文字、点了就能改」的字段）不加填充，聚焦时只出焦点环；它们与普通字段在组件上是两种写法，不靠类名巧合区分。
- **只靠外框才看得出是按钮的小控件**（图标块、小胶囊按钮等）改为有填充的样式，不能退化成裸文字。
- **页签：** 下划线页签改为分段控件：当前项是相对前景色 8% 的填充，其余项透明、悬停出底；仍是 `tablist` / `tab` 语义，键盘操作不变。
- **复选框、单选按钮、开关：** 不变。

## 对话页

- **Tab 条：** 落在外框色上；Tab 之间不画线；活动 Tab 与内容页同色、上沿圆角，与下方内容页连成一体，取代现有的顶部品牌色条。
- **内容页：** 对话标题、转录、输入框在同一张内容页上；标题下不画线。
- **标题栏右侧：** 从左到右为后台任务（有任务运行时才出现）、停止（能停时才出现）、右侧栏开关、更多，均为 32px 纯图标按钮，平时透明、悬停出底；每个按钮都有可及名与悬停提示（新增文案走 i18n，中英两份）。
- **后台任务按钮：**
  - 有至少一个运行中的后台任务（子代理或命令）时显示机器人图标，右上角外沿一颗 6px 状态绿点，缓慢呼吸；系统开启「减少动态效果」时绿点静止。
  - 没有运行中的任务时按钮不渲染。
  - 可及名包含运行中的数量（如「后台任务：12 个运行中」）。
  - 悬停或键盘聚焦按钮时出现预览卡：子代理逐行列出（描述、类型、步数、模型、已运行时长），命令列出前 4 条并写「还有 N 个命令」，底部一行「N 个已结束 · 点击打开完整列表」；预览卡是浮层，靠表面色与阴影立起来。
  - 点击按钮打开现有的后台任务弹层（列表、停止单个任务、定位到发起消息、清理已结束），行为不变。
- **停止按钮：** 实心方块图标；可及名「停止」，悬停提示「停止当前回合」；悬停时危险色的软底与前景。
- **右侧栏：** 从聊天面板内部移到外框上，位于内容页右侧，与内容页之间是外框缝；仍可通过右侧栏开关隐藏 / 显示、拖拽调宽，宽度沿用现有持久化。页签保留文字与计数。大纲条目：当前条目用抬起色，去掉左侧品牌色竖线；「N edits」不再单独占一行带框的小块，改为时间行右端的「✎ N」。
- **输入框（composer）：** 无边，相对前景色填充，圆角加大；聚焦时底色回到内容页色并显示焦点环。
- **转录里的卡片：** 工具卡、思考块、代码块、命令卡、子代理卡、提问卡、审批卡、提示条都去掉外框与内部分隔线，改为填充；卡片里再嵌的分组用留白分开，不再卡中套卡。

## 设置对话框

现状（已验证）：设置是路由 `/settings`，子页只由路由 state `settingsPage` 选定，不持久化，每次进入都从「外观」开始；`/settings` 会被记成 `lastPath`，应用可以直接启动到设置页；离开对话页时对话面板被隐藏。

**打开**

- 以下入口一律打开设置对话框，浮在当前页面上；当前页面（含对话面板、滚动位置、输入框草稿）保持原样不卸载：图标栏齿轮、⌘, / Ctrl+,、命令面板「设置」、状态栏更新弹层的「打开设置」、空对话页的「去配置」、「无法对话」对话框与新会话守卫的跳转、组织页 Agent 详情的两个「去配置」、新建 Agent 对话框里的「去设置 → Agent 后端」、转录里 @设备 提及。
- 带子页的入口落在对应子页（`version-logs` / `agent-backend` / `llm-providers` / `remote-devices` 等，与现有映射一致）；不带子页的入口落在本次运行里上次打开的子页，首次为「外观」。
- 从另一个对话框里跳进设置（「无法对话」对话框、新建 Agent 对话框）时，先关掉那个对话框再打开设置，不叠两层。
- 设置对话框已打开时，带子页的入口切换到该子页；⌘, 关闭对话框。
- 对话框打开期间，图标栏齿轮显示为当前项。

**外观**

- 窗口内居中，四周留出约 32px（上下）/ 56px（左右），最宽 1180px；圆角 16px；靠表面色与阴影立起来，不画边。底下页面被一层半透明遮罩压暗（浅色约 32%、深色约 55% 的黑）。
- 左列是设置导航，外框色，固定宽度、分组标题与图标齐全，不随窗口宽度塌成一行；当前项用前景色 8% 的填充。右侧是内容区，内容页色，单独滚动；页标题、说明、分组照「控件」「结构线」两节的规则。
- 右上角关闭按钮（纯图标，可及名「关闭」）；内容区右侧留出足够的边距，页标题行的按钮不与关闭按钮重叠。
- 窗口最小尺寸（860×640）下每个子页都能完整使用：内容区可滚动，控件不被裁切；LLM 供应商的模型表沿用现有的按容器宽度收列。
- 打开与关闭有 150–200ms 的淡入淡出，「减少动态效果」下取消。

**关闭**

- Esc、关闭按钮、点击遮罩、⌘, 都关闭对话框，回到原来的页面与焦点位置。
- 子页里再打开的对话框（新增供应商、后端编辑器及其「同步供应商」、删除确认、导入预览、设备登录 / 信任证书等）叠在设置对话框之上；Esc 与点击遮罩只关闭最上面那一层。
- 录制快捷键时按 Esc 只取消录制，不关闭设置对话框。
- 子页正处于忙碌态（例如对话框内的保存进行中）时，与现有 `DialogShell` 的忙碌规则一致：Esc 与点击遮罩不关闭。
- 设置里通往别处的链接（LLM 供应商缺口提示里的「去组织」）先关闭设置对话框再跳转。

**路由与恢复**

- `/settings` 不再是页面路由：不再写入 `lastPath`；旧版本留下的 `lastPath = /settings` 在启动时按未知路径处理，落到默认页（对话）。
- 面包屑始终显示底下那一页的名称。
- 对话框打开时窗口仍能通过标题栏区域拖动，macOS 红绿灯可用。
- 对话框是 `role="dialog"`、可及名「设置」；内容区不是 `main` 地标（页面上始终只有底下那一页的一个 `main`）。导航项与各子页保留现有的 `data-testid`（`nav-settings`、`settings-nav-*`、各子页内的 testid）。

## 其它页面

- **看板：** 整页是一张内容页；页头、筛选条、看板底不再各自一个色带；任务卡只靠填充；筛选条里的字段按「字段」规则。
- **组织：** 页标题与索引列在外框上，详情是内容页；索引列的工具条与列表之间不画线；成员行、执行目标列表等去掉外框改为填充。
- **Hooks：** 侧栏在外框上，选中行去掉左侧品牌色竖线、改为抬起色；详情是内容页；「脚本 / 运行日志」为分段控件；分组卡片只靠填充。
- **空状态、引导卡、命令面板、各类弹层与对话框：** 按「结构线」与「控件」两节的规则。

## 兼容性

- `agentre-server` 网页端经固定提交引用 `@agentre-hub/agentre-ui` 并导入同一份 `tokens.css` / `base.css`，没有本地色值覆盖。共享包里的改动（新 token、`Button` / 字段一族 / 弹层 / `ResizableSidebar` / 转录卡片 / 输入框 / 会话列表 / 看板 / 组织组件 / 设置面板）在它升级固定提交后生效；它自己外壳与页面里的线条、表面分配在第二份规格里处理。
- 本文交付时共享包不得出现只在桌面端成立的假设（例如「外框色一定存在于祖先上」）；需要宿主提供的表面由组件参数或宿主样式决定。共享包里自带底色或边线的布局件（`ResizableSidebar` 的 `bg-sidebar` + 边线、组织详情面板的 `bg-card` 等）改为由宿主指定表面（外框 / 内容页），默认不画边——`agentre-server` 现在用覆盖类名去改它们的底色。

## Out of scope

- `agentre-server` 网页端自己的外壳与页面：第二份规格，依赖本文推送后的共享包提交。
- 后台任务「运行中」的残留状态（任务早已结束仍显示运行中）：用户决定本轮不处理。
- 设置做成独立的系统窗口。
- 身份色、状态色、文字角色的取值（2026-10-13 配色收口已定）；唯一例外是上文浅色 `--status-idle` 的微调。
