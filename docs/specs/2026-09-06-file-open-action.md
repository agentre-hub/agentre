# 桌面端文件打开去向：单击动作可配置

> Status: Approved
> Owner: 桌面端
> Last updated: 2026-09-06

**Objective:** 让用户能决定在文件面板里单击一个文件时是开内置预览还是交给外部应用，并让今天点了毫无反应的那批文件也能被打开。

**Hard invariant:**

- 默认值保持今天的行为：单击开临时预览标签、双击转常驻。不设置的用户感知不到这一轮。
- 右键菜单的「预览」「在新标签预览」「用其他应用打开」「在文件管理器中显示」四项与设置无关，始终按各自的字面意思执行。
- 远端会话与无 cwd 的会话不得出现「点了报错」——本机打不开对端路径这件事在渲染时就要被解决掉，不能拖到用户点下去。
- 可预览性判定仍然只有 `frontend/packages/agentre-ui/src/lib/previewable.ts` 一处。

## Problem

1. **不在预览 allowlist 里的文件，单击完全没有反应。** `previewable.ts` 的 `previewKind` 对 `.pdf` / `.zip` / `.xlsx` / 无扩展名文件返回 `null`，`sidebar-row.tsx` 据此把 `previewPath` 算成 `null`、`interactive` 算成 `false`，整行渲染成不可交互的 `<div>`。用户在目录树里点一个 PDF，界面上什么都不发生，也没有任何提示说明为什么；唯一的出路是右键菜单里的「用其他应用打开」。

2. **习惯用外部编辑器的用户每次都得走右键菜单。** `model.onOpenWith` 只挂在菜单项上，`OpenPath` 没有任何更快的入口。对这批用户来说，内置预览是每次都要绕开的一层。

3. **没有任何设置能改这件事。** `settings.tsx` 的「常规」组只有外观、通知、快捷键、数据备份四项，`app_settings_svc` 里也没有与文件打开相关的键。

## Actors and user stories

1. 作为习惯用外部编辑器的用户，我希望单击文件就直接在我的编辑器里打开，这样我不必每次都绕一次右键菜单。
2. 作为只想快速看一眼的用户，我希望内置预览仍是默认，这样这一轮对我没有任何变化。
3. 作为点到 PDF 或压缩包的用户，我希望它能被打开，这样我不必先怀疑是不是界面卡住了。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 一个全局二选一的设置（内置预览 / 外部应用），不按文件类型细分 | 用户决定。二选一能表达「我就是个外部编辑器用户」这个真实诉求，而按类型细分要为它单开一整个配置面。Rejected: 按 markdown / 代码 / 图片 / 其他分别配 —— 设置面的成本远大于它解决的问题 |
| 2 | 无论怎么设置，allowlist 外的文件单击一律交给外部应用 | 用户决定。它不是「设置的一个取值」，而是问题 1 本身：这些文件内置预览**根本渲染不了**，所以没有第二个去向可选 |
| 3 | 默认值 `preview` | 保持既有行为不回归（硬不变量第一条）。Rejected: 默认 `external` —— 会在升级后静默改变所有人的单击语义 |
| 4 | 设置落在 `app_settings_svc` 的键值对上，键名 `files.open_action` | 与 `notify.*` 同一条现成路子（`notification-settings-store.ts` 已经演示了逐键兜底默认值的读法）。Rejected: 只存在前端 localStorage —— 与其余设置的持久化位置不一致 |
| 5 | 设置项落在「常规」组下新增的「文件」页 | 它是行为不是外观，塞进「外观」页会让那一页名不副实。Rejected: 并进「外观」页 |
| 6 | 外部打开不可用时**退回预览**，而不是禁用或报错 | 远端会话拿到的是对端路径、无 cwd 的会话拼不出绝对路径（`sidebar-row.tsx` 的 `absPath` 在这两种情形下都是 `null`）。退回让这些会话里可预览的文件仍然一点就开 |
| 7 | 双击语义不变，仍是「转常驻预览标签」 | 双击是预览标签条自己的语义（`preview-tab-strip.tsx` 同形），它与「单击去哪」是两件事 |
| 8 | 沿用设置页**既有形态**：分区卡 + 一行 Row（左 label 与说明，右 220px Select），不另造并排单选卡 | 对着 `settings.tsx` 的 `AppearanceSettings` / `ThemePreferenceSelect` 与 `notifications-panel.tsx` 的 `Row` 定的——这一页上的多选项设置就是这一个形状（语言、主题模式都是它）。Rejected: 并排单选卡 —— 能把「选了会发生什么」摆得更明白，但会让「文件」页长得和其余设置页都不一样 |
| 9 | 两条「这个设置管不到」的情形写进分区卡的头部说明，不做成选项 | 与 `NotificationsPanel` 里 `header` 的 h2 + 说明同形。它们不是用户能选的，是这个设置的适用边界 |

## 设置项

**前提**：用户打开设置 → 常规 → 文件。**动作**：在「单击文件时」下选择「在 agentre 内预览」或「用外部应用打开」。**结果**：选择立即生效，写入 `files.open_action`，下次启动仍然生效。

读不到该键时按 `preview` 处理——这与 `notification-settings-store` 对 `AppSettingNotFound` 的兜底口径一致，不额外提示。

呈现沿用这一页既有的形状：一张分区卡，头部是「打开方式」与这个设置的适用边界（预览不了的文件始终走外部应用；远端会话的文件只能预览），下面一行 Row —— 左侧是「单击文件时」与一句后果说明，右侧是一个 220px 的 Select，两个取值就是它的两项。适用边界写在头部而不是做成第三个选项：它们不是用户能选的。

设计源：`agentre.pen` 的「文件打开与端口转发」分区，`A1 桌面端 · 设置 · 文件`（Light / Dark）。

## 单击的去向

**前提**：用户在文件面板（目录 / 变动 / Git 三个模式）里单击一个文件行。**动作**：按下表分流。**结果**：

| 文件 | 设置 = 内置预览 | 设置 = 外部应用 |
| --- | --- | --- |
| 在 allowlist 内 | 开临时预览标签（今天的行为，不变） | 交给外部应用 |
| 不在 allowlist 内 | 交给外部应用 | 交给外部应用 |

「交给外部应用」= 今天右键菜单「用其他应用打开」执行的同一件事，含它自己那条失败提示（`chatContext.files.openFailed`），本轮不改措辞。

## 打不开时的退回

**前提**：单击的去向按上表算成「交给外部应用」，但这一行拼不出可交给本机的绝对路径——远端会话，或会话没有 cwd。**动作**：用户单击。**结果**：

- 该文件在 allowlist 内：退回开内置预览标签。
- 该文件不在 allowlist 内：行保持不可交互，与今天一致（没有任何一端能打开它）。

这条退回发生在**渲染时**：不可交互的行仍然渲染成非交互元素、不出 hover 态，用户不会点到一个注定失败的目标。

## 行的可交互性与键盘

allowlist 外、且能拼出绝对路径的文件行，从今天的非交互 `<div>` 变成与其余文件行同形的按钮：有 hover 态、进得了列表的键盘模型、Enter 执行与单击同一个动作、`aria-selected` 仍只表达「这一行正开在预览面板里」（外部打开不产生选中态）。

反过来，远端会话里这些行**保持不可交互**：它们既打不开也预览不了，渲染成可点的按钮等于给一个注定失败的目标。设计源 `A2 桌面端 · 文件面板 · 单击去向对照` 把三种情形并排画出来，第三列就是这一条。

`aria-label` 的取值不变——搜索结果高亮把 basename 拆成兄弟节点的那一支本来就靠它，本轮只是让其中一部分行重新变得可交互。

## 这个设置的作用面会长大

本轮它只管**文件面板**里的单击。`2026-09-06-console-file-preview.md` 会把同一个 `files.open_action` 接到**转录里的文件链接**上——那一轮之后，桌面端「点一个文件」不论从侧栏还是从转录进，去向都由这一个设置决定。两轮的先后不可颠倒：转录那条去向依赖本轮引入的这个键。

本轮不为此预留任何东西，也不改设置项的措辞——「单击文件时」本来就没有把作用面限定在侧栏。

## 右键菜单

菜单四项与设置完全无关：「预览」「在新标签预览」按可预览性出现，「用其他应用打开」「在文件管理器中显示」按能否拼出绝对路径出现。设置改的只是**单击**的默认去向，用户随时能从菜单要到另一种。

## Out of scope

- 指定具体的外部编辑器（交给系统默认关联，与今天的 `OpenPath` 一致）。
- 按项目 / 按会话覆盖这个设置。
- 双击语义的任何改动。
- 让浏览器控制台也有这个设置——控制台里没有「外部应用」这个概念。
