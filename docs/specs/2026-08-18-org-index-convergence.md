# 组织面：两端同形的一套索引，加一条账号级实时通道

<!-- File: docs/specs/2026-08-18-org-index-convergence.md -->

> Status: **Draft**（未批准）
> Owner: 组织架构 / 会话索引 / 共享前端层（跨 `agentre` 与 `agentre-server`）
> Last updated: 2026-08-18
> Mockup（本地产物，不在 Git 里）：`.dev-kit/artifacts/2026-08-18-org-index-convergence/mockups/`

**Objective:** 桌面端 `/org` 从「画布 + 列表两个视图」换成**一套索引 + 主区详情**；
`agentre-server` 的控制台获得同形的组织管理面；索引契约收进共享包；
两端与 server 之间建立一条**常连的账号级通道**，账号级对象的变更由它即时推送。

**Hard invariant:** 桌面端组织数据的写语义一个字段都不改 ——
`moveAgent` / `moveDepartment` / `reorderAgents` 的入参与后端契约保持原样；
会话索引对用户可见的行为在轴投影统一之后与今天**逐条一致**（既有测试即守卫）；
**实时通道断开时，所有功能退化成今天的 30 秒轮询行为，不丢任何变更**；
**任何一条写路径都不得抹掉它没有涉及的载荷键** —— 这是本轮唯一会造成
静默数据损坏、且会经正常同步传播到所有端的失误。

## Problem

1. **两个视图各写一套实现，且能力互缺。**
   `org/org-tree.tsx` 1124 行 + `org/tree-insert-zones.ts` 152 行（`@dnd-kit/core`，
   落点靠 `buildInsertZones` + `isZoneValidTarget`）对 `org/org-list.tsx` 716 行 +
   `org/reorder.ts` 114 行（`@dnd-kit/sortable`，落点靠 `bucketByPlacement`）。
   两套 dnd、两套落点算法、两套渲染。而**树没有搜索**（`org-tree.tsx` 里 `Search` 出现 0 次），
   **列表没有「新建部门」**（按钮被 `org-chart-page.tsx:269` 门控在 tree 模式里）。
   要搜就得切到列表，要建部门就得切回树。

2. **列表根本不能改归属。**
   `org-list.tsx` 的 props 里只有 `onReorderAgent(departmentId, parentAgentId, orderedIds)`，
   **`onMoveAgent` / `onMoveDepartment` 一次都没出现**。今天「换部门 / 换汇报对象」
   **只有画布能做**。所以「删掉画布」必须先回答手势怎么搬。

3. **两个视图是两种不同的层级定义。**
   画布画**存储结构**（部门 ⊃ Agent ⊃ Agent）；列表画**推导结构** ——
   `buildReportToMap`（`org/org-list.tsx:139-143`）＝ 显式 `parent_agent_id` ▸
   沿部门链找首个非自身 leader ▸ CEO 兜底，**部门在列表里不是分组轴**。
   两个视图回答的是不同的问题，所以切来切去既觉得重复又觉得对不上。

4. **详情的 9 个分区挤在 380px 里排成一条纵队。**
   `org-detail-agent.tsx` 953 行 + `exec-target-list.tsx` 666 + `exec-target-skills-block.tsx` 361。
   多档执行目标时更糟：**排序区在上、技能区在下**，技能按档纵向堆叠，
   档与档靠「第 N 档 · 机器 · 后端」这个标题人肉对齐，调完顺序要滚下去核对哪一块跟着动了。

5. **下行只有 30 秒轮询，没有推送。**
   上行是即时的（`agentre` 的 `sync_svc/svc.go:214-217`，本端编辑当场触发 `SyncOnce`），
   下行是 `Pull` 按版本游标增量、**30 秒一轮**（`sync_svc/svc.go:211,229`）。
   两条 websocket（`/v1/relay/daemon` 常连、`/v1/relay/client` 按需连某台 daemon）
   **都不承载同步** —— `relay_svc` 里没有一行同步代码。一端改完，另一端最多 30 秒后才知道。

6. **server 控制台管不了组织。** 导航只有总览 / 对话 / 设备 / 审计
   （`AppShell.tsx:99-113`），而账号级同步组里 `department` / `agent` /
   `agent_backend` / `agent_exec_target` 四类对象本来就在 server 手上。

7. **索引的组形状与呈现在两端各写了一份。**
   桌面端 `components/agentre/session-index/` 2863 行；`agentre-server` 的
   `SessionIndex.tsx` 874 + `lib/sessionAxes.ts` 446 = 1320 行；共享包
   `agentre-ui/session-index/` 只有 `session-row` / `session-group` / `expanded-state` / `types`。

## Actors and user stories

1. 作为**使用桌面端管理组织的用户**，我要在一个界面里同时搜索 Agent、新建部门、
   改归属和排序，不必为了其中一件事切换视图。
2. 作为**要看清汇报关系的用户**，我要在索引上直接读出谁向谁汇报，不必逐个选中查详情。
3. 作为**要调整组织结构的用户**，我要用拖拽完成「换部门 / 换汇报对象 / 纯排序」，
   并在拖到不允许的位置时立刻看出来是不允许，而不是没瞄准。
4. 作为**给 Agent 配多台执行机器的用户**，我要一眼看出每一档跑在哪、用什么后端、
   授了哪些技能、为什么轮不到它，而不必在两个区之间来回对照。
5. 作为**只有浏览器的用户**，我要在 server 控制台上管理部门与 Agent，不需要桌面端在线。
6. 作为**同时开着桌面端和浏览器的用户**，我在一端改完组织，另一端应当立刻看到，
   而不是等下一轮轮询。
7. 作为**网络不稳定的用户**，我要在实时通道断开时一切照常可用，只是更新慢一些，
   并且**不丢任何变更**。
8. 作为**维护这套代码的人**，我要索引的组形状与呈现只有一份实现。

## Design decisions

| # | 决策 | 依据与被否方案 |
|---|---|---|
| 1 | **画布式组织架构图不保留** | 列表已用 `buildHierarchyRows`（`org-list.tsx:65-95`）把 agent→agent 汇报渲染成层级行，画布唯一独有的是**空间鸟瞰**，不是层级信息本身。否决「保留为只读鸟瞰」：仍是两份渲染 |
| 2 | **索引只有一根轴：部门** | 一根轴同时装下三件事 —— 汇报关系由**行内 `↳ 主管名`** 表达、部门负责人由**组头 `Lead · 某某`** 表达、改归属由**行上落点**（决策 5）与详情下拉表达。**否决「部门轴 + 汇报轴」双轴**：曾以「只留部门轴就改不了汇报对象」为由主张双轴，但决策 5 的落点设计已在部门轴上给出该手势 |
| 3 | **下属 Agent 与主管同级，不缩进；汇报写在行上** | 缩进只说「上面那个」，`↳ 主管名` 直接给名字；部门嵌套叠加 Agent 汇报能到 4–5 层，缩进吃掉 320px 侧栏的宽度；拖拽换汇报对象后**标注会变**，手势有了可验证的反馈。随之取消「下属没有部门」的竖线记号 —— `↳` 已蕴含该事实（实体层二选一） |
| 4 | **组头标出部门负责人 `Lead · 某某`** | `buildReportToMap` 的第二级（沿部门链找 leader）因此在索引上直接可见。今天画布已这么做（`org-tree.tsx:977`），列表没有；保留画布这一侧 |
| 5 | **拖拽用三种落点，落点与实体约束一一对应** | `agent_entity/agent.go:158-163` 强制 `departmentId` 与 `parentAgentId` **二选一**。「行之间」＝排序、「行上」＝换汇报对象、「组头上」＝换部门，三者天然互斥，**不需要修饰键或模式切换** |
| 6 | **非法落点画成红色，不是让它消失** | 消失了用户分不清「不许」还是「没瞄准」。判据沿用 `isZoneValidTarget`（防成环），与归属下拉里的置灰判据同一条 |
| 7 | **详情从 380px 右侧面板移到主区，三栏：身份 / 行为 / 执行** | 9 个分区在 380px 里排纵队，用户滚到一半就放弃。「Agent 后端」归入执行栏而非身份栏 —— 每一档执行目标都要指定后端，它与执行目标是一件事 |
| 8 | **执行目标与技能合成一块：一档一行，技能折在行内** | 技能是 **per 档**的，代码写死：「`ExecTargetSkillsBlock` 是 R15e『一档一块』的一块：技能发现来源与授权都钉死在 `props.backend` 这一档，不与 Agent 名下别的档合并」。今天靠两个区之间的标题对齐表达从属，合成一块后变成**物理包含** |
| 9 | **工具是一份紧凑清单，已授权排前** | 这些是把权限授给一个 AI，两项带审批门；开关的分量等同于「深色模式」。动作用按钮（`授权` / `已授权`），已授权的排前 + 底色 + ✓。**否决「已授权用卡片 + 可授权收进折叠区」**：要看两个地方，且卡片分量对一次授权也过了 |
| 10 | **`需审批` 只在已授权时出现** | 今天是常驻 badge —— 没授权时这句话不成立 |
| 11 | **不写「向用户解释我们设计」的说明文字** | 约束由控件表达：「二选一」做成一个下拉两组选项、不能选的就地置灰并写明原因，而不是写一句「二选一，实体层强制」请用户遵守；技能三色做成色块图例而不是一段话。删除既有的 `systemPromptHint`（「风格 / 语气 / 边界都写进 system prompt —— 不另设字段」）。保留的是**当下做决定需要的信息**：离线说明、9 种不可用原因、部门删除两策略 |
| 12 | **筛选不常驻占位** | 搜索框右侧一个筛选入口，**命中后才长出 chip**（`后端：Claude Code ✕`）。否决常驻两个下拉：未筛选时它们既不说明用途也占掉一整行 |
| 13 | **空部门照常摆组头** | 部门是被管理的对象，也是「换部门」的落点；隐藏空部门会让刚建出来的部门当场消失。否决「沿用会话索引『组头只代表这里真有东西』」—— 那条规则是给查询结果分组用的 |
| 14 | **键盘拖拽不回退** | 两个视图今天都挂了 `KeyboardSensor`（`org-tree.tsx:531`、`org-list.tsx:205`），是既有能力 |
| 15 | **共享包承载「组的形状 + 呈现」，不承载取数** | `axis-picker` / `free-group-header` / `own-sessions-header` / `project-glyph` / `row-leading-slot` / `row-secondary-line` 共 440 行**零 Wails、零 store 耦合**，可直接抽；其余都是装配层 |
| 16 | **轴投影收成共享包一份纯函数，取数各留各的** | `buildAxisGroups(axis, input)`（`lib/sessionAxes.ts:362`）是纯函数，`input` 就是「已经在手的行」，不关心怎么来、是不是全量。桌面端保留「每轴一条查询 + 分页」，只把拿到的那批行喂进同一个函数 |
| 17 | **摆哪几根轴由宿主决定**（只影响会话索引；组织面无轴选择器） | 共享投影支持四个轴，桌面端今天只摆三根（`lib/session-axis.ts` 无 machine）。桌面端本轮**不新增机器轴**，否则「行为不变」这条验收标准就毁了 |
| 18 | **实时通道只送信号，不送数据** | 推一条「这个账号的同步版本推进到 V」，客户端收到就去 `Pull`。于是漏一条推送只退化成 30 秒轮询而**不丢数据**（版本游标本就是权威），因此**不需要送达保证、顺序、重放或 ACK**。否决「用通道直接下发对象内容」：那要求可靠投递与顺序，失败处理的成本高一个量级，而收益只是省一次 `Pull` |
| 19 | **通道是账号级的，与中继分开** | 中继是**点对点**（一个客户端找**指定**的一台 daemon，Redis 路由键 `(account, fingerprint) → instanceID` + per-target Stream）；推送是**一对多广播**（任一副本写入后通知该账号所有在线连接）。两者扇出拓扑不同，广播需要 per-account 的 Pub/Sub。否决「复用 `/v1/relay/client`」：它必须指定目标 daemon，没有 daemon 时根本连不上 |
| 20 | **通道的帧带类型标记** | 本轮只有「同步版本推进」一种类型，但通道是常连的账号级设施，日后会承载别的通知。帧上带类型，新增一种不必改协议。**本轮不实现第二种类型** |
| 21 | **浏览器发起的写以 `SourceDeviceID = 0` 表示「服务端直写」** | 零值今天确实未被使用：列在初始迁移即以 `DEFAULT 0` 建（`202608090001_workspace_sync.go:58`），无回填场景，所有行都由 `applyItem` 用 JWT claims 里的真实 `deviceID` 写入。且 `Wins` 里用到它的平局分支**永不触发** —— 版本号取自账号级单调序列，后到达者必然版本更大，该分支只是「保证任意两版本可比」的兜底（`sync_entity/rule.go`）。否决「给账号配一个保留的虚拟设备位」：多一个概念，而零值已经够用 |
| 22 | **server 的组织面用它自己的外壳** | 进 `AppShell.tsx` 的 `NAV_ITEMS` 当第 5 项，不改成桌面端的 56px 图标 rail。索引与详情两端同形，外壳各自保留 |

## 索引

组头是部门，按 `parent` 递归缩进（子部门缩在父部门里），组头上标出该部门的负责人。
行是该部门下的 Agent，**一律同级**：下属 Agent（`departmentId == 0 且 parentAgentId > 0`）
与主管平排，行内带 `↳ 主管名`。系统 Agent（`SystemBadge = default`，
唯一合法的 `dept == 0 且 parent == 0`）单独置顶一行，不属于任何组。

**空部门照常摆组头**（决策 13）。顶栏只有搜索框与筛选入口；
筛选（按后端、按汇报对象，均为今天列表已有）命中后才在下方长出可清除的 chip。

搜索无结果时，除「未找到 Agent」外还要说明**是哪些条件同时生效**，并给一键清除；
一个部门都没建时给出路（新建部门 / 添加 Agent），而不是只说一句「未找到 Agent」。
这两处今天在树与列表里说法不一致，收敛后各自只留一种。

既有的 `agentre.orgView.mode` 键（取值 `tree|list`）随两个视图一并作废；
**读到该键的任何旧值都不应报错或清空其他状态**，直接忽略。

## 拖拽

三种落点，各自对应一个已有的写操作，入参不变：

- **行与行之间的细线** —— 纯排序。只在**同一个桶**（同部门、同上级）的相邻行之间出现，
  落下发 `reorderAgents(departmentId, parentAgentId, orderedIds)`。
- **行本身整行高亮** —— 换汇报对象。落下发 `moveAgent{ newDepartmentId: 0, newParentAgentId }`，
  落定后该行的 `↳ 主管名` 随之更新。
- **组头整块高亮** —— 换部门。落下发 `moveAgent{ newDepartmentId, newParentAgentId: 0 }`；
  部门拖到部门组头上则发 `moveDepartment`。

**非法落点如实拒绝并画成红色**：把一个 Agent 拖到它自己的后代上会成环；
落点保持可见并显示为拒绝态，而不是让高亮消失。
系统 Agent 不可拖动，也不接受任何落点（`agent_svc/agent.go:223,303` 已在服务端拒绝）。

**键盘同样能完成这三件事**：拾起、在候选落点之间移动、落下或取消；
当前落点属于三种中的哪一种要能被读出来，不能只靠颜色区分。

移动端没有拖拽，换部门 / 换汇报对象走详情的「归属」下拉 —— 桌面端的下拉也一直在。

## 详情

选中一行时详情出现在主区，分三栏：

- **身份** —— 名称、简介、头像、头像配色、归属。
- **行为** —— 系统提示词、工具。
- **执行** —— 执行目标（每档含后端与技能）。

字段集合与今天一致，**没有新增也没有删除**；变化是版式与分组。

**归属是一个下拉、两组选项**（部门 / 上级 Agent），选任一组即清空另一边 ——
实体层二选一的约束由控件表达而不是由说明文字表达。子部门在选项里带出路径前缀，
同名部门不致混淆；**自己与自己的后代就地置灰并写明原因**，判据与拖拽的非法落点同一条；
选项多时可搜索。移动端改归属全靠它，因此它必须自足。

归属选中的是**部门**时，其下附一条只读的推导行说明汇报对象（并标明它随部门负责人变动）；
归属选中的是**上级 Agent** 时不出现该行 —— 那种情况下汇报对象就等于归属本身。

**工具是一份清单**：已授权的排在前面、底色标出、行首一个 ✓；一行只有图标、名字、
已授权时的「需审批」、一句话能力、动作按钮。清单以外没有第二处入口。
`需审批` 的判定沿用既有的已知集合，**「组织架构」与「脚本 Hook」两项都要标**。

**执行目标一档一行**，行上给机器、后端与状态摘要，技能折在行内：

- **当前生效**的一档在视觉上与其余区分。
- **不支持技能**的一档不给展开入口，而不是展开后给一句空话。
- **离线**的一档仍可展开：已授权的技能列得出来也移除得掉，只是加不了新的。
- **不可用**的一档留在列表里并给出原因，不隐藏 —— 隐藏了用户不知道为什么轮不到它。

「Agent 后端」不是一个独立字段：后端是**每档各自选**的。
一个 Agent 没有任何执行目标时只给**一条**提示，而不是今天的两条（见「今天说了两遍的状态」）。
多档时不给笼统提示，逐档原因落在各自行上；只有全部档都不可用时才给一条汇总横幅。

**窄窗口下详情不得横向溢出。** 三栏中任一栏装长串（提示词、路径、错误码）时，
栏宽必须能收缩，否则外层滚动容器会把溢出藏起来而不报错。

## 今天说了两遍的状态

`noBackendBound = execTargets.length === 0`（`org-detail-agent.tsx:184`）与
执行目标列表内的「还没有执行目标」空态**是同一个条件**，今天两条同时出现。
本轮合并成一条，同时说明「不能对话」与「至少要有一项」。

`builtinMissingProvider`（`:185-189`）带 `singleTarget &&`，**只在单档时出现**；
代码注释已写明多档时靠逐行徽标。本轮的「一档一行」正是这条注释描述的形态，保持不变。

## 随画布一同失效的既有文案

`org.agent.descriptionHint` = 「可选 · 显示在**卡片副标题**」——
画布删掉之后不再有卡片，这条必须一并改掉，否则它从本轮起就是谎话。

## server 端的组织管理面

`agentre-server` 的控制台增加组织面，进 `AppShell.tsx` 的 `NAV_ITEMS` 当第 5 项。
**索引与详情与桌面端同形**（同一份规格上文描述的形态、同一批共享组件），
外壳仍是 server 自己的 224px 带文字 SideNav。

**写入路径**：浏览器 → server 的 REST 端点 → server 直写 `sync_objects`。
`Version` 本就由 server 的账号级单调序列分配，server 已经是权威写入点，
只是今天只接受设备推上来的内容。**不需要桌面端在线**。

支持建、改、删三种，各自沿用既有的账号级语义：新行由 server 分配同步标识与版本号；
删除落墓碑而不是物理删除；`project_location` 的自然键合并（R4b）与设备上行走同一条路径。
写入范围只由鉴权上下文里的账号圈定，请求体里不含任何身份字段。

**来源标识**：这些行的 `SourceDeviceID` 记 `0`，含义是「服务端直写」（决策 21）。
由此带来一处必须处理的呈现问题：冲突应答里的 `OverwrittenDeviceID` 与
`MergedDeviceID`（`sync_svc/sync.go:189,253,277`）会回传 `0`，
桌面端据此向用户交代「你的改动被谁覆盖了」（R5）。
**收到 `0` 时必须说成「服务端（浏览器）」，不能显示成设备 #0 或空白。**

**浏览器不因此成为可管理设备。** `device_svc.go:520` 的判定不变：
浏览器是中继的短效调用方，`KindWeb` 仍从设备列表里过滤掉。

### 后端是机器的，浏览器只能引用，不能创建或编辑

`agent_backend` 是**设备级**对象（`sync_svc/sync.go:416` 的 `deviceScopedKinds`）：
它带 agentred 指纹，机器离开账号时落墓碑并级联掉引用它的执行目标。
而它的**同步载荷里带着 `cli_path` 与 `env_json`**（`agentre` 的
`sync_svc/adapter_org.go:392,396,444,448`）—— 本机可执行文件路径与透传环境变量。

由此定下三条硬要求：

- **读**：发往浏览器的任何响应里**不得出现 `cli_path` 或 `env_json`**。
  这条今天已经守着了，且守法是结构性的 ——
  `TestListAccountAgents_NeverCarriesCLIPathOrEnvJSON` 的注释写明
  「`AgentView` 一开始就没有能装下它们的字段」。**本轮新增的每一个发往浏览器的视图
  都要沿用同一种守法**：不是在序列化时过滤，而是类型上就没有那个字段。
  （`env_json` 比路径更敏感：实体层专设保留键检查，桌面端日志规则也把它与载荷、
  路径、prompt 并列禁止，见 `agentre` 的 `sync_svc/svc.go:11`。）
- **写**：浏览器**不能新建也不能编辑后端**。它无从知道那台机器上的可执行文件在哪，
  新建出来的档必然不可用。web 上能做的是**从已有后端里挑一个**去配执行目标。
- **不得清空**：服务端直写任何一行时，**只覆盖请求明确涉及的键，保留载荷里其余的原值**。

  这不是新隐患，而是**既有隐患被放大**。`SetExecTargetOrder` 已经踩过一次并留了守卫
  （`TestSetExecTargetOrder_GivenPermutation_ThenOnlySortOrderChangesAndSkillsSurvive`），
  其注释说得最准：「`sync_objects` 是**整行 last-write-wins**（前置规格决策 4 把字段级
  合并列为非目标），而 Go 侧的 payload 结构体只声明了三个键 —— 把载荷解进它再 marshal
  回去，`skills_json` 会被静默抹掉。**这不是一个假想的失误，而是「照着读路径的结构体
  写写路径」这个最自然的写法的默认结果。**」

  本轮把这个面从「一个字段 × 一类对象」放大到**三类对象 × 建 / 改 / 删**，
  因此这条守卫必须对每一条新写路径各来一份，而不是只在评审时口头提醒。

**web 组织面能管的因此是**：部门（建 / 改 / 删）、Agent（建 / 改 / 删，含名称、简介、
头像、配色、归属、系统提示词、工具授权）、执行目标（增删档、排序、每档的技能授权）。
**不含**：后端本身、LLM 供应商凭据（决策 24：只住在那台机器上）。

## 账号级实时通道

一条**常连**的 websocket，桌面端与浏览器都可建立，**不指定目标 daemon**
—— 这是它与 `/v1/relay/client` 的根本区别（决策 19）。

**鉴权**：桌面端用 Device JWT；浏览器不能给原生 WebSocket 设请求头，
沿用既有的 query 搬运做法（`queryTokenBridge`）接受短效票据。
凭据被撤销时连接必须断开，与中继两条连接同一条判据。

**帧**：只送「这个账号的同步版本推进到 V」这一个信号，带类型标记（决策 20）。
**不送对象内容** —— 客户端收到后照常走 `Pull`（决策 18）。

**谁发信号**：`sync_objects` **每一条写入路径**都要发，共三处 ——
设备上行（`sync_svc.applyItem`）、服务端直写（web 组织面）、以及落墓碑的那些
（`PurgeDeviceSyncObjects` / 级联）。**只给新路径加信号是不够的**：
桌面端改完之后另一台桌面端仍要等 30 秒，本轮的目标就落空了一半。

**扇出**：server 任一副本写入后，向该账号的所有在线连接广播，跨副本可达。
中继现有的 per-target Redis Stream 解决不了一对多，需要 per-account 的 Pub/Sub。
**写入方自己也会收到自己触发的信号**，这无害 —— 它照常 `Pull`，
最多拉回一页自己刚写的内容。为此不引入「排除来源连接」的机制。

**合并**：信号只携带版本号，因此**多条待发信号可以合并成最新的一条**。
慢客户端不需要背压机制，压住不发的那些直接被后来的覆盖。

**在线态**：与中继同一模式，由 Redis TTL 表示，断连或进程失联后自动过期，
不主动删除。

### 失败处理

这条通道的设计前提就是**它可以不可靠**：

- **连不上 / 断开**：客户端退回 30 秒轮询，即今天的行为。**不重试到底、不阻塞任何操作**。
- **建连成功**（首次或重连都一样）：立刻主动 `Pull` 一次，而不是等待服务端补发 ——
  通道不保存未送达的信号，也不需要保存。断线期间发生的变更由这一次 `Pull` 补齐。
- **漏帧、乱序、重复**：都无害。信号里的版本号只用于「该拉了」的判断，
  拉取本身由客户端自己的游标决定拉哪些。重复信号最多多拉一次空页。
- **服务端广播失败**：记录并继续，不回滚已经落库的写入 ——
  写入的权威性在数据库，不在通道。

**验收判据**：把通道整个关掉，所有功能仍然正确，只是变慢到 30 秒。

## 同步传播

本轮之后的传播是**上行即时、下行推送、轮询兜底**：

| 方向 | 机制 | 时延 |
| --- | --- | --- |
| 本端编辑 → server | `NotifyLocalChange` 当场触发 `SyncOnce`（R3） | 即时 |
| server → 各端（通道在） | 账号级通道广播信号，客户端立刻 `Pull` | 即时 |
| server → 各端（通道断） | 30 秒周期的 `Pull`（`sync_svc/svc.go:211,229`） | 最多 30 秒 |

**30 秒轮询保留，不缩短也不删除。** 它是通道的兜底，也是「不丢数据」的依据；
删掉它，通道就从「优化」变成「关键路径」，失败处理的成本会立刻上一个量级。

中继的两条 websocket（`/v1/relay/daemon` 常连、`/v1/relay/client` 按需连某台 daemon）
与本通道**彼此独立**，各管各的，不合并。

## 已知风险

本规格一次包含六件事：① 契约与呈现进共享包、② 会话轴投影两端统一、③ 桌面端 `/org` 换索引形态、
④ 账号级实时通道、⑤ 用它推送同步信号、⑥ server 组织面（含浏览器写通道）。

依赖关系：①→②、①→③；④→⑤；⑥ 独立成立（没有 ④⑤ 时它就是 30 秒时延）。
也就是说**三条线彼此正交**，只是被放进了同一个验收面。
用户在知情后选择一轮做完；计划层面据此排成可独立验收的若干段，
每段自带守卫，出问题时能定位到是哪一条线。

**风险最高的是 ④⑤。** 它是本仓第一条账号级广播设施，
而中继现有的跨副本机器（per-target Redis Stream）解决的是点对点，扇出拓扑不同、不能直接复用。
缓解办法写在设计里而不是留给实现：**通道只送信号不送数据**（决策 18），
使得「漏、乱、重」三类失败全部无害，验收判据可以简化成一句
「把通道关掉，功能仍然正确」。

② 的实际代价比「纯重构」高一格：桌面端 `use-index-groups` 今天返回 `sessionIDs: number[]`、
行字段从 store 现算，而共享投影收 `IndexRow[]` 返回已补齐的行，两者之间需要一层适配。
这层适配是新代码，不受「既有测试即守卫」保护，需自带测试。

⑥ 引入的 `SourceDeviceID = 0` 本身代价极小（该值今天未被使用，且 `Wins` 里用到它的
平局分支永不触发），但它会经冲突应答流到桌面端的用户界面上，
那一处呈现是必须一起做的，不能留到以后。
