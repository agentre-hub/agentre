**Objective:** 把 agentre-server 的两个会话列表合并成一个索引，按项目 / Agent / 时间 / 机器
四个维度分组，任何一个轴上都看得见会话的完整归属。

**Hard invariant:** R19 不放宽 —— 项目在某台机器上的绝对路径不出现在发往浏览器的任何响应里。
索引用路径做项目归属判定，这件事**只在服务端发生**，浏览器只收到项目同步标识。

## Problem

1. **同一批会话有两个长得不一样的列表。** `frontend/src/components/session/ChatList.tsx`（1058 行，
   账号级 `/chat`）与 `frontend/src/components/session/SessionList.tsx`（420 行，设备下钻
   `/devices/:id/sessions`）各自实现了一套会话行、一套分组、一套筛选。两者的行结构已经几乎相同
   （状态点 + 标题 + 相对时间 / 第二行「设备 · 后端」/ 移动端 Agent 行 + 文字徽标），却是两份代码。
2. **只能按 Agent 分组，看不到项目。** 桌面端合并后的索引有项目 / Agent / 时间三个轴
   （[`2026-08-16-unified-chat-index.md`](./2026-08-16-unified-chat-index.md)），web 侧只有 Agent
   一个维度（`ChatList.tsx:306` 按 `agentSyncId` 建组），移动端另按状态重排
   （`regroupByStatus`，`ChatList.tsx:129`）。用户在两端看到的是同一批会话的两种组织方式。
3. **「未读」在两端指两件事。** web 的筛选 chip「未读 N」数的是 `waitingForInput`
   （`ChatList.tsx:642` 经 `unreadCount`），桌面端的未读是「有新消息没看过」
   （`lastMessageAt > lastReadAt`，`session-read-store`）。同一个词，两个含义。
4. **设备下钻是一条死路。** 从 `/devices/:id/sessions` 看到的会话没有回到账号视角的入口，
   而它渲染的是同一批会话的子集。

## Actors and user stories

1. 作为**同时用桌面端和浏览器的用户**，我希望两端的会话列表是同一个东西，不用在两套组织
   方式之间重新建立心理模型。
2. 作为**按项目干活的用户**，我希望在浏览器上也能按项目看会话，而不是只能按 Agent。
3. 作为**管着几台执行机的用户**，我希望能按机器看「这台上面在跑什么」——这是浏览器独有的
   需求，桌面端没有对应物。
4. 作为**关注了别人会话的用户**，我希望目标机器离线时那条关注仍然看得见并且知道为什么，
   而不是从列表里消失。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 两个列表合并成**一个索引**，`/devices/:id/sessions` 重定向到索引并预置「机器轴 + 选中该机器」。 | 用户裁决（2026-08-17）。它们渲染同一批会话的全集与子集，差别只是范围，而范围正是「轴 + 选中」能表达的东西。桌面端合并「对话 / 项目」时用的是同一条判据与同一种重定向处理。拒绝：保留两个列表只统一行组件 —— 分组与筛选仍是两份，问题 1 只解决一半。 |
| 2 | 轴是**四个**：项目 / Agent / 时间 / 机器。 | 用户裁决（2026-08-17）。前三个与桌面端一致；「机器」对应 web 真实多出来的能力（会话逐台经中继解析，机器是它天然的归属维度），桌面端没有这一维是因为它的会话要么本地要么在一台已配对的机器上。拒绝：只要桌面端三轴 —— 「看看这台机器上跑着什么」会从分组维度降成筛选，设备运维场景变麻烦。拒绝：再加第五个「状态」轴 —— 与筛选 chip 重复，见决策 5。 |
| 3 | 「未读」chip **改名为「等你处理」，语义不变**（仍是 `waitingForInput`）。web 侧不引入已读状态。 | 用户裁决（2026-08-17）。会话内容不过 server，浏览器也没有存过「读到哪了」；做真已读要么落 `localStorage`（换浏览器即丢失，与刚删掉的 `client_id` 同一个坑，见 [`2026-08-14-exec-target-order-ux.md`](./2026-08-14-exec-target-order-ux.md) 决策 14），要么新表 + 新端点 + 新同步语义。改名的成本是一条文案。拒绝：做真已读；拒绝：两个 chip 并存。 |
| 4 | 会话的项目归属由**服务端**按「会话 cwd == 该机器上某个项目的路径」判定，判定结果只回项目同步标识。 | `sync_objects` 里 `kind=project_location` 的行携带 `(project_sync_id, agentred_fingerprint, payload.path)`，`workspace_svc.configuredProjects` 已经在读它。判定放在服务端而不是浏览器，是 R19 要求的：路径不能出浏览器。拒绝：给 wire 的 `SessionSummary` 加 `projectSyncId` —— daemon 是纯执行端，它只收到 cwd，不知道项目这个概念，要它知道就得改发起方、改 daemon 存储、改 wire 三处。 |
| 5 | 移动端**去掉**「按状态分组」，四个轴与桌面端相同。 | 用户裁决（2026-08-17）。「等你处理 / 运行中」已经是筛选 chip，再做成一套只有移动端才有的分组维度，等于同一件事两套入口。**已知代价**：这是一次可见的行为变化，现有移动端用户会发现分组变了。拒绝：升成第五个轴；拒绝：只在移动端保留（两端轴集合不一致）。 |
| 6 | 解析不出来的会话进一个固定的**「暂时看不到」**组，四个轴下都排在最后。 | 关注记录只存「设备指纹 + 会话标识 + 关注时间」（[`2026-08-10-web-session-access.md`](./2026-08-10-web-session-access.md)），机器解析不出来时这条会话的 Agent 与项目**无从得知**，项目轴 / Agent 轴下它没有可归的组。拒绝：这两个轴下隐藏它们 —— 关注会像丢了一样；拒绝：塞进「未命名」组 —— 那个组的含义是「老会话没有 agentSyncId」，混进来两种不同的原因。 |
| 7 | 三个兜底组的名字与含义**各自独立，不合并**：「未归项目」/「未命名」/「暂时看不到」。 | 三者的原因不同：cwd 匹配不到任何项目路径 / 老会话没有 `agentSyncId` / 目标机器解析不出来。合并成一个「其他」会把三种可操作性不同的状态压成一个（第一种要去配项目路径，第二种无需处理，第三种可移除关注）。**注意**：「未归项目」与桌面端的「随手对话」不是一回事 —— 后者是 `project_id=0`「故意不挂项目」，是一个正当去处。 |
| 8 | 行首那一维与第二行照搬桌面端决策 4/5：分组没说的维度落在行首字形或第二行。 | 同一条规则在四个轴上都成立：项目轴行首放 Agent 字形、Agent 轴行首放项目色文件夹、机器轴行首放 Agent 字形、时间轴无组头且把三维都写进第二行。mockup `?view=axes` 四轴并排验证过每个轴上归属都完整。 |

## 索引的组成

**范围是账号级。** 索引列出「自己发起的 + 关注来的」全部会话，与今天 `/chat` 的范围一致
（`Chat.tsx` 的文档注释）。会话逐台经中继 `session.list` 解析，解析在浏览器侧完成；一条会话
在多台机器上有副本时按既有规则合并（`lib/sessionMerge.ts`），索引里只出现一条。

**四个轴的分组键**：

- **项目**：项目同步标识，按 `parent_sync_id` 递归成树（同步载荷里有这个键）。判定不出项目的
  会话进「未归项目」。
- **Agent**：`agentSyncId`。没有它的老会话进「未命名」。
- **时间**：不分组，单一平铺列表，按最后活动时间倒序。
- **机器**：会话所在设备。**离线机器自己成组，组头标「离线」**——机器认得出来但连不上，与
  「连机器都认不出来」是两回事，后者才进「暂时看不到」。

**筛选与搜索**跨轴一致：全部 / 运行中 / 等你处理，加一个搜索框；筛选生效时只收窄行，同时
隐藏一条都不剩的组头。

## 解析不出来的三种行

关注的目标可能拿不到 `SessionSummary`。三种情况在行的第二行如实写明，状态点与标题置灰，
行不可点：

- **离线** —— 目标机器已认领账号但当前不在线。可以等；关注保留。
- **正在解析** —— 已连上中继、尚未回话。会自己变成正常行，不需要用户做任何事。
- **已不存在** —— 设备已被撤销，或那台机器上已经没有这条会话。提供「移除关注」。

这三种行没有最后活动时间，行尾只有关注开关。它们在机器轴下尽量归入对应机器的组（离线那一
类做得到），其余落进「暂时看不到」。

## 与桌面端共享什么

会话**行**用共享包的 `SessionRow`（已具备 `leading` / `overline` / `secondaryLabel` /
`trailing` / `rowActions` / `href` + `renderLink` 六个接缝，`76c131af` 补齐）。

**分组容器与轴的投影留在各自宿主。** 两端的轴集合不同（web 多一个「机器」）、兜底组不同、
web 还有解析不出来的行这一整类，把它们搬进包等于让包认识只有一端存在的概念。桌面端
`SessionGroup` 提供的折叠动画 / attention 气泡 / 「查看全部 N」溢出，web 侧这一轮不需要
（web 的会话一次全量解析回来，没有分页）。

## 已知的可见变化（都不是 bug，但会被用户看见）

1. **密度整体降一档。** 共享 `SessionRow` 是按 320px 侧栏设计的：行内边距 `px-2 py-1.5`、
   标题 `text-xs`、第二行 `text-2xs`、状态点 6px。web 今天两个列表用的是主内容区的密度
   （`px-3 py-2.5`、标题 `text-sm`、状态点 8px），行高约从 60px 降到 44px。这是「两端一致」
   的直接结果，不是退化 —— 但第一眼会很明显。mockup
   `.dev-kit/artifacts/2026-08-17-session-row-shared/mockups/05-density.png` 是这一条的对照。
2. **相对时间从「紧贴标题」变成「行尾右对齐」。** 共享行的 `trailing` 槽在标题列之后，而
   标题列是 `flex-1`。标题短时中间会拉开空白。
3. **状态点的 aria-label 从本地化变成英文状态码。** 共享包 `StatusDot` 的可访问名是
   `running status` 这类固定英文（包的既定约定：状态码与 `RUNNING`/`IDLE` 同类，不进 i18n），
   而 web 今天用的是 `t("session.list.waiting")` 这类译文。**这是一次可访问性口径的收敛，也
   确实是 web 侧的降级**。移动端行尾另有文字徽标兜底（本地化），桌面端则只剩英文状态码 ——
   若判定不可接受，补救方式是给 `StatusDot` 加一个可选的 `aria-label` 覆盖，属包侧改动。

## Out of scope

- **项目页与组织页的收敛。** 用户裁决「先只收敛会话列表这一块」。整体方案记在
  [`2026-08-16-web-console-convergence.md`](./2026-08-16-web-console-convergence.md)（未批准）。
- **web 侧新建 / 改名 / 删除项目。** 索引只读项目用于分组；项目的编辑仍只在桌面端。
- **已读状态。** 决策 3。
- **会话分页。** web 的会话经中继一次全量解析，没有桌面端那套按 scope 分页的问题。
- **外壳收敛**（rail / 标签条 / 多标签并存）。索引仍然住在今天 `/chat` 的 320px 左列里
  （`Chat.tsx:509` 已是这个宽度）。
