# 新对话靠拢同项目标签页

> Status: Approved
> Owner: desktop app maintainers
> Last updated: 2026-11-17

**Objective:** 开启设置后，新建对话的标签页插到同一项目族最后一个标签页的右边，让同项目的标签页在标签栏里自然聚在一起。

**Hard invariant:** 设置关闭（默认）时，标签栏的一切行为与今天完全一致；无论开关如何，已打开的标签页都不会因为新建对话而改变彼此的相对顺序，固定区不被插入。

## Problem

1. **新对话一律落在最右，同项目的标签页越开越散。** 新建对话的标签页总是追加到标签栏末尾（`frontend/src/stores/chat-tabs-store.ts` 的 `openNewSession`，已验证）。在多个项目之间来回开对话时，同一项目的标签页被其他项目隔开，需要手动拖拽才能归拢。（用户反馈）
2. **项目色线因此断成碎段。** 标签栏底部的项目色线只在相邻标签页同色时连成一段（`frontend/src/components/agentre/chat-tabs/tab-strip.tsx` 中 `lineStart` / `lineEnd`，已验证）；标签页分散时，色线不能帮助用户一眼认出哪些标签页属于同一项目。

## Actors and user stories

1. As a `桌面端用户`, I want 在某个项目里新建对话时，新标签页出现在该项目已有标签页的旁边, so that 不用手动拖拽就能让同项目的标签页聚在一起。
2. As a `桌面端用户`, I want 这个行为可以关掉、且默认不改变我习惯的顺序, so that 升级后标签栏不会出乎意料地变化。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 只改新标签页的插入位置，不引入分组实体 | 用户在 mockup 前的选项中选定。Rejected: Chrome 式标签组（组标签、折叠、整组拖动）——改动大，涉及拖拽、溢出菜单与持久化；Rejected: 每次新建时把整条标签栏按项目重排——会打乱用户手动拖好的顺序 |
| 2 | 「同组」= 同一个顶层项目下的任意项目（顶层项目本身及其各级子项目） | 用户决定「子项目算」。Rejected: 按项目 id 精确匹配——父项目与子项目的标签页会被分开 |
| 3 | 插入点是同组**最后一个**标签页的右边；同组没有标签页时追加到最右 | 用户在 mockup 中确认。最后一个而不是第一个，保证新标签页与同组之间不夹别的项目，且不挪动任何已有标签页 |
| 4 | 不进入固定区：同组最后一个标签页在固定区内时，新标签页放在固定区之后的第一个位置，自身不固定 | 用户在 mockup 中确认；与「固定区只能由用户显式固定」的现有约定一致 |
| 5 | 同组成员包括会话、预览、尚未发出首条消息的新对话和终端标签页；远端设备（peer）标签页不参与 | 用户决定「终端算」。peer 标签页不落本地会话数据、没有本地项目归属 |
| 6 | 只作用于「新建对话」；从侧栏等入口打开已有对话、打开终端仍追加到最右 | 用户决定侧栏本轮不做 |
| 7 | 设置放在 设置 → 常规 → 外观，新增「标签页」一组，一个开关；默认关闭；只存本机 | 用户确认位置与文案。默认关闭以免升级后静默改变标签顺序；与 `files.open_action` 一样是本机偏好，不参与同步 |

## 插入规则

**前提。** 设置「新对话靠拢同项目」为开启，用户通过任一「新建对话」入口（项目页、命令面板、对话页内的新建等）在项目 P 下新建对话。

**同组判定。** 先确定 P 所在的顶层项目 R（P 本身是顶层项目时 R = P）。标签栏中满足以下条件的标签页是同组成员：

- 会话标签页（含预览标签页），其会话所属项目在 R 之下（含 R 本身）；
- 尚未发出首条消息的新对话标签页，其所选项目在 R 之下；
- 终端标签页，其所属项目在 R 之下。

以下标签页不是同组成员：远端设备标签页；附着到对话卡片里已运行命令的终端标签页（没有项目归属）；所属项目信息尚未加载到的会话标签页。

**结果。**

- 有同组成员：新标签页插到最右侧那个同组成员的右边，并成为当前标签页。若那个成员位于固定区内，新标签页改放到固定区之后的第一个位置。
- 没有同组成员：新标签页追加到最右，与今天一致。
- 项目 P 为空（不在任何项目下新建）：追加到最右。
- 项目树尚未加载或其中找不到 P：只把所属项目恰好为 P 的标签页视为同组成员。

**不变的部分。** 已打开的标签页位置、固定状态、预览状态、当前标签页切换逻辑都不受影响；新标签页本身不是预览、不固定，与今天一致。之后用户拖拽排序、关闭标签页的行为不变。插入结果和今天一样随标签栏一起持久化，重启后顺序保持。

**失败。** 判定时缺少的信息（项目树、会话所属项目）一律按「不是同组成员」处理，最坏结果是新标签页落在最右，不会插到别的项目中间。

## 设置

**位置与外观。** 设置 → 常规 → 外观 页面，在「颜色模式」一组之下新增「标签页」一组，内含一行开关：

- 标题：「新对话靠拢同项目」 / `Keep new chats next to their project`
- 说明：「新建对话时，新标签页放在同一项目最后一个标签页的右边；没有同项目的标签页时仍放在最右边。」 / `New chats open right after the last tab of the same project, or at the far right if there is none.`

外观页描述同步改为涵盖标签页（中文：「主题、语言与标签页的显示方式。」）。开关有可见的键盘焦点，可用键盘切换，开关的可及名为标题文字。

**默认与持久化。** 默认关闭；值只存在本机，不参与跨设备同步。读取失败或从未设置过时按关闭处理。

**生效时机。** 切换后立即对之后的新建对话生效；不重排任何已打开的标签页。

**保存失败。** 保存失败时开关保持（或回到）原状态，不显示一个实际未保存的值，并弹出一条错误提示「设置没有保存」 / `Setting was not saved`；插入行为继续按原值执行。

## Out of scope

- 从侧栏、搜索、通知等入口打开已有对话时的靠拢（用户决定本轮不做）。
- 新开终端标签页的靠拢。
- 标签组的可视化（组标签、折叠、整组拖动）与对已打开标签页的自动重排。
- 控制台（agentre-server）网页端：其标签栏不在本轮范围内。

## Testing decisions

| Seam | What it verifies | Prior art |
|---|---|---|
| 标签页 store 的新建对话动作（Vitest） | 开关关闭时追加到最右；开启时插到同组最后一个成员之后；顶层项目族判定（父/子项目互为同组）；终端算、peer 与附着终端不算、项目未知的会话不算；同组仅在固定区时落到固定区之后；项目为空或无同组时追加到最右；已有标签页相对顺序不变 | `frontend/src/stores/__tests__/` 下现有 chat-tabs-store 测试 |
| 外观设置页（Vitest + Testing Library） | 开关默认关闭、读取已保存值、切换后写入、保存失败时保持原值并提示 | `frontend/src/components/agentre/settings/__tests__/`、`file-settings-store` 测试 |
| 应用设置服务的键白名单与取值校验（Go，mockgen） | 新键可写入、非布尔值被拒绝 | `internal/service/app_settings_svc/app_settings_test.go` |
| i18n 覆盖测试 | 新增文案中英文齐全 | `frontend/src/__tests__/i18n.test.ts` |

插入位置完全由 store 动作决定，自动化测试已覆盖全部规则；本轮不安排驱动真实应用的运行期验证，收尾只做源码审查。
