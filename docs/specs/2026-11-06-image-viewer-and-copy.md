# 图片查看大图与复制

> Status: Approved
> Owner: 共享 UI 包（agentre-ui）+ 桌面端，agentre-server 控制台跟随抬钉
> Last updated: 2026-11-06

**Objective:** 对话里和输入框里的图片，点一下就能在应用内看大图，并能把图片本身复制到系统剪贴板。

**Hard invariant:** 文字复制的现有行为不变（包括桌面端已经切到原生剪贴板的那条通道）；在图片查看器以外选中文字按 ⌘C，复制的仍然是文字。

## Problem

1. **点图片看不了大图。** 已核实：转录里的图片块是一个 `<a href={dataUrl} target="_blank">` 包着 `<img>`，缩略图最高 288px（`frontend/packages/agentre-ui/src/transcript/transcript-row-view.tsx:636`）。点了会尝试开新标签页打开 data URL；在桌面 WebView 里会发生什么还没验证（unknown），反正不会在应用内看到大图。截图里的小字在缩略图里看不清。
2. **输入框里的附件只能删。** 已核实：发送前的附件缩略图是 80×64 的裁切小图，只有一个删除按钮（`frontend/packages/agentre-ui/src/composer/chat-composer.tsx:525`），发之前没法确认贴对了图。用户已提出（2026-11-06）这里也要支持。
3. **没法复制图片。** 已核实：共享包只有文字复制（`clipboard-toast.ts`）；桌面端的 Wails v2 运行时只提供 `ClipboardSetText`。WKWebView 里网页剪贴板接口会被间歇拒绝（NotAllowedError），这正是桌面端文字复制改走原生通道的原因（提交 e87ce761）。

## Actors and user stories

1. 作为用户，我想点对话里的截图看原图，看清里面的细节。
2. 作为用户，我想把对话里的图片复制出来，贴到别的应用或别的会话里。
3. 作为用户，我想在发送前点开附件，确认贴的是对的图。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 点缩略图在应用内打开全窗口查看器，不再开新标签页 | 用户已决定（2026-11-06，看过 mockup）。否决：保留新标签页——桌面端没有标签页可开 |
| 2 | 查看器在浅色主题下也用深色遮罩 | 用户已决定（采纳推荐）：看图工具的通行做法，图片边缘在深底上看得清。否决：跟随主题 |
| 3 | 查看器两种显示：适应窗口（默认）和原始大小（1:1，超出部分滚动）；点图片或顶栏按钮切换 | 用户已决定（看过 mockup B3/B4）。否决：滚轮或捏合缩放——这次不需要 |
| 4 | 同一组图可以左右切换：「同一组」指转录里同一条消息的所有图片块，或输入框里当前的所有附件 | 用户已决定（看过 mockup）。否决：跨消息切换整个会话的图片——范围不清，用不上 |
| 5 | 复制入口：转录缩略图悬停或聚焦时右上角的复制按钮、查看器顶栏的「复制」、查看器里按 ⌘C / Ctrl+C。输入框附件缩略图上**不加**复制按钮，在查看器里复制 | 转录缩略图：用户已决定。附件缩略图只有 80×64，右上角已经有删除按钮，再放一颗容易误点。否决：附件上并排放复制和删除 |
| 6 | 写进剪贴板的一律是 PNG | 剪贴板里 PNG 是各平台通用的图片格式；JPEG/WebP 先转成 PNG。代价：动图只保留第一帧。否决：保留原格式——有的平台或目标应用不认 |
| 7 | 剪贴板写入归宿主：共享包定义「写图片」的宿主接口，桌面端装原生实现，没装时（server 控制台）用浏览器的剪贴板接口 | 已核实：文字复制已经是这个结构（共享包 `setClipboardWriter` 宿主口，桌面端装原生通道）。否决：桌面端也走网页剪贴板接口——会碰到同样的 NotAllowedError |
| 8 | 桌面端原生写图片支持 macOS、Windows、Linux | 已核实：发布流水线构建这三个平台（`.github/workflows/manual-build.yml`）。否决：只做 macOS——其他平台点了没反应 |
| 9 | 用户消息里多张图的排列不变（竖着排，每张最高 288px） | 用户已决定（采纳推荐）。否决：改成网格——这次只加交互 |
| 10 | 不加「另存为」 | 用户已决定（2026-11-06）。 |

参考 mockup：`.dev-kit/artifacts/2026-11-06-queued-withdraw-image-viewer/mockups/`（B1–B4；`page-*.png`、`viewer-dark.png`）。

## 转录里的图片缩略图

**前提**：转录里有图片块（用户发的图，以及任何角色消息里的图片块）。

- 缩略图样式和尺寸不变。鼠标悬停时指针变成放大镜。整张缩略图是一个按钮，无障碍名是「查看大图：<文件名>」，没有文件名时用「查看大图」。
- **点击**（或聚焦后按 Enter / 空格）：打开查看器，显示这一张，同组里的其他图可以切换（决策 4）。
- **复制按钮**：悬停在缩略图上，或键盘聚焦到复制按钮时，右上角出现复制按钮；平时不显示。点击后按「复制」一节的规则复制这一张；成功后按钮上的图标变成 ✓，约 1.5 秒后恢复。

## 输入框里的附件缩略图

**前提**：输入框里已经贴了一张或几张图，还没发送。

- 缩略图本身可以点，指针是放大镜，无障碍名同上。点击打开查看器，同组是输入框里当前所有附件，从点的那张开始。
- 右上角的删除按钮不变；点删除不会打开查看器。
- 查看器打开期间附件列表不会变（这时输入框被遮罩挡住）。关闭后焦点回到原来那张缩略图。

## 查看器

**打开后**：全窗口深色遮罩（决策 2），焦点锁在查看器里。

- **顶栏**：左边依次是文件名（没有就不显示）、图片原始尺寸「宽 × 高」和格式、同组有多张时的页码「n / N」；右边是「复制」、「原始大小 / 适应窗口」切换、「关闭」。所有按钮都有无障碍名，都能用键盘操作。
- **图片区**：默认适应窗口，不放大超过原始尺寸。点图片切到原始大小，超出窗口的部分可以滚动查看；再点一下回到适应窗口。切到另一张时回到适应窗口。
- **切换**：同组多张时，左右两侧有「上一张 / 下一张」按钮，← / → 键也能切换。到第一张或最后一张时，对应方向的按钮隐藏，不循环。只有一张时既没有切换按钮也没有页码。
- **关闭**：按 Esc、点「关闭」，或点图片以外的遮罩区域。关闭后焦点回到打开它的缩略图。
- **⌘C / Ctrl+C**：复制当前图片。如果查看器里有选中的文字（比如文件名），复制的是文字。
- **底部提示**：一行快捷键说明（「Esc 关闭 · ← → 切换 · ⌘C 复制 · 点图片切换原始大小」），只有一张时不显示「切换」那段；Windows / Linux 上显示 Ctrl+C。
- **图片解不出来**（数据损坏）：图片区显示「图片无法显示」，「复制」和尺寸不显示，其他照常。

## 复制

**前提**：用户从缩略图按钮、查看器按钮或快捷键触发复制。

- 把图片转成 PNG（决策 6），交给剪贴板写入（决策 7）。
- **成功**：弹出提示「已复制图片」。之后在别的应用里粘贴，得到的是这张图片。
- **失败**：弹出错误提示「复制图片失败」，附上原因（原生通道或浏览器给出的错误）。剪贴板内容不变。
- **server 控制台在非安全上下文**（`http://` 局域网地址，浏览器根本不提供剪贴板接口）：直接失败，原因是「当前页面不支持复制图片，需要通过 HTTPS 访问」。文字复制的 `execCommand` 兜底对图片不起作用，不做兜底。
- **桌面端**：三个平台（决策 8）都把 PNG 写进系统剪贴板，其他应用能当图片粘贴；写入失败时把原生错误带回给上面的失败提示。

## 文案、主题与无障碍

- 所有新文案走共享包 i18n，中文和英文都要有。
- 查看器是模态对话框：有无障碍名（「图片查看：<文件名>」），打开时焦点进入，关闭后焦点回到触发它的元素。
- 系统开启「减少动态效果」时，查看器的开关不做动画。

## 两个宿主

- 缩略图、查看器、复制流程都在共享包里，桌面端和 server 控制台一起生效。
- 桌面端装原生写图片实现。server 控制台不装，走浏览器剪贴板接口；抬钉后不需要额外接线。

## Out of scope

- 助手回复正文里的 markdown 图片。
- 另存为、滚轮或捏合缩放、旋转。
- 用户消息里多张图的排列方式。
- 排队消息撤回：另见 `docs/specs/2026-11-06-queued-withdraw-to-composer.md`。
