## 问题与目标

**目标：让浏览器（桌面与移动）成为账号下一个完整的中继客户端——自己发起新对话，也能看到某台 agentred 上已有的全部会话并把要跟进的关注过来；读转录、发新消息、批准工具调用、回答提问；并保证这么做过之后，那条会话回到桌面端上仍然读得懂。会话内容不因此离开设备。**
（末句已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 决策 1 推翻：保存进账号的对话，其内容镜像在 server 上。）

**硬不变量（已被推翻）：~~agentre-server 不持有任何会话内容。~~** 这句在本轮成立：轮 A 落地时 server 只做三件事——签发浏览器的设备身份、转发中继帧、以及块 1 已有的账号级对象读取，且没有任何存放会话、消息或转录的服务端表。**[`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 决策 1 推翻了它**（2026-08-18，用户裁决）：新的边界是**范围即同意**——账号里保存过的对话，其摘要与完整转录镜像在 server 上（`mirror_session_summaries` / `mirror_journal_frames`）；没保存过的一个字都不落库，删除一条对话会把 server 与执行端两份一起清掉。本规格 R14 的关注名单相应改名为「保存名单」，它同时**就是**镜像的范围。

### 问题

1. **浏览器完全不是一个客户端。** `device_entity` 里 `KindWeb` 与 `KindMobile` 已声明（`device.go:9-10`）但**非测试代码零使用**；中继两个端点都挂在 `DeviceJWT` 组下（`router.go:90-91`），而 web 控制台走的是 `SessionAuth() + CSRF()`（`router.go:61`）。浏览器今天既没有设备身份，也上不了中继。

2. **wire 协议只有 Go 一份实现。** `wire.go` 546 行定义帧与方法，客户端侧 `internal/daemon/client` 712 行承载拨号、多路复用、重连与补齐。浏览器要说这套协议，需要一份 TypeScript 实现——今天一行都没有。

3. **agentred 上的会话没有命名层。** `RunParams`（`wire.go:212-236`）只带 `AgentID` 与 `SessionID` 两个**发起端的本地自增 ID**，没有标题也没有 Agent 名；`SessionSummary`（`wire.go:384-393`）同样；`daemon_sessions` 七个字段里也没有（`session_repo/session.go:30-39`）。而块 1 已确立本地自增 ID 跨机无意义。设计稿屏 42 左栏要渲染的「后端 Agent」「改 refresh 的过期判断」两行，数据源都不存在。

4. **浏览器无法给一条会话发新消息。** claudecode 与 codex 的 runtime **完全不读 `req.History`**（全仓库零匹配；唯一消费者是 `builtin/runtime.go:242`），CLI 靠 `providerSessionId` 续自己的上下文。而 **daemon 不持久化 `providerSessionID`**：桌面端每轮在 `RunParams` 里传入、从 `RunAck` 收回（`daemon/handlers/runtime.go:456`、`:608`）并落**自己**的库，`daemon_sessions` 没有这一列。因此除非发起端的桌面端在线并交出它，浏览器续不上任何一条会话——而桌面端在线时用户直接用桌面端就够了，本轮价值归零。

5. **「这台机器上有哪些会话」有入口，「账号下有哪些会话」没有。** 一个客户端只能对**它已经连上的那台** daemon 发 `runtime.session.list`；账号维度的汇总不存在。

### 基线事实

**agentred 侧的多客户端能力已经实现并合并**，本轮不重造：

- **可见性已是账号级**——前置规格 R12：「已归属账号的 daemon 上，任一同账号客户端可以看到并操作该 daemon 上的全部会话，无论会话由哪个对端发起」。
- **显式接管已有入口**——`runtime.session.attach`（`wire.go:51-59`），刻意与 `list` / `pull` 分开：「list 只是看一眼有哪些会话（看一眼不该改变任何东西）」。
- **按会话扇出已实现**——`connRegistry`（`daemon.go:133-163`）的 `ownerOf` 交回「属主连接 + **这条会话上**的其余同账号订阅者」，注释自陈「桌面与手机因此同时收到同一会话的实时事件」；`subscribersLocked` 把订阅资格定成「上过这条会话」+「同账号认证进来」两条。
- **转录补齐已有 journal**——daemon 级通知日志按 (对端, 会话) 分区、带 seq 游标（`daemon.go:1837-1842` 的 `journalReader.ListSince`）。

因此本轮在 daemon 侧的新增**只有问题 3 与问题 4 那几列**，其余全是浏览器侧与 server 侧。

**本轮基线**（2026-08-10 采集于两个仓库的 `feat/2026-08-10-web-session-access` worktree；`agentre` 起点 `204b7e70`，`agentre-server` 起点 `78d0b48`）。工作区根的 `go.work` 不包含 worktree 路径，因此全部 Go 命令加 `GOWORK=off`：

|---|---|---|
| `agentre` 后端 | `GOWORK=off make test-backend` | EXIT=0，124 个包全过 |
| `agentre` 前端 | `cd frontend && pnpm test` | EXIT=0，239 文件 / 2414 测试 |

采集中发现两处**与本轮无关的既有问题**，按约定只记录不修改：

- **既有抖动**：`agentre-server/internal/pkg/usercode` 的 `TestGenerate_Unique` 首跑失败（`collision at 4595: AZS-XQD`），随后连跑 5 次全绿。它从 32 字符的字母表抽 6 位码（空间 32⁶ ≈ 1.07×10⁹）连抽 10000 个并断言零重复，生日碰撞概率约 **4.6%**——约每 22 次跑必挂一次，是测试本身的设计问题，不是回归。本轮把它当已知抖动。
- **`agentre` 新检出无法自举**：根包 `main.go:26` 的 `//go:embed all:frontend/dist` 与 `make generate` 互为前置（generate 要编译根包 → 根包要 dist → `pnpm build` 出 dist 又要 generate 产出的 `frontend/wailsjs/`），两者都是 gitignore 的产物，因此全新 worktree 里 `make test-backend` 与 `make generate` 都在 setup 阶段就挂。破环办法是先写一个占位 `frontend/dist/index.html`（`agentre-server` 的 `prepare-web-dist` 目标已经这么做，`agentre` 没有对应物）。本轮据此自举，不改 Makefile。

## 参与者与用户故事

1. 作为**出门在外的用户**，我想用手机浏览器看家里那台 agentred 上正在跑的对话，并在它停下来等我批准工具调用时就地点一下，而不是回家开电脑。
2. 作为**关掉了桌面端的用户**，我想从网页给一条还在 agentred 上跑的对话补一句新指令，而不必先把那台桌面端开起来。
3. 作为**手上只有浏览器的用户**，我想直接开一条新对话交给某台 agentred 去跑，而不是只能接着别人开的头。
4. 作为**同时开着桌面端与网页的用户**，我想两边看到的是同一条对话的同一份实时流，而不是各说各话。
5. 作为**换了浏览器或丢了手机的用户**，我想在设备列表里单独把那个浏览器踢下线，而不影响我的桌面端。
6. 作为**注重隐私的用户**，我不想因为开了网页，就让对话内容被 server 存下来。
   （已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 推翻，2026-08-18 用户裁决：换成「没有被我保存过的对话，一个字都不会到 server 上」——保存这个动作同时是同意的表达。）

## 设计决策

| # | 决策 | 依据（及被否方案） |
|---|---|---|
| 1 | 块 2 拆成三轮，本轮只做「浏览器 ↔ agentred」 | 用户裁决（2026-08-10）。拆分依据是**服务端侧已经有什么**：agentred 侧的可见性、attach 与扇出全部已实现并合并，所以本轮的浏览器客户端（最贵也最容易出错的一块）能对着一个**已经跑通**的服务端去验；等传输层站住了，B 轮再换上新的服务端形态。否：一轮做完 A+B+C（体量大致是刚做完的工作区同步的一倍以上，且直到最后才能在真环境里验证任何东西）；否：先做 B（服务端新形态没有任何客户端验得上，只能靠单测） |
| 2 | ~~会话仍只住在发起端与执行端，server 一条都不存~~（**已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 决策 1 推翻**，2026-08-18：保存进账号的对话，其摘要与转录镜像在 server 上；范围即同意） | 用户裁决（2026-08-10）：「都不读，应该是只记录自己发起的对话，或者是自己作为执行端的对话」。这与工作区同步规格的决策 11 一致，也与今天的现实一致——桌面端发起、agentred 执行时，两边本就各持一份（桌面端有标题与消息，agentred 有 `daemon_sessions` 与 journal）。本轮不搬任何数据，只加「别的端能不能列出并接入」。否：会话上行同步到 server（另一个量级的隐私承诺，且块 4 的「显式拿出来」就失去存在意义） |
| 3 | 不做**自动**汇总：发现走设备页下钻，跟进走用户显式「关注」 | 用户裁决（2026-08-10，两次）。自动汇总要么让每个客户端对 N 台设备各发一次 `session.list`（打开页面就是 N 次往返，离线设备的对话连名字都没有），要么让 server 存一份**全量**会话元数据索引（决策 2 的让步）。用户提出的第三条路避开了两者：**下钻是发现，关注是跟进**——「对话」页只列用户显式关注的那几条，跨机器但不是全量。分工因此是「设备页 = 这台机器上的全部对话；对话页 = 我挑的那几条」。否：server 存全量元数据索引（决策 2 让步，隐私政策要改）；否：逐端现问（N 次往返 + 离线设备完全缺席）；否：只有下钻、没有对话页（每次跟进都要先想起来「它在哪台机器上」，而这正是用户不该记的事） |
| 4 | 浏览器注册成一台 `kind=web` 的设备，走既有的设备 JWT | 用户裁决（2026-08-10）。`KindWeb` 已在 schema 里（问题 1），中继侧因此**零新鲜事**——鉴权仍是单一来源。可观察收益是用户故事 5：每个浏览器在设备列表里各占一行，可以单独解除授权。代价：设备列表会变长。否：让 `/v1/relay/client` 也接受 `SessionAuth`（中继鉴权从单一来源变成两套，WebSocket 带 cookie 还要自己处理 CSRF 与跨站，且无法单独踢掉某一个浏览器） |
| 5 | 浏览器的设备注册不走设备码，由已登录的 web 会话直接换取 | 无选择余地。RFC 8628 设备流的终点是「在另一台设备上输码批准」，而此处发起方**就是**那台已经登录的浏览器，让它自己批准自己没有意义，也不增加任何安全性。新端点要求 `SessionAuth + CSRF`（与既有 web 控制台端点同组）。否：浏览器也走设备码（用户要在同一块屏幕上抄一遍六位码给自己） |
| 6 | 一个浏览器一台设备，凭据存活到用户主动登出或解除授权 | 每次打开标签页都注册一台新设备会让设备列表迅速失控，而用户故事 5 要的是「把**那个**浏览器踢下线」——设备必须稳定对应一个浏览器实例。设备指纹由浏览器本地生成并持久化，首次注册时上报。否：每次会话新建一台设备（列表失控，解除授权也失去指向）；否：整个账号共用一台 `web` 设备（踢一个等于踢全部） |
| 7 | 会话的标题与 Agent 身份随 `runtime.run` 每轮携带，daemon 落库并在 `session.list` 回传 | 用户裁决（2026-08-10）。问题 3 只有三条出路，这条是唯一能让屏 42 照稿实现的。Agent 用**块 1 的同步标识**而不是本地自增 ID（`AgentID` 跨机无意义），浏览器拿它向 server 解析名字与头像——块 1 的 `workspace_svc` 读取端点已经存在。每轮幂等覆盖，因此改名最多滞后一轮。否：不扩展协议，列表只显示「工作目录 · 后端 · 状态 · 最后活动」（同一项目下的几条对话长得一模一样，设计稿要改）；否：留给 B 轮（本轮发出去的界面是残的，而本轮本来就只对有 agentred 的用户有价值） |
| 8 | daemon 持久化 `providerSessionID` | 问题 4：不做这一条，本轮的「发新消息」就要求发起端桌面端在线，而那时用户直接用桌面端即可，整轮价值归零。前一轮规格 R15b 已经写着「执行、cwd 与 `provider_session_id` 在那台 agentred 上」——代码还没兑现这句，本轮兑现它。写入点是既有的 `RunAck` 那条路径（`daemon/handlers/runtime.go:456`、`:608`），不新造链路。分量：一个不透明标识符，而 CLI 自己的会话文件本就在那台机器上。否：浏览器发消息时先向发起端桌面端索取（要求桌面端在线，见上）；否：浏览器只读不写（与本轮目标和用户故事 2 直接冲突） |
| 9 | 浏览器的断线补齐复用桌面端那一条路，不新造机制 | `session.attach` + `session.pull` 按 seq 游标补齐是前置规格为「重连的客户端」定的入口，浏览器与桌面端在这件事上没有任何区别。既有的 `StreamConnectionState`（connected / reconnecting / lost，`chat_svc/types.go:110-113`）也照搬。否：为浏览器另设一套快照接口（同一个问题两套解法，且 journal 的逐事件补齐比快照更准） |
| 10 | 桌面与移动两套界面同一轮做完 | 用户裁决（2026-08-10）。设计稿里移动那套（屏 20/21/22/26/29-33）比桌面还全，两套隔轮做会让信息架构走偏。代价：本轮前端工作量大致翻倍，而真风险在传输层。否：移动另起一轮 |
| 11 | 机器语境放顶栏面包屑，不放左栏 | 用户裁决（2026-08-10），对着 mockup 帧 45a / 45b 两个变体选定。面包屑与 SideNav 的层级关系一致（设备页 → 这台机器），左栏因此完整留给会话分组。否：左栏顶部放机器卡片（45b，机器与它的会话在空间上更粘，但左栏多一层、与搜索行叠起来偏挤） |
| 12 | 桌面按 Agent 分组、移动按状态分组，不强行统一 | 用户裁决（2026-08-10）。两端屏幕尺寸决定了不同的取舍：桌面一屏能容下多个 Agent 分组，移动上「等你处理」置顶才有用。这也是设计稿两端的既有形态，本轮不为一致性去改一个本来就合理的差异。否：统一按 Agent（移动上待批准的会话可能埋在第三个分组里）；否：统一按状态（桌面屏 42 左栏要重画，且同一 Agent 的会话被拆散） |
| 13 | 浏览器发起的一轮必须在桌面端上读得懂，本轮一并做 | 用户裁决（2026-08-10）。前置规格 R17 的来源标识只覆盖 steer，而浏览器在空闲会话上发消息走的是「开新一轮」那条路——桌面端因此只会看到一段没有提问的回复，与真·自主续轮在界面上完全同形。不做它，本轮发布的净效果是**用了新功能反而弄坏了老功能**：手机上聊过的会话，回到桌面端就读不懂。这不是打磨项。代价：本轮在 `agentre` 仓库多一条 daemon + wire + `chat_svc` + 转录的联动改动。否：只标「来自其它设备」不解析设备名（省一个握手字段，但多台设备时分不出是哪一台）；否：排到下一轮（中间态是坏的） |
| 14 | 关注名单存在 server 上，账号级 | 用户裁决（2026-08-10）。本轮的主场景是「出门在外用手机看」，而手机上关注的那一条，回到电脑上打开网页就该已经在那儿——存浏览器本地做不到这件事。**存的是指针**（目标设备指纹 + 会话标识 + 关注时间），不是会话内容：server 仍然拿不到标题与消息，硬不变量不破。（后半句已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 推翻：这份名单现在**就是**镜像的范围，名单里的每一条其内容都存在 server 上；「关注 / 取消关注」也随决策 5 改名为**保存 / 删除**。）否：存浏览器 `localStorage`（零服务端状态，但每个浏览器各一份、清缓存即失，主场景直接落空）；否：不持久化只管当次（「关注后不用再下钻」这个好处只在当次成立） |

## 浏览器的设备身份

**R1 — 已登录的浏览器可以取得一台属于自己的设备身份。** 用户在 web 控制台登录后，浏览器以自己持久化的设备指纹换取一台 `kind=web` 的设备与设备 JWT。同一个浏览器重复请求时得到的是**同一台**设备（按指纹幂等），不新增行。未登录的请求被拒绝，不产生任何设备行。

**R2 — 浏览器出现在设备列表里，且可以被单独解除授权。** 该设备与桌面端、agentred 并列出现在设备页，标明它是一个浏览器与最近使用时间。解除它的授权后，它的设备 JWT 失效、中继连接被拒，**其余设备不受影响**；用户在该浏览器上刷新页面时按 R11 表达为「这台设备已被解除授权」。吊销的生效延迟受前置规格 R4 约束。

**R3 — 浏览器的设备凭据不比桌面端多任何权限。** 它与桌面端一样是中继上的**纯出站调用方**，只能连 `/v1/relay/client`；它不能登记为可被寻址的目标，也不能被派活。

## 列出与接入会话

**R4 — 从设备页下钻到一台 agentred 的会话列表。** 用户在设备页选中一台在线的 agentred 后，进入该机器的会话列表：列出这台机器上的**全部**会话，无论由哪个对端发起（前置规格 R12 已放开可见性）。离线的 agentred 不可进入，行上标明离线与最后在线时间。

**R5 — 会话列表每条显示标题与状态；分组依据桌面与移动各不相同。** 每条会话显示：对话标题、运行状态、是否**正在等待用户输入**、最后活动时间；Agent 的名称与头像经块 1 的同步标识解析（R7）。**桌面按 Agent 分组，移动按状态分组**（等你处理 / 运行中 / 已中断），沿用设计稿两端各自的既有形态（决策 12）。

R7 到达之前创建的老会话既没有标题也没有 Agent 标识，此时归入一个「未命名」分组并如实退化为「工作目录 · 后端 · 状态」，**不猜、不填占位名**（mockup 帧 46 的 R5 格）。

**R6 — 接入一条会话后收到实时流，并可与其它端同时在场。** 用户打开一条会话即显式接管它（`session.attach` 的语义），随后按 seq 游标补齐历史转录，并开始接收实时事件。**同一条会话可以同时被桌面端与浏览器接入**，两边收到同一份实时流——这是前置规格已实现的按会话扇出，本轮只是多了一类订阅者。

**R7 — 会话的标题与 Agent 身份随每轮执行到达 agentred。** 桌面端发起每一轮时携带该会话当前的标题与它所属 Agent 的**同步标识**（块 1 的账号级标识，不是本地自增 ID）；agentred 落库并在会话列表里回传。因此：改名后最多滞后一轮生效；从未跑过一轮的会话不在 agentred 上存在，自然也不在列表里。**agentred 上因此开始留存对话标题**，见「安全与隐私」。

## 读与写

**R8 — 浏览器读到的转录与桌面端一致。** 接入一条会话后，浏览器展示的转录内容与桌面端上同一条会话一致：消息、工具调用与结果、以及各类结构化卡片。~~**渲染的保真度不在本轮承诺范围内**~~——这句写于共享包抽离之前，**已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 决策 14 推翻**（2026-08-18）：`@agentre-ai/agentre-ui` 现在导出整套转录渲染（`TranscriptRowView` / `CanonicalToolRouter` / `ToolApprovalCard` / `buildTranscriptRows`），web 控制台用的就是它，两端因此是同一套卡片，不再留保真度例外。

**R9 — 浏览器可以给一条会话发新消息，不需要发起端在线。** 用户在浏览器上发出的消息进入该会话的下一轮，在那台 agentred 上执行；上下文由 agentred 侧持有的 `providerSessionID` 续上（决策 8），**不要求发起该会话的桌面端在线**。发出的消息与产生的回复对同时在场的其它端一并可见（R6）。

**R10 — 浏览器可以批准工具调用与回答提问。** 会话停在等待用户输入时，浏览器给出与桌面端同一套选择，用户的决定即时生效。**同一个待决策只能被回答一次**：已被别的端回答过时，浏览器就地说明它已被处理并刷新状态，而不是报错或静默失败。

**R11 — 不可达与失效都有明确说法，且彼此可区分。** 以下四种情形各自给出不同的说明，不折叠成同一个错误：目标 agentred 离线；浏览器与 server 之间断线（可自动重连，按既有的 connected / reconnecting / lost 表达）；该浏览器已被解除授权（须重新登录）；账号已登出。断线重连后自动补齐断连期间的事件，用户不需要手动刷新。

## 关注与「对话」页

下钻是**发现**，关注是**跟进**（决策 3）。两者的分工是：设备页回答「这台机器上有哪些对话」，「对话」页回答「我在跟进哪几条」。

**R12 — 每一条会话都可以关注与取消关注；入口在桌面与移动上位置不同。** 用户可以把一条会话标为关注，再操作一次取消。关注是一个**显式动作**，`session.attach` 那种「打开就接管」的接入行为不构成关注（决策 15）——**桌面端上自己发起的会话同样不自动进入名单**。取消关注不影响那条会话本身，也不影响别的端。

入口位置：**桌面**放在会话列表的行尾（mockup 帧 45a），列表密度容得下，且悬停即可辨识；**移动**放在对话详情页的顶栏（帧 48c），不放在列表行里（决策 16）。两端的状态与名单是同一份，在哪一端操作都一样。

**R13 — 「对话」页是这一端的对话，以 Agent 为骨架；关注来的会话在这里出现，不需要下钻。** SideNav 的「对话」项列的是**这一端的对话** = 它自己发起的（R15）+ 关注来的（R12）。两个来源在这一页上**不作区分、不分节、不加徽标**——用户看到的就是「我的对话」，来源是实现细节。页面因此叫「对话」，不叫「关注的对话」。

**骨架是账号下的 Agent 列表**（块 1 已把 Agent 同步到 server，`workspace_svc` 的读取端点已存在），因此这一页**任何时候都有内容**：桌面按 Agent 分组，移动的列表行本身就以 Agent 命名。**机器落在每一条会话行上**（一行小字「机器 · 时间」），不作分组维度——跨机器只是这些对话的属性之一，不是用户找它们的路径。每条显示与 R5 同一套信息，可直接打开读转录与发消息，**不必先去设备页**。

- **不存在「整页空白」这种空态。** 一条对话都没有时，Agent 骨架照常列出，每个 Agent 下面一行「还没有对话」。空态的**主动作是「开始第一个对话」**（R15），去设备页关注是底下一行次要出口。空态文案里**不出现「关注」**这个机制词——web 自己发起的对话同样落在这里，用机制词描述这个状态是错的。桌面见 mockup 帧 49b，移动**沿用设计稿既有的屏 32**（文案与主按钮原样不动）。
- 关注来的会话所在机器**离线**时，该条仍然列出并标明离线，点进去按 R11 说明它此刻读不到；**不因为机器离线就从名单里消失**。
- 关注来的会话在那台机器上**已经不存在**时（例如 daemon 侧的记录被清理），该条标为失效并可一键从名单移除。

**R14 — 关注名单属于账号，不属于某一个浏览器。** 在任一端关注之后，同账号的其余端打开「对话」页时该条已在名单里（决策 14）。解除某台设备的授权不改变名单内容（名单属于账号，不属于那台设备）。**「名单里只有指向、不含标题 / 消息 / 转录」这半句已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 决策 1 / 2 推翻**（2026-08-18）：名单本身仍然只有指向，但名单里的每一条其摘要与整条转录都镜像在 server 上——这份名单就是镜像的范围，也是隐私开关本身。

## 从 web 发起新对话

**R15 — 浏览器可以自己发起一条新对话。** 用户挑一个 Agent 与一个项目，对话在**某台 agentred** 上起来：按块 1 的 R15d，server 端的挑选**跳过 `device_id` 为空的档**（那是「当前这台桌面端」，浏览器语境下没有指代对象），只在 agentred 里按顺序取第一个可用的。全部档都不可用时不静默失败，按块 1 的 R15 逐档说明原因（未配对 / 离线 / 那台机器上没配这个项目的路径 / 各类既有 `BlockReason`）。界面见设计稿屏 23 / 24 / 25。

**R16 — web 发起的对话整条住在那台 agentred 上，并自动出现在「对话」页。** 浏览器没有本地存储，因此它作为发起方不持有任何东西：会话行与转录事件都在那台 agentred 的 `daemon_sessions` 与 journal 里（标题落在 R7 新增的那一列）。**server 仍然一条都不存**，硬不变量不变。这条对话是这一端自己的，因此**不需要「关注」**就出现在「对话」页（决策 15 只约束别的端发起的对话）。

**R17 — web 发起的对话不注入 `org` / `subagent` / `hook`，且这件事在界面上说得明白。** 这三个内置工具的真身在桌面端（决策 18），web 发起时无法注入。**发起前**就要让用户看见这个差别——不是等工具调用失败了才报错；措辞说清「这三个工具此刻用不了」以及原因（它们要那台桌面端在场）。从桌面端发起的对话不受影响，行为一个字不变。

## 桌面端上的呈现

本轮的主体是浏览器，但浏览器的每一次写入都会出现在同一条会话的桌面端上。以下两条约束的是**桌面端**（`agentre` 仓库）。

**R18 — 浏览器发起的一轮，在桌面端上读得懂。** 桌面端接入同一条会话时，浏览器发出的那条用户消息**在桌面端的转录里落成正常的一行用户消息**，并按前置规格 R17 带上来源标识（「来自 <设备名>」）。

这一条不是打磨项：前置规格 R17 的渲染层已经实现，但它只覆盖 **steer**（轮次进行中被 backend 消费的插话）。浏览器在一条**空闲**会话上发消息走的是「开新一轮」那条路，桌面端今天没有任何路径把那条用户消息落成转录行——不补的话，桌面端只会看到一段没有提问的回复，与真·自主续轮（CLI 在后台任务完成后自发跑的纯 assistant 轮）**在界面上完全同形**，用户无法分辨。因此本轮要让「开新一轮」这条路也携带发起方的设备标识与用户文本，扇出给同一条会话的其余订阅者。

**单端使用时界面零变化**：本机发出的消息不带来源标识，呈现与今天逐像素一致（前置规格 R17 的既有承诺不变）。

**R19 — 来源标识显示的是人能认出的名字。** 浏览器在握手时声明自己的设备显示名（如「Chrome · macOS」），桌面端据此渲染来源标识。名字缺失时按既有行为回退到指纹或通用文案，**不阻塞消息落地**。

## 界面

界面照设计稿 `设计稿/agentre-server.pen` 实现：桌面屏 42（对话），移动屏 20 / 21 / 22（对话列表、按项目筛选、对话详情）、26（换项目）、27（设备——移动端下钻路径的入口）、29（导航抽屉）、30（桌面端未连接）、31 / 32（空态）、33（审批已过期）、23 / 24 / 25（从 web 发起新对话，决策 17 拉进本轮）。

**下钻路径**：设备页 → 选一台 agentred → 该机器的会话列表 → 一条会话。列表因此是**这台机器上**的会话，不是账号全域的。

**机器语境放在顶栏的面包屑上**（决策 11，mockup 帧 45a）：「设备 / <机器名>」加在线态与本机会话数，行尾一个「换机器」入口就地切换。设计稿屏 42 现有的顶栏（「对话 9 · 桌面端已连接」）与移动屏 20 现有的跨机器 OfflineStrip（「公司 Mac mini 未连接，2 个对话停在那儿」）都预设了账号全域汇总，**随本轮一并改掉**：机器在线态由顶栏承载，别的机器不在本屏出现。

**不新增导航项**，SideNav 保持块 1 定下的总览 / 对话 / 设备 / 审计四项；本轮把「对话」从占位页变成真页面——它的内容是 **R13 的这一端的对话**（自己发起的 + 关注来的，mockup 帧 49 / 49b），不是账号全域的会话汇总。

**两条路径的入口各自明确**：设备页展开一台 agentred 时多一节「对话」，给出条数、等待处理数与「查看这台机器的对话」（mockup 帧 47）；会话列表里每条行尾是关注开关（帧 45a）；「对话」页顶栏给「去设备页找更多对话」（帧 49）。

**桌面端也有界面改动，虽然本轮的主体是 web 控制台。** R18 / R19 落在桌面端的转录上：来源标识的渲染层是前置规格 R17 已实现的 inline pill，本轮**不新造控件**，只是让「开新一轮」这条路也走到它。桌面端不新增页面、不新增导航、不改设备面板（浏览器不进那张表——它列的是配对的 agentred）。

新增文案在 web 控制台侧同时落 en 与 zh-CN（`agentre-server/frontend/src/i18n/`，既有的 `locale-parity.test.ts` 以 en 为基准守卫键集）；桌面端侧同时落 en 与 zh-CN（`agentre/frontend/src/i18n/locales/{en,zh-CN}/common.json`，`i18n.test.ts` 守卫）。**可访问性**：运行状态、等待输入、离线与解除授权四类状态不得仅靠颜色区分，均带文字。

## 安全、隐私与兼容性

- **~~server 不持有会话内容。~~ 已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 推翻**（2026-08-18）：账号里保存过的对话，其摘要与整条转录存在 server 上；没保存过的一个字都不上行，删除会把两边一起清掉。中继本身仍然只转发帧、不落盘——落盘的是 server 作为常驻中继客户端另开的那条路。
- **agentred 上开始留存对话标题。** 决策 7 的直接后果。标题是对话内容的摘要，分量高于 `daemon_sessions` 现有的七个字段，但低于 prompt——而 prompt 每轮都已经过线（前一轮规格已就此裁决）。agentred 是用户自己的机器；~~官方托管下标题**不经过 server 落盘**，只在中继帧里过境~~——**这半句已被 [`2026-08-18-server-session-mirror.md`](2026-08-18-server-session-mirror.md) 推翻**（2026-08-18）：保存进账号的对话，标题连同整条转录一起落在 server 上。
- **浏览器凭据的存放。** 设备 JWT 存在浏览器里，其失窃后果与桌面端设备凭据失窃相同：可读写该账号下全部 agentred 上的会话。用户故事 5 的单独解除授权是这条的对冲。**不为桌面端另设开关**——用户裁决（2026-08-10）：设备连上账号即拥有完整权限，与前一轮 2026-08-08 的同一条裁决一致。
- **老 agentred 兼容。** 未升级的 agentred 不认识 R7 的新字段与决策 8 的新列：它照常工作，只是会话在浏览器上按 R5 退化显示，且 R9 的发消息不可用。浏览器必须如实说明该机器需要升级，**不得静默失败**。反向同样：升级后的 agentred 面对老桌面端照常工作。
- **不改动既有握手与帧结构。** 本轮只**新增**字段与方法，不改变前置规格定下的握手、中继信封与既有帧的语义。
