# 转发失败的归因：共享代理把「是哪一件事」交给宿主

> Status: Draft
> Owner: pkg/wire/portforwardhost
> Last updated: 2026-09-09

**Objective:** 端口转发的宿主能准确知道每一次失败是七件事里的哪一件，并自己决定怎么呈现；被转发应用**自己**的响应永远不经过这条路。

## Problem（都有运行期证据）

控制台那一半上线后的运行期验证（`agentre-server` 的 `e2e/scratch/2026-09-09-console-port-forward-host/report.md`）查出两条，根因都在这个共享包：

1. **共享包把四种不同的失败答成同一个 502**（`pkg/wire/portforwardhost/proxy.go:541-576`）：「端口上没有服务」「设备够不着」「上游把请求断了」「转发没完成」。宿主拿不到任何可靠信号去分辨它们，只能按状态码猜。
   后果实测：控制台把**被转发应用自己答的 502** 换成了「端口上没有服务」那张页——服务明明在跑，页面却叫用户去把它起起来（证据截图 `07-upstream-502-rewritten.png`）。
2. **七句用户可见文案硬编码在共享包里**（`proxy.go:531-539`），且是桌面端口径。控制台沿用它们就会说错话：用户在**控制台**里把映射停用，却被告知「到 **agentre** 里把它启用之后再打开」——而他未必装了桌面端。

两条的共同根因是同一个：**这一层在做只有宿主才有资格做的两件事——判断和措辞。**

## Actors and user stories

1. 作为一个把转发挂在自己 UI 里的宿主，我希望拿到「是哪一件事」而不是一句写死的中文，这样我能用自己的话、按自己的形态说给用户听。
2. 作为通过控制台访问转发的用户，我希望失败提示指向我真正该做的下一步，而不是叫我去开一个我没有的应用。
3. 作为桌面端用户，我希望这次改动之后我看到的东西**一个字都不变**。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 新增一个**类型化的失败种类**（七个，与今天七句一一对应），连同端口与默认状态码交给宿主 | 四个失败点今天全部汇到同一个 `writeFailure(w, status, message)`（`proxy.go:282/309/333/482`），接入点唯一。Rejected: 只补一个「是不是代理自己的失败」的布尔 —— 分不开「端口没服务」与「设备够不着」，而那正是要给用户的两句不同的话 |
| 2 | 渲染钩子是**可选**的；不传就用包内今天那几句纯文本，**逐字节不变** | 用户决定：桌面端这一轮零行为变化。那几句（「到 agentre 里…」）对桌面端本来就是对的，错的只是控制台沿用了它。Rejected: 强制宿主提供 —— 会把桌面端拖进这一轮 |
| 3 | 钩子**只在代理自己的失败上**被调用；被转发应用的响应一个字节都不经过它 | 这条是 Problem 1 的根治：宿主不再需要按状态码嗅探，也就不可能误伤上游自己的 502/404。这是本轮唯一真正的行为契约 |
| 4 | 交给宿主的**不包含**包内那几句中文 | 给了它，宿主就会有人去匹配它，于是又长出一条「上游改一个字就静默失灵」的耦合——那正是消费方规格决策 13 拒绝过的形状 |
| 5 | 不动 wire 协议、不动 `.proto`、不动任何生成物 | 这是一个 Go API 的扩展点，与线上格式无关。因此 `protocol_version` 保持 `0.5.0`，两个宿主的版本守卫不受影响 |

## 可观察的要求

1. **前提**：宿主装了渲染钩子。**动作**：代理自身发生七种失败中的任意一种。**结果**：钩子被调用一次，拿到该次失败的种类、端口与默认状态码；响应体完全由宿主写出。
2. **前提**：宿主装了渲染钩子。**动作**：被转发的应用自己答出任意响应（含 4xx/5xx）。**结果**：钩子**不被调用**，该响应原样透传。
3. **前提**：宿主**没有**装渲染钩子。**动作**：代理自身发生任意一种失败。**结果**：与本轮之前逐字节相同的纯文本答复（状态码、`Content-Type`、`Cache-Control`、正文）。
4. **前提**：任意宿主。**动作**：任意一次转发。**结果**：101 升级、流式与信用背压的行为不变。

## Non-goals

- 不给这七句做 i18n（它们只是默认值；要 i18n 的宿主自己出文案）。
- 不改变任何失败的**默认状态码**。
- 不改 wire 协议、不改设备侧。
- 桌面端不接钩子（用户决定）。

## Testing decisions

| Seam | What it verifies |
| --- | --- |
| 代理的失败用例 | 七种各自把正确的种类交给钩子；端口与默认状态码正确 |
| 透传用例 | 被转发应用自己的 4xx/5xx 不触发钩子、正文原样 |
| 默认渲染用例 | 不传钩子时七种答复与本轮之前逐字节相同（这条是桌面端零变化的守卫） |
| 桌面端宿主 | `internal/pkg/portforward` 既有用例全绿且未修改 |

## Out of scope

- 控制台那一侧怎么用这个钩子——归 `agentre-server` 的消费方规格，它 pin 本轮推送后的修订。
