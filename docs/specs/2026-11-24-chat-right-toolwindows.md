# 对话页工具窗、worktree 跟随与会话关联

> Status: Approved
> Owner: desktop app maintainers
> Last updated: 2026-11-24

**Objective:** 把对话页右侧改成 IDEA 式的工具窗体系（四个槽位、常驻图标条、停靠 / 自动收起 / 浮动、文件在编辑区分屏打开、终端停靠在对话下方），新增「关联」「会话信息」「网页预览」三个工具窗与「会话 ↔ 看板任务」关联，并让整个对话页——工具窗、终端、文件预览、转录里的文件与 localhost 链接——始终跟着 AI 实际所在的位置（worktree、远端设备）走。

**Hard invariant:**
- 工作根的信任边界不放宽：只有与会话工作目录指回同一个 git 主仓库（git 公共目录相同）的目录才能成为工作根；`/tmp` 之类 AI 碰过的路径永远不会成为工作根。
- 不再出现「同一个链接，预览给的是一份文件，复制路径 / 系统打开给的是另一份」。
- 输入框上方的任务进度条、标题栏的后台任务胶囊与弹层保持现状（任务进度只修数据缺口）。
- 看板任务的阶段只由用户改变，本轮任何自动行为都不改阶段。
- agentre ↔ agentred 协议只增加字段、不增加方法与事件类型、不升协议版本；新桌面端配旧 agentred、旧桌面端配新 agentred 都能正常工作，缺少新信号时回落到今天的行为。
- agentre-server 网页端除随共享包升级的链接 / 预览 / 看板接口适配外，可见行为不变。

## Problem

1. **打开文件预览后，对话被挤到约 420px。** 侧栏（默认 240px，`chat-context-sidebar/index.tsx`）与文件预览（默认 440px，`file-preview/file-preview-panel.tsx`）是两条独立的列，都从对话区要宽度（已验证，mockup「现状」）。
2. **侧栏一次只能看一页，关上后什么状态都看不到。** 大纲 / 变更 / 目录是同一侧栏里的三个 tab（`chat-sidebar-store.ts`），变更数只在侧栏打开且停在「变更」时可见（已验证）。
3. **终端会把对话切走。** 终端是独立的标签页（`chat-tabs-store.ts` 的 `terminal` 标签），打开后看不到 AI 正在做什么（已验证）。
4. **AI 进入 worktree 后识别得太晚。** 工作根只在 AI 写文件之后才被认领（`workspace_fs_svc/work_roots.go` 认领条件 1），且前端只在轮次结束后重取（`use-work-roots.ts` 的 `doneTick`）（已验证）。
5. **建在仓库内部的 worktree 永远认领不上。** Claude Code 的 EnterWorktree 默认建在 `<repo>/.claude/worktrees/<name>`，Hermes 建在 `<repo>/.worktrees/`；这些路径前缀落在主根之内，被 `withinAnyRoot` 当成已在根内而跳过（代码阅读 + Claude Code 2.1.326 实测；复现测试待写）。
6. **ACP 与 Hermes 的写文件在轮末重算时认不出来。** 这两家的写入只在实时路径被识别（`acp/translator.go`、`hermes/translator.go`），落库后的工具名 / 入参 `canonical.FromToolUse` 不认，因此永远触发不了认领（代码阅读；复现测试待写）。
7. **相对写入路径被直接跳过。** pi / builtin 常写 `../wt/x.go`，认领逻辑见到相对路径就跳过（`work_roots.go` 的 `isAbsPath` 分支，已验证）。
8. **转录链接与预览用的不是同一个根。** 转录链接按会话工作目录解析（`rich-link.tsx` 的 `classifyLink`），预览按侧栏当前工作根取数（`workRootBySession`）；AI 在 worktree 里说 `src/a.ts` 时，预览、复制路径、系统打开可能指向不同的 checkout（代码阅读）。
9. **兄弟 worktree 的绝对路径进不了预览。** 它在会话工作目录之外，一律交给系统打开；远端会话只能得到「本机上没有这个文件」（代码阅读）。
10. **切换工作根会让已打开的预览标签悄悄换内容。** 预览标签只按相对路径记（`file-preview-tabs-store.ts`）（代码阅读）。
11. **识别 worktree 所需的信号大多已到手却没人读。** Claude Code EnterWorktree / ExitWorktree 的结果元数据已进入 `ToolResult.Meta`；Codex 每条命令的 `cwd` 已存进工具入参；Claude init 帧的 `cwd` 被丢弃，PostToolUse hook 输入的 `cwd` 未解析（2026-11-24 调研，Claude Code 2.1.326、Codex 0.172.0 真实运行验证）。
12. **会话之间的派发关系基本没有记录。** 只有 `agrctl send --wait` 在派发方转录里留一张卡片（`SubagentStateBlock`）；不带 `--wait` 的 send 不记录；agent 派发（agent_call）的调用链只在内存里（`subagent_svc/subagent.go`）；被派发的会话无从知道谁派发了它（代码阅读）。
13. **会话与看板任务之间没有关联。** `issues.session_id` 从未被写入，同步时清零（`sync_svc/adapter_issue.go`），看板卡片与对话页都看不到彼此（代码阅读）。
14. **远端会话里的 localhost 链接打开的是桌面本机。** `http://localhost:...` 被原样交给系统浏览器（`rich-link.tsx`、`transcript-ports-desktop.ts`），而服务跑在远端设备上（代码阅读；复现测试待写）。
15. **长会话里 Codex 的任务进度会漏。** Codex 计划是 `plan` 块，整会话补取只取 `text` / `tool_use`（`hooks/use-chat-session.ts`），最近 30 条消息之外的计划拿不到（代码阅读；复现测试待写）。
16. **会话的元信息散落各处或根本不可见。** 模型、思考力度、权限在输入框旁，后端与设备在标题栏，累计用量、带入的记忆、CLI 会话 ID、创建时间没有任何展示（代码阅读）。

## Actors and user stories

1. As a `桌面端用户`，I want 同时看到变更、目录和终端而不挤掉对话，so that 我能一边看 AI 在说什么一边核对它改了什么。
2. As a `桌面端用户`，I want 侧栏关着也能看到改了几个文件、有没有别的会话在改同一份代码，so that 不用反复开关面板。
3. As a `桌面端用户`，I want 打开文件时文件和对话并排、需要时让文件占满，so that 看 diff 时不必在两条窄列之间取舍。
4. As a `桌面端用户`，I want AI 一进入 worktree，整个对话页就跟过去（本机与远端都一样），so that 我看到的目录、变更、终端和链接都是 AI 正在动的那份代码。
5. As a `桌面端用户`，I want 点对话里的文件链接或 localhost 链接，打开的就是 AI 当时说的那个文件 / 那台机器上的服务，so that 不会把主仓库或本机的东西当成 AI 的成果。
6. As a `桌面端用户`，I want 看到这个会话是谁派发的、它又派发了谁、它挂在哪些看板任务上，so that 多个 Agent 协作时我能顺着关系找到相关会话。
7. As a `桌面端用户`，I want 在应用内直接看 dev server 的页面，so that 不用在浏览器和对话之间来回切。
8. As a `桌面端用户`，I want 从看板任务直接开一个会话、或把会话挂到任务上，so that 任务和执行它的会话互相找得到。

| 23 | 会话 ↔ 看板任务：三个入口（看板卡片「开始会话」、关联窗里关联已有任务、关联窗里新建任务），多对多，阶段不自动改，只存本机不同步 | 用户逐项决定；会话本身不跨设备 |
| 24 | 网页预览与远端 localhost 链接走现有「打开会话端口」的端口转发路径；自动建的转发设置保留；https 不自动开「忽略证书错误」 | 与今天后台弹层「打开端口」一致；忽略证书是安全开关，留给用户决定 |
| 25 | 问题 5、6、7、14、15 与本轮一起修，修前先写复现测试 | 用户决定并入本轮 |
| 26 | 全部在同一轮交付 | 用户决定「一起做」；实现计划按依赖拆阶段 |

## 工具窗布局

**槽位与默认。** 对话页右侧与对话下方共有四个槽位：右上、右下、底部左、底部右。默认位置：右上 大纲、变更、网页预览；右下 目录、关联、会话信息；底部左 终端；底部右为空。每个槽位同一时刻最多显示一个工具窗；同侧两个槽位都有工具窗时分屏显示（右侧上下分，底部左右分），分隔条可拖动；右侧与编辑区之间、编辑区与底部之间的分隔条也可拖动。所有工具窗的内容超出可视高度时可滚动。

**图标条。** 对话页最右边是一条常驻的竖向图标条，按槽位分组：右上一组、右下一组（之间有分隔），底部两组放在图标条下端。
- 点击：该工具窗未显示时，显示它（替换同槽位当前的工具窗）并获得焦点；已显示时隐藏它。
- 变更图标带角标，数字为变更工具窗当前档位的文件数；为 0 或数据未就绪时不显示。
- 终端图标在本会话有存活的终端进程时显示运行中圆点。
- 关联图标在「同一份代码上在跑」出现文件重叠时显示提醒色圆点。
- 悬停显示工具窗名称与快捷键；右键弹出与工具窗 ⋯ 菜单相同的菜单。
- 对话标题栏里现有的「显示 / 隐藏侧栏」按钮移除。

**工具窗标题栏。** 显示名称（变更、关联带数量）；⋯ 与「隐藏」在悬停或获得焦点时出现。获得焦点的工具窗有一圈焦点描边。终端与网页预览的标题栏同时承载各自的标签。

**⋯ 菜单。** 视图模式（停靠·固定 / 停靠·失焦自动收起 / 浮动，当前项打勾）；移到（右上 / 右下 / 底部左 / 底部右，当前项打勾）；最大化；隐藏；恢复默认布局。

**视图模式。**
- 停靠·固定：占据槽位，与编辑区并排，焦点离开也不收起。默认模式。
- 停靠·失焦自动收起：占据槽位；焦点移到编辑区或其它工具窗时自动隐藏。
- 浮动：浮在编辑区上方，不占槽位宽度；拖标题栏移动、拖右下角改变大小，位置与大小被记住；焦点离开不收起，用「隐藏」、⇧Esc 或再点图标关闭。

**拖动换槽。** 把图标拖到图标条的另一组：拖动中目标槽位整块高亮并标出槽位名，图标条上出现落点；松手后工具窗移到该槽位并显示。拖回原组或拖出图标条则不变。

**窄窗口。** 对话页可用宽度小于 1200px 时，右侧槽位里处于停靠模式的工具窗改为以「浮动 + 失焦自动收起」的方式盖在对话上方；窗口恢复宽度后回到停靠。这一切换不改写用户保存的模式。

**专注。** ⇧⌘\\ 隐藏全部工具窗，图标条保留且不显示「已打开」高亮；再按一次恢复之前的显示状态。打开任一工具窗也会退出专注。

**快捷键。** 见决策 10，行为与点击图标相同；⇧Esc 隐藏获得焦点的工具窗；焦点在工具窗内时按 Esc 把焦点还给输入框（处于「失焦自动收起」的工具窗随之收起，浮动窗不收起）；⇧⌘'（Ctrl+Shift+'）最大化获得焦点的区域；⌘0（Ctrl+0）收起 / 展开会话列表（再次点击左侧「对话」图标效果相同）。这些快捷键出现在快捷键面板中，本轮不可改绑。

**持久化与升级。** 布局（各工具窗的槽位、模式、是否显示、分隔比例、浮动位置与大小、会话列表是否收起）全局保存在本机，换会话、换标签页、重启后都保持；读回的值非法或缺失时逐项回落到默认。从旧版本升级：旧侧栏是打开的，则显示旧一级 tab 对应的工具窗；旧侧栏是关闭的，则不显示任何工具窗；「变更」的档位与「显示忽略项」偏好保留。

**新建会话提示页**（尚未发出首条消息）不显示图标条与工具窗，与今天不显示侧栏一致。

**无障碍与文案。** 图标条是工具栏，图标是报告「已打开 / 未打开」的切换按钮；工具窗是带名称的区域；分隔条获得焦点后可用 ⌃⇧方向键调整；所有菜单可用键盘操作。新可见文案全部走 i18n（zh-CN、en），措辞与产品现有叫法一致（例如「思考力度」「本地」，权限模式标签与输入框旁一致）。

## 编辑区与文件

**分屏。** 编辑区平时只有对话。从任何入口打开文件（变更 / 目录工具窗的行、转录里的文件链接）时，编辑区分为左右两栏：左为对话，右为文件。文件一侧有自己的标签条，每个标签可单独关闭；「Diff / 文件」切换、HTML 渲染、Monaco 显示等沿用今天预览面板的行为与「单击文件时」设置。关闭最后一个文件标签（或「全部关闭」）后分屏收起。两栏比例可拖动并被记住。

**文件占满。** 文件一侧的「占满」按钮或 ⇧⌘' 让文件占满编辑区：对话缩成左侧窄栏，显示最后一条用户消息、AI 当前正在执行的动作（没有进行中的动作时不显示这一行）和一个可直接输入发送的输入框。再按一次或点「还原」回到分屏。

**文件标签与根。** 每个文件标签绑定「工作根 + 相对路径」，切换会话当前工作根不改变已打开标签的内容。所属根不是会话主根时，标签上显示根名，路径行显示该根下的路径。标签按会话保存。所属根被移除后，标签划掉并标「已移除」；「Diff」仍按对话记录显示，「文件」显示文件不存在的状态。

## 终端工具窗

- 承载本会话的终端，可有多个标签；「新建终端」在会话**当前工作根**启动（远端会话在执行设备上、以该设备上的路径启动），会话有两个以上工作根时标签名带根名。
- 从转录卡片接入一个正在运行的进程，作为本工具窗里的新标签打开并显示本工具窗。
- 隐藏本工具窗不结束终端进程；关闭终端标签的行为与今天关闭终端标签页一致；切换会话时显示该会话自己的终端标签。
- 工作根变化时，已打开的终端不会自动 `cd`。
- 远端断线时的「新开终端」改为在本工具窗内新开标签。
- 从项目列表打开的「项目终端」仍是独立的对话标签页。

## 关联工具窗

自上而下四组，每组为空时整组不显示；全部为空时显示空态并保留两个任务按钮。

**任务。** 本会话关联的看板任务：编号、标题、阶段（待办 / 进行中 / 待审 / 已完成），以及「另有 N 个会话」（该任务还关联了其它会话时）。点击打开看板并定位到该任务。组下方有「关联任务」「新建任务」两个按钮（见「会话 ↔ 看板任务」）。

**派发我的。** 用 `agrctl send` 或 agent 派发拉起本会话的那个会话：会话标题、Agent、派发方式（agrctl send / agent 派发）、相对时间；点击打开该会话。

**我派发的。** 本会话派发出去的会话：任务文本、Agent、派发方式、状态（等待 / 运行中 / 已完成 / 失败 / 已取消，与子代理卡一致）与耗时。可见会话点击打开；隔离会话（`--isolated` 或 agent 派发）标「隔离」、不提供打开，点击展开显示它最后一条回复。

**同一份代码上在跑。** 本桌面端拥有的、正在运行（含后台活动）且 AI 当前位置与本会话处在同一执行设备同一工作根的其它会话：会话标题、Agent、所在根名；点击打开。若它与本会话写过同一个文件，整行以提醒色标出并写明文件（多个时写第一个并附数量），图标条上的关联图标同时显示提醒色圆点。

派发关系自本版本起记录，此前的会话不显示派发关系。

## 会话信息工具窗

只读的键值列表，所有值可选中复制：Agent（头像与名称）；后端（用户为后端起的名字 + 「本地」或设备名）；模型与思考力度；权限模式（标签与输入框旁一致）；上下文用量（用量条 + 已用 / 窗口）；累计用量（本会话各条消息已记录用量之和：输入、输出、缓存命中；各后端统计口径不同，子代理的用量不计入）；带入的记忆（条数 +「查看」，查看以只读方式显示本会话带入的记忆内容；没有带入时显示「无」）；位置（当前工作根名与类型，及另有几个 worktree）；创建时间与轮数（轮数 = 用户消息数）；CLI 会话 ID；「复制启动命令」（仅 Claude Code / Codex / Pi，与标题栏菜单一致）。某项数据不可得时该行不显示。

## 网页预览工具窗

- **标签。** 本会话进程正在监听的端口自动成为标签（来源与后台弹层的「进程与端口」相同，含远端会话），标签名为「:端口 + 命令」。当前标签的端口不再被监听时，标签保留并显示「这个端口已不再监听」与「重新加载」；非当前标签随端口消失而移除。
- **地址栏。** 显示当前地址，可输入任意 http / https 地址；有后退、刷新、在浏览器打开；⤢ 占满编辑区。
- **远端会话。** 指向 localhost / 127.0.0.1 / ::1 的地址经端口转发打开：沿用今天「打开端口」的做法（在执行设备上复用、启用或新建以端口号命名的转发设置，再在本机开一个转发地址）。地址栏仍显示 AI 说的原地址，旁边标「<设备名> · 经端口转发」，悬停显示本机实际访问的地址。「在浏览器打开」打开的是可用的转发地址。自动新建的转发设置保留在该设备的端口转发列表里。
- **https。** 远端的 https localhost 地址按 https 转发，不自动开启「忽略证书错误」；证书校验失败时显示失败原因和「打开端口转发设置」入口。
- **无法内嵌。** 页面无法在应用内显示时（被系统组件拦截或目标站禁止嵌入），内容区说明原因并提供「在浏览器打开」。
- **入口。** 转录中的 localhost 链接悬浮卡与后台弹层中的端口各多一个「应用内预览」，点击后在本工具窗打开对应地址并显示本工具窗；它们原有的默认打开方式不变（但远端会话改为经端口转发，见「文件与 localhost 链接」）。
- **已知限制。** 页面里写死的 `http://localhost:<端口>` 绝对链接，在远端会话的预览中会指向本机；本机转发地址的端口在应用重启后会变化，预览中的登录状态可能需要重新登录。

## 会话 ↔ 看板任务

**关联。** 一个任务可关联多个会话，一个会话可关联多个任务。关联只保存在本机，不随任务同步到其它设备。任务或会话被删除时，相关关联随之删除。关联不改变任务阶段。

**看板卡片「开始会话」。** 任务卡 ⋯ 菜单的第一项。点击后打开新建会话：项目为任务所属项目；Agent / 后端 / 模型取任务上指定的值，未指定的项按新建会话的默认；输入框预填「任务标题 + 空行 + 任务描述」，不自动发送。会话在首条消息发出时创建，并在此时与该任务建立关联；未发送就离开则不建立关联。

**看板卡片显示关联会话。** 任务卡下方列出全部关联会话：运行状态标记（运行中 / 空闲 / 出错，与会话列表的状态标记一致）、会话标题、Agent；点击打开该会话。没有关联会话时不显示这一块。agentre-server 网页端的看板不显示这一块。

**关联已有任务。** 关联工具窗任务组的「关联任务」弹出搜索列表，范围为本会话所属项目及其子项目的任务（会话不属于任何项目时为全部任务），每项显示编号、标题、阶段，已关联的打勾；点击切换关联 / 取消关联。列表末尾是「新建任务『<搜索词>』」。

**新建任务。** 关联工具窗的「新建任务」以本会话标题为默认标题（从搜索列表进入时为搜索词）、本会话所属项目为项目，在「待办」阶段创建任务并立即关联；创建后任务出现在任务组中。

## 工作根与 worktree 跟随

**标题栏工作根胶囊。** 对话标题栏副标题行显示工作根胶囊，取代今天的工作目录文本：
- 当前是主仓库：中性色，显示根名与分支；不是 git 仓库时只显示目录名。
- 当前是 worktree：醒目色，显示分支名与「worktree」。
- 只有一个工作根时不可点击；两个及以上时点击弹出下拉：列出每个工作根（名称、主仓库 / worktree、路径、「本次会话」变更数），当前根打勾，AI 当前所在的根标「AI 在这里」，底部是「跟随 AI 切换」开关。

**会话级当前工作根。** 变更（两档）、目录、新建终端、从工具窗打开的文件都使用会话当前工作根。会话没有工作目录时不显示胶囊，各工具窗沿用今天的空态。

**跟随。**
- 「跟随 AI 切换」默认开启。开启时，AI 当前位置移到另一个已认领的工作根（包括回到主仓库），会话当前工作根随之切换，并在胶囊下方显示约 5 秒的「已跟随 AI 切到 worktree <名称>」，附「留在 <原根名>」：点击后回到原根并关闭跟随。
- 用户在下拉中手动选根时跟随自动关闭；重新开启时立即切到 AI 当前所在的根。
- 跟随开关与当前工作根按会话保存，应用重启后重置为默认（开启、AI 当前所在的根）。
- 会话本身在 worktree 里启动时，胶囊从一开始就显示该 worktree。

**worktree 被移除。** 当前工作根从认领集合中消失时，回到主根并提示一次「worktree <名称> 已被移除，回到 <主根名>」；变更工具窗中该根的「本次会话」文件以「<名称>（已移除）」分组划掉显示，仍可点击查看对话记录里的 diff。

## 识别信号

**AI 当前位置。** 每个会话维护「AI 当前位置」（一个绝对目录，属于会话的执行设备），初值为会话工作目录（Claude Code 以 init 帧报告的目录为准）。以下信号在对应工具事件到达时更新它，即在轮次进行中生效：

| 后端 | 信号 |
|---|---|
| Claude Code | EnterWorktree 结果的 worktree 路径；ExitWorktree 结果的恢复目录（选择删除时同时撤销该根）；启动 / 恢复时 init 帧的目录；每次工具调用 PostToolUse hook 输入的 `cwd`（覆盖 Bash `cd`） |
| Codex | 每条命令开始时的 `cwd` |
| Hermes | `terminal` 调用的 `workdir`，及结果报告的 `cwd` |
| OpenClaw | `exec` 调用的 `workdir` |
| Pi / builtin / ACP | 无结构化信号：从 shell 命令文本识别 `git worktree add <路径>`、`cd <路径>`、`git -C <路径>`；不能确定时不更新 |

子代理（hook 带子代理标识）的位置变化只参与认领。重启或重新打开会话后，AI 当前位置取最后一个带位置记录的工具调用块的目录。

**认领。** 候选路径：AI 当前位置的每次变化、每次写文件的目标路径（相对路径按该调用的 AI 当时所在目录补全，而不是跳过）、`git worktree add` 命令中的路径、用户点击的绝对路径。候选的 git 公共目录与会话主根相同时，认领它所在工作树的根。新增两点：落在已认领根之内但属于另一个工作树的路径（`<repo>/.claude/worktrees/x`、`<repo>/.worktrees/x`）也认领为新根；比较路径前统一为真实路径，真实路径在执行设备上解析。认领结果持久化，重新打开会话与重启后仍在；认领立即反映到胶囊、下拉与各工具窗。git 判定失败时不认领、不报错。

**远端会话。** 位置信号由执行设备上的运行时产生，随工具调用 / 工具结果事件传到桌面；git 判定在执行设备上进行，结果按会话缓存，避免每次取工作根都重新逐层询问。执行设备上的 agentred 较旧、不提供 hook / init 的目录时，仍使用已随事件到达的信号（EnterWorktree / ExitWorktree 结果、Codex 命令目录、命令文本、写入路径），不报错、不提示。

**轮末重算。** 轮末重算与实时识别使用同一套写入识别规则：ACP、Hermes 的写入在重算中同样被识别。

## 文件与 localhost 链接

**AI 当时所在目录。** 每个工具调用块记录产生它时的 AI 当前位置，随消息保存，重新加载后不变。文字块里的链接使用同一轮中它之前最近一个工具调用块的记录；没有这样的块时使用该轮开始时的 AI 当前位置。没有这项记录的旧消息按会话工作目录解析（今天的行为）。

**文件链接。**
- 相对路径按「AI 当时所在目录」补全为绝对路径。
- 绝对路径落在某个已认领工作根之内时，归属包含它的最深的根，在该根内预览；落在同一仓库尚未认领的 worktree 内时，当场认领后预览；认领不成立时按今天的外部文件处理。
- 预览、复制路径、系统打开使用同一个解析结果；「单击文件时」设置对 worktree 内的文件同样生效。
- 悬浮卡在路径前显示根名标签（所属根不是会话主根时）。
- 远端会话同样适用，经今天的远端读取通道预览，不再对远端 worktree 内的文件给出「本机上没有这个文件」。

**localhost 链接。** 本机会话不变。远端会话里指向 localhost / 127.0.0.1 / ::1 的 http / https 链接，无论系统浏览器打开还是应用内预览，都经端口转发访问执行设备上的服务，路径与查询参数原样保留（规则同「网页预览」的远端会话一节）。

**agentre-server 网页端。** 共享链接组件、预览接口与看板卡片改为可选地携带新信息（根、关联会话）。网页端的适配层把根固定为会话工作目录、不提供关联会话，可见行为与今天一致。
