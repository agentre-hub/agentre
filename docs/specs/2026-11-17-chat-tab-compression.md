# 对话标签栏像 Chrome 一样压缩

> Status: Implemented
> Owner: desktop app maintainers
> Last updated: 2026-11-17

**Objective:** 标签页多了以后不再互相叠压、不再滚动，而是一起压窄、逐档收起细节；悬停的标签页不再像「又选中了一个」。

**Hard invariant:** 标签栏永不横向滚动、标签页永不互相覆盖；活动标签页始终看得到、关得掉。

## Problem

1. **标签页互相叠压。** 可排序外壳 `min-w-0` 可以被压到约 100px，里面的 `Tab` 却是 `min-w-[120px]`，每格向右溢出约 20px 压在下一格上：下一格的悬停底盖住了这一格的 ×，项目色线按外壳宽度画、与标签页本身对不上。（用户截图，按像素核实）
2. **悬停像选中。** 深色悬停面 `#1e1f22` 与活动标签页 `#242529` 只差 1.08；浅色悬停面直接取了活动标签页的色值 `#f6f6f7`。悬停时看起来同时选中了两个标签页。（用户截图，按像素核实）
3. **边缘硬切、× 常驻。** 被滚出的标签页在左边缘留下孤零零的 ×，右边缘的活动标签页被溢出按钮切掉；每个标签页都常驻 ×，运行中的还是 spinner + × 两个记号，120px 宽时标题只剩「https:…」。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 不设下限地一起压缩（每格从 240px 起等比压窄），永不滚动；活动标签页最少 60px | 用户在 mockup 中选定「像 Chrome 一样继续压缩，不要滚动」「不要下限，继续挤」。Rejected: 压到 120px 后横向滚动 + 边缘渐隐；Rejected: 压到 36px 后再滚动 |
| 2 | 按每格自身宽度分档（外壳是 size container）：≥88px 方块 + 标题 + 尾部一格；<88px 尾部一格收起（悬停也不出 ×）、运行中 spinner 顶替方块、待处理胶囊收成状态点；<56px 标题也收起，只剩居中方块，状态点贴到方块右上角；活动标签页 <96px 收标题、始终留 × | 用户在 mockup 中确认。窄标签页不出 × 以免误关，关闭走 ⌘W / 右键菜单（都已有）；完整标题由悬停卡给（已有） |
| 3 | 尾部只留一格：运行中显示 spinner，否则活动标签页显示 ×；悬停时这一格一律换成 × | 用户在 mockup 中确认。活动且运行中的标签页保留 spinner，不丢状态 |
| 4 | 悬停面：深色 `#1a1b1e`（离外框 1.09、离活动标签页 1.13）；浅色 `#e7e7ea`，落在外框之下（离外框 1.05、离活动标签页 1.14） | 浅色外框与活动标签页只差 1.09，夹在中间的色与两边都分不开。用户先选了 `#e2e2e5`，它让弱化文字（4.47 < 4.5）与空闲点（2.87 < 3.0）的守卫变红，改选 `#e7e7ea`；悬停面离外框的下限因此单独放到 1.04 |
| 5 | 不做「活动标签页自动滚入可视区」 | 用户否决；且决策 1 之后标签栏不再滚动 |

## Out of scope

- 溢出菜单 ⌄ 上「被挤出去且需要处理」的计数：不再滚动后几乎不会出现，本轮保留不动。
- 普通竖向滚轮横向滚动标签栏：不再滚动后无意义。

## Acceptance

- 标签页数量从 6 到 28 个时，720px 宽的标签栏里所有标签页都可见、互不覆盖，分档如决策 2。
- 两个主题下悬停的非活动标签页与活动标签页一眼可分。
